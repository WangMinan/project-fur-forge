## 3. 关键交互决定

1. **隐藏字段不提交**。`toWorkFieldsPayload` 按 `purpose` 分支构造请求体，非领养分支根本不写入 `adoptionMethod`/`businessStatus`/`priceCnyMinor`，不依赖服务端丢弃多余字段。单元测试与 E2E 都断言请求体不含这些键。
2. **用途变化可见**。用途选择器下方常驻 `role="status"` 说明当前用途出现/隐藏哪些字段；从已保存的领养切换到非领养时额外提示「保存后会清空领养方式、业务状态与价格；已有设定图时服务端会拒绝切换」。
3. **价格只在适用领养显示**。界面单位为元，提交前用既有 `parseCnyYuanInput` 转成正整数分；零、负数、三位小数、指数形式在客户端就被拦下并关联到价格输入；留空表示不公开价格，公开端整块不渲染，不出现「请咨询」。
4. **dirty 基线按用途归一化**。合法价格与排序按契约值归一化，保存后用服务端返回重建基线不会立刻回到「有未保存更改」；非法输入保留原文，保证错误输入仍能触发保存并看到校验结果。
5. **排序与精选的编辑方式**。当前数据量下使用数字输入 + 勾选，逐行即时保存，不为了拖拽引入额外依赖。精选与首页 Hero 轮播在文案与位置上明确区分。
6. **历史展会记录不静默丢弃**。带 `event_drop` / `event_sale` / `currentEventName` 的作品显示只读分区并锁定用途与保存，必须经确认对话框转为常规领养后才能继续编辑；不提供展会编辑器。

## 4. 已知接口边界与 blocker

1. **已发布作品无法修改排序与精选**。`updateManagedWork` 对 `publication_status = 'published'` 返回 409「Unpublish the work before editing it.」，因此精选/排序只能在草稿或下架状态维护，已发布作品必须先下架再改。前端已在列表和编辑页显式说明，没有在客户端伪造成功。**这是当前真实的运营限制，是否需要为排序/精选单独开放已发布态写入，需要 `BACKEND_PRIMARY` 决定，不在本次前端范围内修改。**
2. **常规领养仍不可发布**。`checkWorkPublication` 对领养作品固定返回 `ADOPTION_FLOW_NOT_READY`，属于 T25 范围。因此本次无法在浏览器中走通「领养作品出现在公开端」的完整链路；公开端领养事实的投影正确性由后端集成测试与既有 T19/T20 公开 E2E（含 adoption 夹具）覆盖。
3. **E2E 助手此前会被新契约拒绝**。后端把 `sortOrder` 与 `featured` 变为必填后，`tests/e2e/helpers/admin-work.ts` 的旧 payload 会被 400 拒绝；本次已修复并扩展为支持三用途。
4. **公开导航仍解析到未实现路由**。开发服务日志出现 `/commission`、`/adoptions`、`/returns`、`/about`、`/contact` 的 `VUE_ROUTER_R0004` 警告，属于 T26–T29 之前的既有状态，不是本次改动引入，也未在本次修复。

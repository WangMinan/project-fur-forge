# 固定比例构图拖动精度修复

## 授权与定位

用户反馈 PC Web 编辑安安时直接拖动裁剪框出现“选区比例与展示用途不符”，随后明确授权再次确认后直接在 main 修复。修复基线为 `0815a32`，工作树初始干净。

`ImageCompositionControls` 还原选区时按显示尺寸设置 Cropper 的比例；交互事件再次读取显示尺寸并换算原图坐标。亚像素尺寸漂移可能令归一化后的原图比例超出共享校验的 `0.00001` 相对容差。显示的选区像素经过取整，不能证明内部比例合格。鼠标拖动与方向按钮最终调用同一个移动方法，先点按钮不构成可靠修复。

Chrome 隔离加载主分支原组件、使用 1403×1001 合成原图元数据和 640×457 预览，1280×720 视口可复现：初始应用按钮可用，首次直接拖动后禁用；原图比例约为 `1.0000103662911388`。不依赖生产作品数据。

## 修改

在现有 `onSelection` 完成边界校验和夹取后，固定比例用途复用 `fitCrop`，将选区在原图坐标中按目标比例内接，保留中心。覆盖详情缩略图1:1、作品目录4:5、首页代表作品3:4；两种领养自由裁切仍使用原坐标。出厂照、横版封面和设定图共用此组件。

共享校验、服务端保存/发布规则、放大上限、数据库与媒体配方未修改。

## 验证

- 原组件隔离对照：移除修复时首次拖动失败；修复后五种用途分别在1280×720/DPR1、1920×1080/DPR1.25、1536×864/DPR1.5、1024×768/DPR2、390×844/DPR1通过，共25组。检查真实鼠标移动、边角缩放、方向按钮、应用与重新打开；固定用途输出比例误差小于1e-12，坐标不越界，自由用途未锁成方形。
- 扩展现有 `tests/smoke/image-composition.spec.ts`：4209×3003合成素材与640×457预览，首次直接鼠标拖动后应用仍可用且选区确实移动；保存后检查原图坐标为1:1。既有取消、还原、八档编辑器视口、六档公开页、decode、溢出、console与测试库重新播种检查均通过，1项smoke通过。

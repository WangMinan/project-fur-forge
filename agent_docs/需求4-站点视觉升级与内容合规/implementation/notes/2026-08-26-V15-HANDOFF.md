## Locked Decisions

- Safe Area 继续使用浏览器约束默认视口；本阶段不增加 `viewport-fit=cover`，除非后续同时设计并验证完整 inset 保护。
- 联系二维码继续使用原生 lazy loading；自动证据负责真实滚动触发，不把测试工具限制修成生产端 eager loading。
- 1023px 继续是折叠导航/原生滚动，1024px 继续是 Desktop 导航/桌面布局边界；两侧均已单独截图验证。
- 可见交互目标下限保持 44×44；`opacity: 0`、`pointer-events: none` 的非当前 Hero 控制不计作可操作目标。
- Hero 品牌文字、Footer、正式页面短 opacity 入场、无跨页媒体 morph 和既有业务边界继续锁定。

## Regression Risks

- 后续若启用 `viewport-fit=cover`，当前 safe-area 结论立即失效，必须为 Header、Mobile Nav、底部 controls 和表单行动补齐四向 inset 验证。
- 全页截图若删除懒加载滚动步骤，会再次得到“URL 正确但图片未解码”的假阴性，尤其影响 `/commission` Mobile 二维码。
- 1023/1024 共用样式调整可能同时破坏导航切换、Works 列数、Adoption 卡片和 Homepage 滚动模式，必须成对回归。
- 详情主图圆角必须保留在实际 `<img>` 层；只给外框圆角而缺少裁切会再次出现锋利图片角。

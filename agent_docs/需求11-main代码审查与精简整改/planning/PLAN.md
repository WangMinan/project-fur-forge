## 执行结论

2026-10-08 用户追加授权按此计划实施，当前 F01–F12 修改已落地并进入验证；完整发现见 [REVIEW](../review/REVIEW.md)，完成勾选以 [TASKS](../implementation/TASKS.md) 为准。

## 执行顺序

### 1. 数据删除与请求安全：F01/F02

- F01：先固定跨进程、ID/回执别名、盘点期间编辑三个竞争场景；核对现有 `email_deletion_pending` 能否承担持久删除标记。在数据库事务内核对当前版本/状态并取得删除权，各编辑入口遵守标记，再进入外部对象删除。失败后的重入语义必须明确。
- F02：对照实际路由处理统一安全路径匹配，覆盖登录、统计及同类精确比较。保留认证、Origin/CSRF、请求体上限和各限流维度，补等价路径用例。

### 2. 任务生命周期：F03/F04/F05

- F03：在现有恢复器之上补有界后续扫描与停止清理，不引入队列系统；覆盖快速重启、活跃租约、扫描上限及终态幂等。
- F04：共享轮询按 key 跟踪活动身份与取消状态；每次 await 后检查有效性，防止旧请求调度或执行业务回调。核对 Hero 自动启用和作品发布调用方。
- F05：为管理上传核验明确执行者存活/超时判定及安全终态，衔接现有取消、重试和清理。先检查真实上传耗时边界，再决定是否复用现有 lease 能力或需前向迁移。

### 3. 无效入口与旧代码：F06/F07/F08

- F06：删除无效排序 UI、表单状态、校验和 dirty 参与项；检查创建、更新和展示设置请求，确定最小兼容处理。保留 DTO 中用于展示的顺序与完整精选集合排序。
- F07：超限提示引用现有共享常量，不新增配置。
- F08：核实旧 mapper/Schema/类型完整引用链后删除；将有价值的断言转到实际 `ManagedWorkDto`/`VerifiedAssetDto` 出口，并修正仍指向旧契约的注释。

### 4. 确定重复的职责：F09/F10

- F09：从设定图和领养封面的重复状态与上传操作中抽取最小共用部分，继续复用 `useStudioPhotoUpload`；业务特有 payload、构图和预览留在原组件。
- F10：抽取公开对象完整性检查，调用方明确预期格式/尺寸；保留各 recipe 的身份、生成、重试及错误处理，不合并整套 recipe/runner。

### 5. 低优先级精简：F11/F12

- F11：只共享轮播控件显隐及清理，不把两个轮播展示做成参数化万能组件，也不把无独立控制条的当前领养轮播强行纳入。
- F12：移除 `ImageDropzoneCard` 未使用的后台主题，固定公开按钮与样式；不为了“增加调用方”改造后台上传流程。

## 技术决策

- 不以总行数为目标；先删除无效实现，再合并真实重复，最后处理小型精简。
- 原编号不随实施顺序改变；每批修改同时核对调用方、测试、文档及兼容边界。
- 安全/恢复修复与 UI/精简拆为小提交；实现、合并、镜像和生产操作分别记录授权与结果。
- 复用后保留原错误处理和业务差异；新非平凡逻辑留下小而有效的行为测试。

## 验证路线

1. F01–F07 优先建立能暴露原缺陷的场景；F08–F12 检查引用和行为等价，不为删除几行代码新增镜像实现的测试。
2. 执行 lint/typecheck、受影响 core；Nuxt/runtime/config 变化追加 build。
3. UI 变更用隔离假数据完成浏览器测试，核对上传恢复、冲突保留、禁用/焦点、触控、偏好、图片 decode 与溢出。
4. 单独核对 [原测试局限](../review/REVIEW.md#验证记录)；不能把审查前通过记录当成整改后验证，也不能把所有失败都解释为机器负载。
5. 文档归档仅校验结构、链接、编号和状态，不触发 release/manual 或生产流程。

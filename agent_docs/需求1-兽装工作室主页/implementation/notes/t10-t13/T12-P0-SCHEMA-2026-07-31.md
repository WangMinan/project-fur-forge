本任务把当前 P0 领域契约落入首批版本化迁移，没有把共享 DTO 机械复制为数据库表。

## 2. 迁移与表

迁移：

- `0000_sparkling_absorbing_man.sql`：11 张 P0 表与首批领域约束；
- `0001_preserve_design_sheet_purpose.sql`：阻止已关联设定图的领养作品改为其他用途。

建立 11 张 P0 表：

- `users`；
- `works`、`work_feature_tags`；
- `assets`、`asset_variants`、`work_assets`；
- `site_hero_slides`、`publication_operations`；
- `business_statuses`、`site_content`、`audit_logs`。

关键约束：

- `owner_display` 无默认值、去空白后非空；测试显式保存“有点小狗工作室”和“不公开”，没有 `owner_type`。
- 价格以整数最小单位保存，金额/币种同时为空或仅领养作品使用固定 `CNY`；没有定金、付款、美元或等价字段。
- 短属性位置只允许 0–7，值去空白后 1–24 字符，同作品位置和值均唯一。
- 原图只保存私有相对 Key、摘要和元数据；核心身份不可更新。私有与公开 variant 统一记录在独立于 `assets` 的 `asset_variants` 表，通过可见性字段区分；数据库不保存环境相关完整 URL。
- `work_assets` 只允许 `design_sheet` / `studio_photo`；设定图仅领养作品且最多 1 张，出厂照最多 5 张；作品用途更新也不能绕过设定图约束。
- 首页横竖资产角色和方向独立；启用项必须是 READY 配对、alt 非空、人工排序唯一、最多 5 项，可选关联已发布作品。
- “至少 1 个启用项”由 `validateHeroSlidesForPublication` 在发布边界验证；空库和纯草稿库仍是合法运行状态。
- variant identity 唯一键覆盖输入摘要、媒体角色、用途、尺寸、格式、质量、裁切、recipe、水印 profile、Logo 摘要和锚点；公开 P0 variant 固定 `brand-standard-v1`，身份不可原位改写。
- `publication_operations` 只允许生成、水印、验证、提交、清理、失败和完成状态，没有 ACL 切换状态。

## 3. 投影

- `server/utils/work-mapper.ts` 继续逐字段输出已发布作品；草稿返回 `null`，联系人、密码/Session、私有 Key、内部错误和草稿 URL 均不会进入公开 DTO。
- `server/utils/media-mapper.ts`
  - 管理资产 DTO 只返回 `assetId`、版本、角色、状态、MIME 和尺寸，不返回私有 Object Key 或摘要；
  - 公开 variant 只接受 `PUBLIC + READY`，由运行时媒体 origin 和相对 Key 生成 URL；
  - 首页投影要求启用且横竖两侧均至少有一份公开 READY variant；未发布作品不会形成链接。

## 5. 风险与后续

- SQLite 触发器保存在版本化 SQL 迁移中，Drizzle Schema 不表达触发器；行为集成测试会在后续迁移误删约束时失败。
- T12 只建立 Schema、投影和发布校验，没有作品 CRUD、上传、媒体处理或发布 API；这些分别属于 T14–T20。
- 首页发布的“至少 1 项”不能作为表级永久约束，否则无法表达初始空库和草稿编辑；调用发布事务前必须运行现有校验函数。

## 接口口径

- 保留认证、Origin、CSRF、限流、请求大小与严格 Schema 校验。
- F06 只去掉已经无效的手工排序入口；代表作品集合排序接口与读取结果继续存在。请求兼容方式在实现前核定，不能直接删除共享 DTO 中仍有用途的 `sortOrder`。
- F08 所称旧管理 DTO 与真实接口的 `ManagedWorkDto`、`VerifiedAssetDto` 必须区分；不得误删公开投影或仍被调用的 mapper。
- F09–F11 复用行为，不统一不同业务的 owner、媒体角色、裁剪规则或展示布局。

## 数据库口径

- 关注 `commission_submissions` 的版本、状态和现有 `email_deletion_pending`；优先评估复用持久字段，不直接增加新锁表。
- 发布任务使用现有 lease/attempt 与条件更新；不能因需要恢复就抢占有效租约。
- 管理上传 `upload_sessions` 与匿名委托上传 `commission_upload_sessions` 是不同链路；F05 的“过期清理排除 VALIDATING”证据针对前者，不直接套用到后者。
- 本轮没有 Schema 变更。若后续确需迁移，只新增前向迁移，并记录原因及恢复影响。

## 安全约定

- 保留 [项目稳定入口](../../../CLAUDE.md) 的私有媒体、PII、不可变对象和生产授权边界。
- 复现使用内存库、合成数据或隔离测试库；文档不记录秘密、真实申请信息、签名 URL 或私有对象身份。
- 删除前必须先获得持久执行权并确认对象身份；删除后才发现版本变化不能作为安全保护。

## 编码与命名约定

- Windows 使用 `pwsh`；默认 `codex/*` 分支，小范围提交，只暂存本任务文件。
- 先复用现有服务、组件和常量；不引入通用框架、依赖或无实际调用方的配置。
- 删除旧实现时把必要行为断言迁到真实入口，不删除安全覆盖换取测试通过。

## 2. 必修问题

### UI-01 · 管理端独立布局与单一 main

管理端作品页当前没有声明独立布局，因而继承公开 `Header`、`Footer` 和外层 `<main>`；`AdminShell` 内又创建第二个 `<main>`。建立管理端专用 layout 或等价的明确边界，管理端不得继承公开 Header/Footer，最终文档树只保留一个 main landmark。登录页现有独立呈现也必须保持。

### UI-02 · 首页 Hero/Header 确定性文字对比度

首页 Header 与 Hero 文字覆盖在作品图上，不能依赖某一张夹具恰好较暗。增加对任意正式图片都成立的确定性对比度保护，例如受控遮罩、文字背板或等价方案；不得用大面积蓝色营销面板抢夺作品主体。

### UI-03 · 动态参数变化

`/works/[slug]` 与 `/admin/works/[id]` 当前只在 setup 初次读取参数。使用响应式派生或参数监听，使同组件实例中的参数变化能够重新选择作品、更新 SEO/表单状态，并正确进入存在或不存在分支。补浏览器回归测试，不得只验证首次直达。

### UI-04 · dirty 覆盖全部可编辑字段

管理端 `isDirty` 当前遗漏领养方式、业务状态和价格等字段。所有可编辑字段、短属性顺序及增删都必须影响 dirty；切换作品 ID 后应重建基线，保存接口未接入时不得假装清除 dirty。

### UI-05 · 金额校验与服务端一致

服务端 `adminWorkDtoSchema` 对 `priceCnyMinor` 的要求是：可选；存在时必须为正整数最小货币单位；只允许领养作品。前端人民币输入必须严格接受完整十进制格式、最多两位小数、换算后大于零且为安全整数；拒绝负数、零、指数、尾随非法字符和两位以上小数。不得继续使用宽松 `parseFloat` + `Math.round` 形成与服务端不同的接受集合。补单测与 E2E。

### UI-06 · reduced-motion 横向轨道

`FeaturedTrack` 的按钮和键盘路径当前强制 `behavior: 'smooth'`。当 `prefers-reduced-motion: reduce` 时改用非平滑滚动，并补浏览器断言；正常动效偏好下可保留 smooth。

### UI-07 · 真实任务阶段文案

把界面中的“OSS 衍生图 T11–T12”等错误阶段描述改为真实任务阶段：T14–T15 是私有上传/校验，T16 是跨 Bucket 衍生图生成，T17 是后台创建与草稿保存，T18 是发布/下架。只修正文案，不实现这些能力。

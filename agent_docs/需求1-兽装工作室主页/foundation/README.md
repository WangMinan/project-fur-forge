# 阶段 0 · 地基（Foundation）

> **角色**：锁定产品边界、事实优先级与不可被实现细节绕过的原则。

## 权威与证据

- 当前正式规格工作区是本需求目录。
- 事实优先级：用户与景宸的明确确认 > 本文件 > `requirements/SPEC.md` > `planning/PLAN.md` > `.design/` > `implementation/TASKS.md`。
- `materials/`、`planning/prototype-v1/`、`implementation/notes/` 仅作证据或历史记录；旧原型中的名称、价格、20 MB、单 Bucket、付款备注等内容不具有当前实施效力。
- 每次变更必须同步 SPEC、PLAN、模型说明、设计契约、TASKS 和 STATE；不得只在代码中临时决定。

## 产品边界

公开站固定包含：首页、作品展示、自设委托、角色领养、返图墙、关于我们/基本约定、联系。每件作品以 `/works/{slug}` 为唯一 canonical；领养详情兼容地址只做重定向。

一期不建设：

- 访客账号、收藏、订单、支付、登记、线上签约或站内估价；
- 制作排期、合同、客户生命周期、经营看板或消息中心；
- 多管理员、RBAC、OAuth、设备管理；
- 万能 CMS、任意 HTML/脚本、公开投稿；
- 消息队列、媒体 worker、自动重试服务或多实例部署。

首版面向中国大陆并使用简体中文。委托通过 `3114559925@qq.com` 人工估价；官方 QQ 为 `3114559925`，抖音为 `to3114559925`。领养和展会掉落只展示真实状态、作品属性与已录入人民币价格，后续沟通在线下完成。

## 交付优先级

- **P0 · 可部署核心**：生产视觉基线、唯一管理员登录/改密/受保护命令重置、作品 CRUD、原图直传、角色化图片处理、首页横竖双源轮播、基础水印、发布/下架、首页/作品/委托/领养/关于/联系、基础营业状态、SEO 与 SQLite 备份恢复。
- **P1 · 一期完整增强**：返图、展会关联、完整多图/裁切/排序、返图水印策略、站点内容维护、回收站、slug 改址和手机轻量维护。
- **P2 · 独立后置**：邮件找回密码、完整导出中心、永久原图档案 UI、访问统计、CDN、复杂媒体恢复与批量运维。

P0 可以形成首个可部署版本；P0 + P1 形成一期功能闭环。正式素材、部署与景宸实际使用验收仍由 T51–T53 单独完成。P2 不得阻塞核心网站上线。

## 数据边界

- `works` 是统一作品聚合，不按委托/领养/展示拆成多套核心表。
- 角色主人公开显示值始终非空：工作室作品固定显示“有点小狗工作室”，隐私作品固定显示“不公开”；一期不增加独立 `ownerType`。
- 后台可以保存领养人或角色主人的联系人；公开投影永不包含该字段。
- 不保存 `depositNote`、`paymentNote` 或等价的定金/付款备注。
- 返图可保存三个可选私有字段：`consentSource`、`consentConfirmedAt`、`consentNote`；缺失不阻止发布。
- 价格一期只支持人民币；金额以整数最小单位保存并约束币种为 `CNY`。未来多币种通过数据库迁移扩展。
- 作品短属性为每件 0–8 条有序短文本，不演进为通用 EAV。
- 领养方式为“常规领养/展会掉落”；业务状态为“准备中/可领养/展会出售中/排期中/制作中/已完成交付”。“展会出售中”必须关联当前展会。
- 公开媒体必须按角色区分：`design_sheet` 为领养设定图，`studio_photo` 为出厂照/作品展示图，`return_photo` 为返图；同一原图不得同时冒充多个角色。
- 每件作品最多 5 张出厂照和 5 张返图；领养作品另有 1 份设定图。设定图以横版完整画布为主，出厂照与返图以竖版/原比例展示为主，不得用统一 3:4 裁切抹平差异。
- 首页轮播是站点级对象，不挂在单件作品字段上。每个启用项必须同时关联一张横版图和一张竖版图；至少 1 项、最多 5 项，顺序由管理员维护。
- 原图最大 30,000,000 字节，最长边 12,000；等于边界可接受。
- 委托与领养营业状态是两个独立、版本化对象，状态只允许“开放 / 有限开放 / 关闭”三种受限语义；不得借此扩展制作排期、客户记录或经营看板。
- `site_content` 只保存固定页面所需的明确字段：委托短说明、人工估价说明、邮件行动、已确认 FAQ、关于页工作室事实与制作范围、基本约定纯文本、公开邮箱/QQ/抖音和防诈骗文字。重复 FAQ 只能使用受限的“问题 + 回答”结构，不接受自由 HTML、Markdown 脚本、iframe 或富文本。
- 首页媒体、轮播关系和水印 profile 继续使用专用表/对象，不进入站点内容 JSON。OQ-120 已确认的委托、关于、基本约定、防诈骗和营业状态文案作为数据库初始化默认值；迁移只补空字段或缺失状态，不覆盖管理员已有内容。未来未经用户登记的新文案仍保持空值/草稿，不生成占位 seed。

## 技术地基

- 单 Nuxt 4 全栈应用、Node.js 24 LTS、Vue 3、TypeScript strict、Nitro。
- 公开站 SSR，管理端 `/admin/**` CSR；公开 Host 不暴露后台、管理 API 或预览。
- SQLite + Drizzle + `better-sqlite3`，单进程单写入者，数据文件挂载持久卷。
- 开发机完成测试、Nuxt 构建和 Docker 镜像构建；生产机只运行镜像。
- 所有运行时配置由版本化 Schema 统一解析，优先级固定为“环境变量 > 活动配置文件 > 安全 fallback”。非测试环境的公开、后台、媒体和 OSS 上传 origin 必须由 `.env`、进程环境变量或活动配置文件显式提供，不内置 `localhost`、`127.0.0.1` 或其他域名 fallback；秘密无 fallback，不进入仓库、镜像或日志。
- 配置硬编码是工程门禁：凡被定义为配置项，其具体值只能出现在测试文件、被 Git 忽略的 `.env`、进程环境变量或不入库的活动配置文件中；测试之外的应用代码、脚本和版本化文档/模板只能保留配置键、Schema、读取与校验逻辑，不得写死具体值。产品不可变约束继续作为版本化契约或常量维护，不作为配置项。

## 双 Bucket 媒体地基

- `project-furry-forge-private`：`original/`、`draft/`、`temp/`、`preview/`；Bucket 与对象保持私有，Block Public Access 应开启。
- `project-furry-forge-public`：`web/`；只保存已经发布、可匿名读取的网页衍生图，不保存任何原图或私有资料。
- 两个 Bucket 必须位于同账号、同地域并支持 OSS 图片处理跨 Bucket `sys/saveas`。
- 浏览器通过 V4 条件 PUT 直传永久私有原图；AccessKey 不进入浏览器，上传请求体不经过 Nitro。
- OSS 图片处理原图硬上限为 20 MB。20,000,000 字节以内且满足用途尺寸的原图直接进入 OSS 衍生链；更大的合规原图由服务端使用随应用安装的固定版本 FFmpeg 生成最长边不超过 4,096 px、且不超过 20,000,000 字节的私有处理中间件。不得调用宿主机 `PATH` 中的 FFmpeg。
- 首页/委托页大图推荐横版至少 `1920×1080`、竖版至少 `1080×1920`。方向正确但未达到推荐尺寸时允许保存；管理端必须在启用前说明清晰度风险并取得明确确认，随后由同一内嵌 FFmpeg 使用固定 Lanczos 插值生成目标画布的私有适配源。该处理不是 AI 超分，不能恢复原图不存在的细节；永久原图不得覆盖。设定图、出厂照和返图继续不自动放大。
- OSS 仍是公开网页 variant、最终格式和水印的唯一配方权威；本地预处理只解决 OSS 输入上限或经管理员确认的大图尺寸适配，不生成公开结果，不复制水印或公开 recipe 参数。
- 私有原图永久保持无水印、不可覆盖；水印只烘焙进公开衍生图。首页/委托页横版大图和设定图的公开衍生图使用不重叠的左右双水印，竖版大图和出厂照使用单个居中水印；返图在 P1 使用独立的轻量水印配置。
- 发布是“生成/验证公开衍生对象 + 提交数据库公开引用”；下架是“先移除公开投影 + 删除公开衍生对象”。不再切换 Object ACL。
- 数据库只保存相对 Key 与业务标识，不保存环境相关完整 URL。管理端浏览器不直接接收私有 Object Key 或 OSS 签名 GET；下载与预览原图通过 `assetId` 访问认证、同源、`no-store` 的管理 API。

## 设计地基

- 第一视觉层级：作品图片 > 工作室名称/Logo/页名 > 必要事实与行动 > 装饰。
- 页面以白色和摄影为主，明显蓝色常态占 5%–10%，硬上限 15%。
- 主题色语义固定，不新增无证据的相邻蓝色。
- `agent_docs/materials` 中的工作室 Logo 是当前品牌源：完整组合标用于页头，适合小尺寸的图形标用于 favicon、触控图标与水印；具体导出和使用权仍由 EXT-01 manifest 收口。
- 首页首屏不得回到文字与图片等权的左右分栏；必须由 1–5 项代表作品轮播占据首个主要视口。每项横屏使用独立横版图、竖屏使用独立竖版图，不得仅靠同一张图改变焦点冒充双源适配。
- 公开内页一级标题复用同一紧凑页名尺度；`/works` 不使用接近首页 Hero 的超大标题。`/commission` 可以复用第一项已启用首页横/竖图片做单张背景引导，但不得复制首页轮播或回到左右等权营销面板。
- 轮播必须可手动切换、触控滑动和键盘操作；自动轮播默认关闭。若管理员开启，必须提供暂停控制，在 Hover/焦点进入时暂停，并在 `prefers-reduced-motion` 下停止自动切换。
- 生产视觉必须通过 390 × 844、768 × 1024、1440 × 900 三个固定视口截图审查，并由用户确认。

## 交互与验收地基

- 用户主动触发且可能明显超过即时响应时间的操作，例如上传、媒体处理、发布、全站重建、批量清理、导出、备份和恢复，必须在操作所在页面持续展示当前阶段与任务进度。总量未知时显示明确的不定进度；总量确定后显示真实的已完成/总数，允许刷新恢复的任务必须以服务端持久状态为准。不得只禁用按钮、显示旋转图标、弹出短暂 Toast，或等整个请求结束后才显示最终结果。
- E2E 是用户路径和页面质量门禁，不是用例数量门禁。每条关键路径必须验证实际交互、中间状态、成功/失败结果、重载恢复及关键可见内容；涉及图片和响应式页面时还要检查真实解码、布局溢出、焦点/键盘行为和规定视口。仅断言 HTTP 成功、元素存在、记录数量或“测试若干条通过”不能证明页面可用，评审必须结合浏览器日志、截图或 trace 认真检查页面结果。

## 安全与隐私

- 公开 DTO、日志、导出和错误响应不得包含联系人、返图授权备注、私有 Object Key、凭据、Session、签名 URL 或找回令牌。
- 管理写接口必须执行服务端认证、资源校验、Origin/Host/CSRF 防护、幂等或资源版本控制。
- 返图授权记录是轻量备忘，不做成法律合同系统；正式服务条款仍须由工作室确认并在上线前审阅。
- T26–T27 固定内容和营业状态使用独立“文案配置”管理入口，但继续复用受限字段与既有版本化 API，不演进为万能 CMS；公开投影每次正常 SSR/API 请求直接读取当前 SQLite，并使用 `no-store`，不返回后台版本、草稿标识、内部备注或作品私有联系人。

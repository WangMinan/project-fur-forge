# 管理端信息架构

> **角色**：当前管理端导航、页面分区、Card 边界、长任务反馈和响应式规则。
> **状态**：阶段 C.1 目标；现有文案页和部分 Hero 状态需按 T34-F3/F4 迁移。

## 1. 设计方向

管理端是安静、清晰、低误操作的编辑工具，不复制公开站的摄影叠字和大幅展示布局。

原则：

- 一个 Card 对应一个管理员能理解的业务对象或一次保存边界；
- 页面标题说明“在这里维护什么”，不展示内部任务号；
- 状态、冲突、失败和恢复靠文字与结构表达，不只依赖颜色；
- 不把十几个字段塞进一个无限增长的 Card；
- 危险操作明确确认；
- 长任务始终显示真实服务端状态。

## 2. 全局导航

一级导航：

- 作品管理；
- 首页与委托大图；
- 文案配置；
- 品牌水印；
- 账户。

当前页有清晰选中态。移动端可以折叠，但不得隐藏当前长任务和未保存状态。

## 3. 作品管理

### 3.1 列表

页面结构：

```text
标题与新增作品
查找、筛选、分页
作品表格或卡片列表
排序与精选控制
```

每件作品显示：

- 角色名、slug；
- 用途和装型；
- 发布状态；
- 设定图/出厂照摘要；
- 排序和精选；
- 编辑入口。

批量功能不在 P0 扩张。列表分页和搜索必须能定位刚创建的唯一作品，不依赖它恰好位于第一页。

### 3.2 编辑

编辑页按业务分区：

- 基础字段；
- 领养字段；
- 设定图；
- 出厂照；
- 发布状态和阻断项；
- 危险操作。

媒体上传、完成、预览、失败和重试保持在对应媒体分区。已发布作品禁止直接修改事实和媒体。

## 4. 首页与委托大图

同一页面或同一导航下使用清晰 placement 切换：

- 首页大图；
- 委托页大图。

两个 placement 共用组件，但请求、数据、反馈和操作记录按 placement 隔离。

每个大图项 Card 显示：

- 横版源摘要；
- 竖版源摘要；
- alt；
- 顺位；
- 可选关联作品；
- 启用状态；
- 无水印站点展示变体就绪状态；
- 低分辨率适配状态；
- 发布操作和恢复入口。

管理端预览可以显示私有原图或本次生成的站点展示结果，但必须明确：

- 公开 Hero 最终无水印；
- 预览不是永久公开原图；
- 低分辨率适配不会创造新细节。

首页至少保留一个启用项；委托页允许全部停用。错误提示使用稳定业务 reason，不匹配后端英文消息。

## 5. 文案配置

### 5.1 页面布局

页面头部只保留简短说明，下面使用独立 Card。推荐顺序：

1. 营业状态；
2. 官方联系方式；
3. 委托基础文案；
4. 委托 FAQ；
5. 关于工作室；
6. 服务条款；
7. 隐私政策。

桌面端可以使用两列栅格，但长正文 Card 应占满整行。移动端单列。

### 5.2 营业状态 Card

委托与领养各自一个小 Card，字段：

- tone；
- 状态标签；
- 一行详细说明；
- 固定公开链接提示；
- 独立保存。

两者视觉相同，不嵌在一个更大的“营业状态外壳 Card”中形成多层边框。

### 5.3 官方联系方式 Card

统一维护：

- 邮箱；
- QQ；
- 抖音号；
- 防诈骗提示。

不再让邮箱和 QQ 位于“首页设置”，抖音和防诈骗位于另一页面。迁移后首页设置只管理口号和轮播行为。

### 5.4 委托基础文案 Card

字段：

- 委托短说明；
- 人工估价说明；
- 邮件行动说明。

只保存当前 Card，使用独立版本。

### 5.5 委托 FAQ Card

- 每项有稳定 ID；
- 问题、回答和顺序；
- 新增、删除、上移、下移；
- 未填写完整时显示行内错误；
- 删除只影响当前草稿，保存后生效；
- 不使用数组下标作为持久 key。

### 5.6 关于工作室 Card

字段：

- 工作室事实；
- 制作范围。

提示管理员只填写可核对事实。空值对应公开区块隐藏。

### 5.7 服务条款与隐私政策 Card

两个独立整行 Card：

- 文本域有合理初始高度；
- 字数和校验提示靠近字段；
- 保存按钮固定在 Card 底部；
- 不把两篇长文塞入同一 Card；
- 隐私政策提示必须与网站实际数据收集一致。

### 5.8 Card 保存状态

每个 Card 独立具有：

```text
clean
dirty
saving
saved
conflict
error
```

规则：

- 页面其他 Card 保存时不禁用当前 Card；
- 同一 Card saving 时禁用自己的重复提交；
- saved 提示在再次编辑后消失；
- conflict 保留本地草稿，并展示最新服务端版本摘要；
- 管理员可以采用最新值或保留草稿人工比较；
- 不自动重发完整旧 payload。

## 6. 品牌水印

品牌页继续使用分区 Card：

- Logo 候选；
- profile 参数；
- 真实预览；
- 影响摘要与应用。

阶段 C.1 更新影响摘要：

- “作品保护图片”会重新生成；
- “首页、委托页和业务入口”是无水印站点展示位，不受 profile 变化影响。

应用过程中显示：

- 当前阶段；
- 已完成/总数或不定进度；
- 失败阶段；
- 清理待办；
- 刷新后恢复；
- 重试入口。

## 7. 账户

账户页提供：

- 当前用户名；
- 修改密码；
- Session 失效说明；
- 离线重置命令提示。

不在浏览器显示或生成管理员初始密码。

## 8. 全局状态与错误

### Loading

- 首次页面加载使用页面级状态；
- Card 保存只显示 Card 级状态；
- 不用全屏 Spinner 阻塞无关内容。

### Empty

- 无作品、无 Hero、无 Logo 候选均有下一步行动；
- 不使用虚假样例填满页面。

### Validation

- 行内显示；
- 聚焦第一个错误；
- 服务端 400 不丢失输入。

### Conflict

- 使用业务 reason 和资源版本；
- 说明哪一块发生变化；
- 重新加载对应资源，不刷新整站；
- 保护当前草稿。

### Operation failure

- 显示失败阶段和可理解动作；
- 内部错误码只用于映射和支持，不直接堆给景宸；
- 清理失败和重试状态刷新后仍可见。

## 9. 响应式

### 桌面

- 侧栏固定；
- 内容最大宽度受控；
- 短 Card 可以两列；
- 长正文和复杂媒体 Card 全宽；
- 操作按钮靠近所属 Card，不在页面最底部放一个全局保存。

### 平板

- 侧栏可收窄或折叠；
- 两列只在字段不拥挤时保留；
- Hero 横竖预览可上下排列。

### 手机

P0 允许查看和轻量编辑，但复杂品牌应用和大图媒体维护可以提示使用桌面。基本要求：

- 无横向溢出；
- 表单标签不被截断；
- 操作按钮有足够高度；
- Dialog 不超出视口；
- 长任务状态可查看；
- 不能因布局折叠而丢失保存和冲突提示。

## 10. 管理端验收

- 文案页面不再出现单个超长 `SiteContentCard`；
- 每个 Card 独立 dirty、save、saved、conflict；
- 同时打开两个管理上下文修改不同 Card，不相互覆盖；
- 同时修改同一 Card，后提交方收到可理解冲突；
- Hero 管理明确最终公开图无水印；
- profile 应用明确不影响站点展示位；
- 刷新、登录过期、429、400、409、500 和任务恢复均有可操作状态；
- 三固定视口无溢出和不可达操作。

## 1. 产品目标

系统为“有点小狗”备案网站提供图片主导的兽装主页和唯一管理员后台。完整工作室称呼可在介绍、作品主人或法务正文中按其各自已确认事实使用；公开导航品牌必须与备案网站名称分离。

阶段 C 已完成作品展示、常规领养、委托说明、首页维护、品牌水印、备份恢复和可重复部署配置。阶段 D 已增加：

1. 独立一级导航 `/returns` 的无水印返图墙；
2. 复用现有作品与领养管理的轻量展会掉落。

系统不建设交易、订单、排期、多管理员、万能 CMS、访客投稿或社交互动。

阶段 E 只增加最小化第一方访问统计并完成发布级 CI/独立 Review；阶段 F 完成备案品牌、两只现有 Bucket 私有化、CDN URL 鉴权、正式域名/TLS、升级、回滚和恢复演练。

产品阶段完成与正式发布就绪是不同结论：只有 T49–T53 全部关闭后才可声明正式上线就绪。

## 2. 访问面与路由

### 2.1 公开站

公开 Host 当前提供：

- `/`：首页；
- `/works`：作品列表；
- `/works/{slug}`：统一作品详情；
- `/adoptions`：常规领养与展会掉落；
- `/adoptions/{slug}`：兼容永久重定向到统一作品详情；
- `/returns`：独立一级导航返图墙；
- `/commission`：自设委托；
- `/about`：关于工作室和官方联系方式；
- `/service`：服务条款；
- `/privacy`：隐私政策；
- `/contact`、`/terms`：兼容重定向；
- `/robots.txt`、`/sitemap.xml`：SEO 基础。

`/returns` 是独立公开页面，不是作品详情内部的 Tab，也不建设单张返图详情路由。返图项进入 `/returns/{slug}` 设定页，设定页可选链接关联作品 `/works/{slug}`。

公开 Host 必须拒绝 `/admin/**`、`/api/admin/**`、认证接口、私有预览和其他管理路径。

### 2.2 管理端

管理 Host 当前提供：

- `/admin/login`；
- `/admin/works`；
- `/admin/works/new`；
- `/admin/works/{id}`；
- `/admin/site/home`；
- `/admin/site/content`；
- `/admin/site/branding`；
- `/admin/account`。

阶段 D 已增加：

- `/admin/returns`；
- `/admin/returns/new`；
- `/admin/returns/{id}`。

阶段 E T46 完成后增加：

- `/admin/analytics`：仅管理员可见的第一方访问统计。

展会掉落继续在现有作品列表和作品编辑页维护，不增加展会一级导航、展会管理页或展会详情页。

管理 Host 根路径进入登录流程。未登录访问受保护页面不得先显示任何私有数据。未实现功能不得出现可点击空入口。

### 2.3 媒体与上传 Origin

媒体公开 origin、OSS 上传 origin、公开 origin 与管理 origin 必须互不相同：

- 杭州生产 ECS 的服务端 OSS SDK 使用 `https://oss-cn-hangzhou-internal.aliyuncs.com`；
- 本地开发服务端使用杭州公网 Endpoint；
- 管理浏览器条件 PUT 使用私有 Bucket 杭州公网域名，不能出现 `-internal`；
- 公开图片只使用 CDN 媒体 origin，不能出现 OSS Bucket 域名。

应用只在测试环境暴露假媒体端点；生产环境不得注册测试控制路由。当前代码尚需在 T52-F1 将 `OSS_UPLOAD_BASE_URL` 真正接入签名链。

## 3. 作品领域

### 3.1 作品用途与装型

底层作品用途保持三种：

- `commission`：委托作品；
- `adoption`：领养作品；
- `showcase`：纯展示作品。

作品装型保持：

- `full`：全装；
- `partial`：半装。

管理端可以向景宸显示四个易理解的业务选项：

```text
委托作品    -> purpose=commission
常规领养    -> purpose=adoption, adoption_method=regular
展会掉落    -> purpose=adoption, adoption_method=event_drop
纯展示      -> purpose=showcase
```

不得为展会掉落新增第四种底层 purpose，避免复制领养价格、状态、设定图和发布规则。

### 3.2 基础字段

每件作品至少包含：

- 稳定 UUID；
- 唯一 slug；
- 角色名；
- 物种；
- 装型；
- 用途；
- 角色主人公开显示名；
- 可选私有联系人；
- 0–8 个短属性；
- 人工排序；
- 是否精选；
- 资源版本；
- 发布状态。

公开 DTO 必须把私有联系人固定投影为 `null` 或省略，不得因页面不同偶尔暴露。

### 3.3 领养方式、状态与展会字段

领养方式固定为：

- `regular`：常规领养；
- `event_drop`：展会掉落。

领养状态继续复用现有集合：

- `preparing`；
- `available`；
- `scheduled`；
- `in_production`；
- `delivered`。

展会掉落额外需要：

- `event_name`：展会名称，短文本；
- `event_time`：展会时间展示文本，可以表达单日、日期范围或已确认时段。

约束：

- `purpose=adoption` 且 `adoption_method=event_drop` 的**已发布**作品，
  两项均必须为非空；草稿允许暂时缺项，由发布检查
  （`EVENT_DROP_FIELDS_REQUIRED`）拦截，与 alt、设定图同一套心智；
- 其他作品的两项必须为空；
- 展会时间只用于公开展示，不触发定时任务，也不自动改变领养状态；
- 当前版本一件掉落作品只保存一组展会名称和时间；
- 不保存展会地点、摊位、主办方、封面、统一规则或展会历史。

领养价格可为空；存在时必须为正数人民币最小单位。网站只展示价格，不执行登记、抽选、定金、付款或退款。

### 3.4 发布状态

作品状态固定为：

- `draft`；
- `published`；
- `unpublished`。

已发布作品的事实字段和媒体关系不能直接修改，必须先下架。排序和精选等展示设置可以通过受限接口调整，但仍需资源版本校验。

已发布 slug 默认视为稳定公开地址。当前版本不建设 slug 改址历史；相关分享与长期 URL 策略记录在未来迭代备忘录中。

## 4. 返图领域

### 4.1 设定与返图

返图是与作品**完全独立**的模型：老作品没上过架、甚至没有建作品记录，也可以有返图。

层级只有两级：**设定**（`return_characters`）与其**返图照片**（`return_photos`）。一个设定可以有多张返图，横版竖版混放。不建设“批次”“相册”或第三级。

设定记录至少包含：

- 稳定 UUID 与公开 slug；
- 必填名称，例如“天暮”；
- 可选昵称，公开显示为 `@昵称`；
- 可选 `work_id`，关联一件已有作品。留空是正常状态，不影响返图发布；
- 主图指向该设定自己的一张返图；
- 资源版本与时间字段。

返图照片记录至少包含：

- 稳定 UUID；
- 必填 `character_id`，归属一个设定；
- 必填 `asset_id`，关联一张 `return_photo` 私有永久原图；
- 必填 alt；
- 是否为该设定主图；
- `draft | published | unpublished`；
- 资源版本与时间字段。

返图不设人工排序：公开返图墙每次请求随机打乱（见 11.1）。首版不维护返图长说明、返图者个人主页、社交账号或拍摄日期。

### 4.2 可选授权记录

返图可以保存以下可选后台字段：

- 授权来源或确认渠道；
- 授权确认时间；
- 内部备注。

这些字段：

- 只进入受认证的管理响应；
- 不进入公开 DTO、HTML、图片元数据、缓存、普通日志或公开导出；
- 缺失时可以显示后台提示，但不自动阻止保存或发布；
- 不形成法律审批流、附件上传或多级审核。

### 4.3 与作品解耦

返图的公开可见性只取决于自己：

- 设定的关联作品是可选的，留空时返图照常发布和公开展示；
- 返图能否发布**不取决于**关联作品是否已发布，也不取决于作品是否存在；
- 公开查询只要求返图照片本身为 `published`；
- 作品下架、重新发布或删除都不改变返图的公开可见性；
- 关联作品被永久删除时，设定的 `work_id` 置空，返图与私有原图保留。

设定页在有关联作品时给出一个作品入口，没有时不显示该入口。返图不改变作品发布状态，也不进入作品详情的出厂照图集或返图 Tab。

### 4.4 删除边界

阶段 D 不建设 30 天回收站，也不把通用 `deleted_at` 扩散到作品、返图和媒体。

- 已发布返图必须先下架；
- 首版必须完整支持下架；
- 永久删除不是阶段 D 的必做公开入口；
- 若实现草稿永久删除，只能使用明确影响说明和精确对象清理，不得假装可恢复；
- 删除设定前必须先处理它的返图照片；
- 不得因为没有回收站而删除私有永久原图生命周期保护或备份边界。

## 5. 媒体角色与上传

### 5.1 媒体角色

阶段 C 已实现：

- `design_sheet`：领养设定图；
- `studio_photo`：作品出厂照；
- 首页与委托页横竖 Hero 对应角色或 placement；
- `watermark_logo`。

阶段 D 增加：

- `return_photo`：返图私有永久原图。

角色必须与归属匹配：非领养作品不得绑定设定图；站点 Hero 与品牌 Logo 不得绑定到作品媒体关系；返图不得复用 `studio_photo` 冒充出厂照。

### 5.2 原图上传

浏览器通过条件 PUT 直传私有 OSS，Nitro 不代理图片二进制。创建上传会话时必须声明：

- MIME；
- 字节数；
- MD5；
- SHA-256；
- 宽高；
- 归属类型、归属 ID 和归属版本；
- 媒体角色。

上传会话有效期 5 分钟，Object Key 不可预测且禁止覆盖。服务端完成时重新验证 HEAD、摘要、真实 MIME、真实尺寸、EXIF 方向和角色约束。

支持 JPEG、PNG、WebP；原图最大 30 MB，最大边不超过 12000 px。水印 Logo 必须是带透明通道的 PNG。

失败重试创建新会话和新 Key，不原位覆盖。过期上传会话由主动清扫命令处理，OSS 生命周期只作为临时前缀兜底。

### 5.3 私有预处理

超过 OSS 图片处理输入限制的原图，或经管理员明确确认的低分辨率站点大图，可以生成私有 FFmpeg 处理源。处理源不能替代永久原图，也不能宣称恢复原图不存在的细节。

## 6. 公开媒体与水印

媒体公开行为只以 [`MEDIA-PUBLICATION-POLICY.md`](./MEDIA-PUBLICATION-POLICY.md) 为准。关键规则为：

- 首页 Hero、委托页 Hero和首页两个业务入口使用无水印站点展示衍生图；
- 作品列表、作品详情、常规领养和展会掉落使用活动 `brand-centered-v2` 水印；
- `/returns` 返图使用独立无水印公开衍生图；
- 永久原图、处理源、Logo 候选、管理预览和返图授权记录始终私有；
- 所有公开图片预生成、验证完成、去除不需要的 EXIF，并使用不可变 Key；
- 生成、验证和切换失败时保持当前公开版本。

阶段 F 的正式访问边界：

- 继续复用当前两只杭州 Bucket，但两只 ACL 都改为 private，并开启 Bucket 级 Block Public Access；
- 原图 Bucket 保存永久源、处理源和管理预览；网页衍生 Bucket 只保存 READY 网页衍生物；
- CDN 只对网页衍生 Bucket 使用同账号私有回源；其全 Bucket 读取能力由严格内容隔离约束；
- 原始 OSS Bucket 域名匿名 GET 均应 403；公开响应按鉴权方式 A 生成约 `86400` 秒有效的 CDN URL；
- 数据库不持久化完整 CDN 签名 URL，日志/错误/审计不记录完整签名 URL 或鉴权 Key；
- CDN 鉴权后忽略全部查询参数且不保留回源参数，公开页不能使用 `x-oss-process`；
- 浏览器缓存最长 86400 秒，CDN 节点可按不可变 Key 长缓存；媒体域名不开启响应过期缓存。

返图公开变体使用独立用途和配方，例如：

```text
usage = return-wall
recipe_version = return-display-v1
protection_mode = none
```

返图不关联活动水印 profile，水印 profile 切换不得改变返图 URL、摘要或内容。

## 7. 作品与返图发布

### 7.1 作品发布前检查

普通委托和展示作品至少需要：

- 完整有效字段；
- 至少 1 张 READY 出厂照；
- 恰好 1 张主出厂照；
- 全部公开图片有 alt；
- 所需作品水印变体完整；
- 活动水印 profile 可用。

所有领养作品还需要：

- 合法领养方式和状态；
- 至少 1 张 READY 设定图；
- 设定图 alt 有效；
- 价格字段成组有效。

展会掉落额外要求 `event_name`、`event_time` 非空。不得以缺少独立展会表为由阻止掉落发布。

### 7.2 返图发布前检查

返图至少需要：

- 归属一个设定；
- READY `return_photo` 私有资产；
- 有效 alt；
- 完整、READY 的无水印 `return-wall` SourceSet；
- 资源版本匹配。

可选授权记录缺失不作为硬阻断。设定的关联作品是否存在、是否已发布，都**不是**返图发布条件。

### 7.3 原子发布操作

作品和返图发布均必须：

1. 固化请求版本；
2. 生成缺失公开变体；
3. 验证公开对象；
4. 原子更新业务状态和公开投影；
5. 写入审计记录；
6. 失败时只清理当前 attempt 新建对象，保留旧公开状态。

下架先撤销公开状态，再精确清理不再引用的公开对象。阶段 F 接入 CDN 后还必须：

1. 固化不含鉴权参数的精确 CDN File URL manifest；
2. 调用 `RefreshObjectCaches`，`Force=true`；
3. 保存任务 ID并用 `DescribeRefreshTasks` 查询；
4. 刷新失败保留可恢复状态和 manifest，重启后继续收敛。

页面在数据库投影撤销后立即下架；用户已接受 CDN 服务器侧通常约 5～6 分钟完成撤销。不得把“页面已下架”冒充“CDN 已全网撤销”。运行中的发布/撤销不得被普通删除操作破坏。

## 8. 公开首页

首页顺序固定为：

1. 代表作品 Hero；
2. 精选作品；
3. 统一业务入口区；
4. 当前领养。

### 8.1 Hero

- 1–5 项；
- 横版和竖版为独立资产；
- 当前项才渲染图片，后续项按需加载；
- 自动轮播固定开启、10 秒一张，不是管理配置项；
- 悬停、焦点、页面隐藏和减少动效时暂停；
- 支持按钮、键盘和触控切换；
- 横竖图均使用无水印站点展示变体。

### 8.2 精选作品

最多展示 6 件已发布精选作品，按人工 `sort_order` 排列。这是全站唯一需要人工排序的位置。

精选顺序与精选勾选**在作品发布后仍可直接修改并立即生效**，不随作品字段一起被上架锁定：调整首页顺序不应要求先下架作品。

无精选时整区隐藏；精选接口失败不得导致首页 Hero 和导航整体 500，可以降级隐藏并记录安全日志。

### 8.3 统一业务入口

入口区最多包含两张统一卡：

- 自设委托；
- 角色领养。

每张卡包括独立无水印入口图片、业务标题、当前营业状态、一行短说明和明确行动入口。缺少可用图片时使用受控无图状态，不得泄漏私有原图或任意借用其他作品。

### 8.4 当前领养

展示最多 2 件当前已发布领养，可以同时包含 `regular` 与 `event_drop`，并提供查看全部入口。

展会掉落卡片必须明确显示“展会掉落”、展会名称和展会时间。无可展示领养时整区隐藏。不增加独立“当前展会”首页区块。

## 9. 作品列表和详情

### 9.1 作品列表

`/works` 支持用途和装型的交集筛选，显示结果数量、当前筛选状态和清除入口。非法筛选参数不得抛 500，应返回空结果和明确提示。

公开排序为**越新的越靠前**（按发布时间倒序，后接稳定 ID）。人工 `sort_order` 只服务首页精选，不影响 `/works` 与 `/adoptions`，因此景宸不需要为每次新作品重排整站顺序。

作品卡保持统一比例，消费作品水印衍生图。列表只展示具有公开作品媒体的已发布作品；只有设定图、没有出厂照的领养可以出现在 `/adoptions`，但不进入 `/works`。

### 9.2 作品详情

统一详情包含：

- 角色名、物种、装型、用途；
- 角色主人公开显示；
- 短属性；
- 可公开领养价格；
- 设定图分区；
- 出厂照图集；
- 前后浏览；
- 相关作品。

## 11. 返图页

### 11.1 返图墙

`/returns` 是一级导航中的独立返图墙，展示收到的真实穿着返图，与标准作品档案分开。

页面结构：

```text
紧凑页面标题与短说明
原比例返图瀑布流 / 真实空状态
底部编号分页（含上一页 / 下一页）
页脚
```

页面不设置大 Hero、搜索、筛选、统计或热门区。

墙上每一项是**一张返图照片**，不是一个设定：同一个设定的多张返图都会出现在墙上，横竖混排。每页默认 24 条。

排序为**每次请求随机打乱**：返图之间没有优劣顺序，也不给景宸增加排序维护负担。随机种子按页面请求确定，同一次请求内分页无重复无遗漏。

返图墙是**纯净瀑布流**：只有图片，不标设定名称或任何说明文字。

点击任意一张返图进入该照片所属设定的返图页 `/returns/{slug}`，**不跳转到作品详情**。

### 11.2 设定返图页

`/returns/{slug}` 展示一个设定的全部已发布返图：

```text
圆形主图 + 设定名称 + @昵称（有则显示）
该设定全部返图的原比例瀑布流
可选的关联作品入口（没有关联作品时不显示）
```

主图使用该设定自己指定的一张返图。页面不建设返图者个人主页、搜索、点赞、评论、公开投稿或访客账户。

### 11.3 瀑布流

`/returns` 与 `/returns/{slug}` 使用同一套瀑布流：

- 使用真实图片固有宽高维持原比例；
- 采用 masonry/瀑布流，而不是统一 3:4 强裁切；
- 图片统一圆角矩形，与 `/works` 保持一致；
- DOM 顺序、键盘顺序和屏幕阅读顺序保持一致；
- 图片加载前保留尺寸，避免明显 CLS；
- 使用底部编号分页，链接可在 SSR 和无 JavaScript 环境下工作；
  不使用自动无限滚动，也不以“加载更多”为默认交互；
- 单图失败显示受控错误状态，不使整页或导航 500。

### 11.4 公开数据边界

公开返图 DTO 只包含：

- 公开返图身份；
- READY 无水印 SourceSet、宽高和 alt；
- 所属设定的公开名称、可选昵称、slug 和 href。

设定页额外包含可选关联作品的公开名称、slug 和 href。

不得包含授权来源、授权时间、内部备注、私有联系人、私有 Object Key、私有 OSS 签名 URL、原文件名或 EXIF。阶段 F 允许包含为当前页面生成的约 24 小时 CDN 鉴权 URL。

首版不提供返图者主页、搜索、点赞、评论、公开投稿或访客账户。

## 16. 阶段 E 最小访问统计（T46 目标）

### 16.1 收集范围

只建设第一方、同源、最佳努力统计，允许以下白名单事件：

- 页面浏览；
- 作品详情浏览；
- 返图设定页浏览；
- 官方联系方式行动（只保存行动类别，不保存目标地址或联系内容）。

服务端只保存：事件时间、规范 `route_key`、可选公开实体 ID、可选 `action_key`、HMAC 后的会话标识。

明确不保存：IP、User-Agent、Referer、原始 URL、查询串、Cookie、localStorage、联系方式、表单正文或浏览器/设备指纹。不接入第三方统计平台。

### 16.2 会话、保留与写入

- 客户端随机会话 ID 只放 `sessionStorage`；
- 服务端使用现有 Session Secret 和固定域分离前缀做 HMAC，只保存摘要，不保存原值；
- “会话”只表示浏览器会话级近似，不宣称精确独立访客；
- 原始事件滚动保留 90 天，清理幂等，不增加常驻 worker；
- 公开写接口使用严格 Schema、小 body、专用限流和稳定安全错误；
- 客户端使用 `sendBeacon` 或 keepalive fetch；失败不得阻断页面、导航或媒体；
- 健康检查、媒体请求、管理页面和仅 SSR 未运行客户端脚本的机器人不计入。

### 16.3 管理端

`/admin/analytics` 只提供今日、7 天、30 天：页面浏览、近似会话、热门页面/作品/返图和联系行动计数。不得建设公开排行榜、实时大屏、导出中心、任意维度查询器、用户画像或转化归因。

隐私政策必须在 T46 由用户确认最终公开文案，并与实际字段、用途和 90 天保留一致。当前规格不替代法律意见，也不授权 Agent 自行持久化未确认公开文案。

## 17. 认证、安全与隐私

- 只允许一个活动管理员；
- 密码使用强哈希；连续失败可以锁定账户；
- 改密和离线重置使旧 Session 失效；Session 空闲上限 8 小时；
- 管理写请求验证管理 Origin、Session 和 CSRF；
- JSON 请求体限制 64 KiB；
- 登录与管理写入按可信主体限流；
- 可信客户端 IP 只从明确配置的反向代理链取得；
- 错误响应使用稳定 `code` 和业务 `reason`；
- 管理响应使用 `no-store`、`noindex`；
- 日志不得记录密码、用户名明文、邮箱、联系人、返图授权记录、Session、Cookie、签名 URL、AK/SK 或私有 Object Key。

## 18. 长任务与恢复

适用于作品、Hero、品牌 profile、站点展示 reconcile、返图公开生成/发布，以及阶段 F 的 CDN 强制刷新。

每个 operation 至少包含：状态、请求版本、进度、失败阶段、稳定失败码、已创建对象清单、attempt、lease owner、lease 到期时间、heartbeat、recovery reason、必要的下一次重试时间和完成时间。

容器启动时扫描未终止 operation：可安全重放则重新取得 lease；不能安全重放则转为可恢复失败；已提交业务状态但未写终态时通过幂等核对收敛；清理失败保留精确对象清单；重复重启不得产生重复公开对象或破坏旧有效版本。

当前没有阻断 T46/T49/T50 的业务开放问题。T51/T52 上线时仍需用户提供：正式公开/管理/媒体域名、真实 ICP 备案号、URL 鉴权主/备 Key 已设置状态、月度预算、基于目标环境实测确定的 CDN 用量封顶数值，以及 EXT-01 已登记素材是否就是正式上线素材的确认（不是则只提供替换项）。占位值不能被视为完成。

实现者可以在不改变公开行为、数据事实和管理心智模型的前提下完成局部技术取舍；若新问题会改变本契约，必须先更新规格并取得用户确认。

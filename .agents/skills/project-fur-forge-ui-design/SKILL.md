# 有点小狗 UI 设计原则

让用户看得懂、点得准、知道发生了什么，并能从失败中继续。公开站让角色和摄影成为主角；管理端让内容维护任务清楚、可靠。安静的界面不等于缺少状态，有性格也不等于装饰堆叠。

## 范围与协作

- 这是跨页面的设计判断层，不是另一套设计流程、组件库或像素模板。与 `design-flow` 配合时，把本原则用于 brief、tokens、实现和 review；局部任务直接使用相关章节，不重跑完整访谈。
- 先读仓库根的 `CLAUDE.md`、`agent_docs/README.md`，再按任务读对应 STATE、SPEC、TASKS、COPY、design 及后续覆盖条款。纯假设情景只定向核对会影响建议的契约，不扩成全站审查，也不把题设写成已发现的代码缺陷。所有仓库路径相对根目录；找不到路径时先搜索新位置。
- **现有页面不是原则的上限。** 不因首页已经这样做就保留缺陷；可以提出与现状不同的目标。区分一般视觉习惯与明确冻结的设计契约：前者可在已授权的 UI 任务中改进，后者指出冲突和目标，待相应范围获授权后再同步契约与实现。原则本身不代表已修复或验收。
- 保持业务、媒体、隐私和安全边界：不为“空态”增加访客账号或订阅，不为“离线”缓存私有图片或申请 PII，不恢复退役功能，不用 UI 便利绕过删除确认。
- 只提出或修改本次目标需要的内容。创建原则、只读评审、代码实现分别按用户请求执行；不顺带重构首页，不把历史阶段限制扩成永久禁令。

## 工作方式

1. **明确任务与主行动。** 用户此刻要看作品、提交申请还是维护内容？确定当前区域的主要视觉焦点和下一步；次级动作可以存在，但不等权争抢。
2. **按任务核对链路。** 评审当前实现或准备改代码时，从目标页面、共享组件追到异步结果和恢复入口，列出实际会出现的状态；修改共享组件前搜索所有调用方。纯方案按题设分析，只对拟用能力做必要核验。先复用，再考虑局部补齐。
3. **补全相关状态与反馈。** 用下方规则说明触发条件、用户可见内容、可用行动、失败后保留什么。无需为不可能出现的状态建框架。
4. **收敛视觉。** 先改信息分组、对齐、间距和层级，再调颜色与装饰；复用语义 token，不新增一套页面专属色板。
5. **按范围验证。** 文档只检查结构、链接与规则一致性；实现用真实浏览器验证相关状态和输入方式，再执行仓库要求的代码检查。输出已验证与待验证事项，不能以截图或自动测试代签真实手机和审美验收。

首次应用或需要溯源、判断图片中数值是否应采用时，读 [来源与项目映射](references/source-and-project-map.md)。

## 1. 表单：标签一直在，错误能修正

| 状态 | 设计要求 |
| --- | --- |
| 默认 / 空值 | 保留可见且关联控件的 label；必要时标注必填、单位、格式。placeholder 只放有帮助的示例，不能代替标签；不要只写“请输入”。 |
| 聚焦 | 明确显示焦点，聚焦环不被裁切、不引起布局跳动；键盘也可识别。不为装饰强制隐藏仍有用的占位示例。 |
| 已填 | 输入值与辅助信息层级清晰，失焦后标签仍可见。“已填”不代表“校验通过”，不自动加成功勾。 |
| 错误 | 就近说明问题和修正方法；不能只标红。关联 `aria-invalid`、`aria-describedby`，提交失败可定位首个错误；不要每敲一个字就打断或重复播报。 |

- 另按真实流程处理只读、禁用、校验中、提交中和提交结果；这些是可叠加状态，例如已填且聚焦、已填但错误。
- 保留失败前的输入和可恢复的上传状态；会话失效或上传失效时说明下一步，不能假装文件仍可用。需要保护内容时保持在当前页面内存，不自行写入 localStorage、日志或公开 URL。
- 清空按钮只用于确有价值的输入，如搜索；提供可访问名称和足够命中区，清空后保留合理焦点。不要给每个金额、测量、只读字段机械加叉号。
- 禁用需要解释如何恢复；若“禁用提交”会使错误原因无法发现，考虑允许触发校验并就近提示，仍保留防重复提交与业务门槛。
- 中文申请表、公开中英界面、中文后台分别遵守现有语言边界；不要因为原则提到英文就扩展表单国际化。

## 2. 按钮：五种状态之外，还有键盘焦点

| 状态 | 设计要求 |
| --- | --- |
| 默认 | 文案说明动作与对象，如“保存修改”；主要动作突出、次要动作降权。导航用链接，执行动作使用按钮。 |
| Hover | 只在支持 hover 的设备上增强可点击感；沿现有 hover token 变化，触控不能依赖悬停才看到入口。 |
| Pressed | 按下立即产生视觉响应，不等请求返回；可用背景或轻微形变，不移动周围布局。 |
| Focus-visible | 键盘焦点独立于 hover 清楚可见；不能因为移除了默认 outline 就丢失定位。 |
| Disabled | 既表达不可用也保留可读性；必要时就近给出原因。真正阻断鼠标、触控和键盘触发，`aria-disabled` 本身不会阻断行为。 |
| Loading | 立即表示已接收操作，使用“上传中 / 保存中”等具体文案；防重复触发，保持按钮尺寸稳定，完成或失败后退出忙碌态。 |

- 选择、展开等持久状态不等于按下瞬间；需要时使用 `aria-pressed` / `aria-expanded` 及对应视觉，不把所有按钮都做成 toggle。
- 使用现有 `PublicAction`、管理端 `Action` 和它们的语义/状态模式；共享组件不满足时修正共同原因，不在调用处重复补丁。
- 独立按钮、图标控制和触控入口以 **至少 44 × 44 CSS px 的实际命中区**为项目默认目标，图标本体可小；命中区不能覆盖相邻操作。正文行内链接按阅读语义处理，不硬撑行高。
- 交互反馈以用户感知即时为目标，约 100ms 是检查预算，不是故意延迟，也不是要求请求在 100ms 内成功。reduced-motion 下用颜色、描边和文本保留反馈。

## 3. 页面与异步任务：正常态之外也能走通

| 状态 | 内容与行动 |
| --- | --- |
| 无内容 | 区分首次无数据、暂无可领养角色与筛选无结果。说明原因，有真实下一步时提供一个主要行动；没有就不造按钮。首页无领养隐藏整幕与目录空态可采用不同策略。 |
| 加载 | 保持已有内容和页面框架，局部忙碌用局部提示；已知布局的首次加载可用骨架。图片预留比例，避免内容解码后跳动。 |
| 错误 | 说明受影响的操作、当前结果和可采取的补救。字段错误就近，列表失败留在列表，页面级失败才使用页面状态；不泄露内部异常或私有数据。 |
| 网络异常 | 有证据才区分离线与服务失败；浏览器网络信号只是线索，无法确定时说“连接未成功”，不要断言服务器挂了。恢复连接不等于写入成功。 |

- 不必等到 1 秒才反馈。约 1 秒仍未结束时检查用户是否知道正在等待；更久时补充真实阶段、已等待时间和可用的取消/恢复方式。快请求不强加骨架闪烁或最低等待时间。
- OSS 上传显示真实字节比例；处理、核验、发布使用已有阶段、计数、elapsed 或 indeterminate。上传 100% 不等于发布成功，禁止定时器假进度。
- 重试只在安全且受支持时出现。读取可重试；写入超时可能已成功，先核对已有状态查询或幂等/恢复能力，不盲目重发，不假装可撤销。若当前流程没有结果查询能力，保留“结果尚未确认”并提供已有联系路径，不能画出虚构查询按钮或顺带新增接口。
- 无权限、会话到期、资源不存在和主动取消各给相符的行动，不统统包装为“稍后重试”。
- 单张媒体失败保留画布比例与替代信息，不拖垮整页；公开内容 SSR 默认可见，不以 JS、动效或图片全部加载完成作为显示正文的前提。

## 4. 反馈分级：按用户下一步选择载体

| 用户需要什么 | 首选载体 | 项目例子 |
| --- | --- | --- |
| 知道一次轻量操作的结果 | 就近 status / 轻提示 Toast，不抢焦点 | 复制邮箱成功，保持按钮文案和位置稳定 |
| 修正字段或理解局部问题 | 字段 / 区域内 Inline | 申请字段校验、图片上传失败 |
| 持续观察一个任务 | 区域内任务进度和持久结果 | 上传、处理、发布；复用管理端 `TaskProgress` |
| 必须作出有后果的选择 | Modal 或当前流程中的明确确认 | 放弃未保存修改、执行已授权的单条删除 |
| 记住关键结果或继续后续步骤 | 持久结果区 / 结果页 | 委托投递回执，不能只出现 2 秒 |

- 不用“保存成功，请确定”弹窗打断普通操作；也不要把重要错误放进很快消失的 Toast。
- Toast 时长取决于内容和阅读需要，不统一锁成 2 秒。关键操作或可行动消息保持足够可达；含按钮时支持键盘访问并在焦点停留期间避免消失。仅当系统真的支持撤销时才提供撤销。
- 优先复用局部反馈，避免一次动作同时弹窗、Toast、红条三重提示。普通结果使用 `role="status"` 或适当 polite live region；紧迫错误才用 alert，避免每次进度刷新打断朗读。
- Modal 一次只处理一个决策，避免嵌套；提供标题、初始焦点、焦点约束、取消/关闭路径及关闭后的焦点恢复。危险操作不默认聚焦确认，文案明确对象和后果；执行中关闭不等于取消服务端任务。

## 5. 视觉减法：把注意力留给内容

- **色彩按职责分配。** 中性底色承托内容，层次色划分区域，品牌强调色指向主行动和必要焦点；错误/成功使用语义色并辅以文字。照片天然多彩，不把摄影像素算进 UI 配色占比，也不为凑比例给照片降饱和。
- **60/30/10 是权重提示，不是面积验收。** 不强制改成截图的亮蓝色，不要求纯色只能占 5%，不把“一个品牌强调色”误解成禁用状态色。具体用色沿用现有 token，并检查实际背景上的可读性。
- **先留白分组，再加线。** 相关信息近、组间距离更大；删去无作用的卡片套卡片、重复描边和阴影。表格、输入边界及需要辨认的分隔仍应保留，不能为极简牺牲可用性。
- **间距有节奏，不硬凑 8 的倍数。** 优先已有 4/8 基准的间距 token；8/16/24/32 可作为常见节奏，12/20 等中间档和光学微调可以成立。卡片内边距按密度与视口选择，不强制所有后台列表 24px 起步。
- **建立对齐关系。** 同一信息组共享对齐轴、基线和边缘；品牌展示可居中，表单和长文优先便于扫描的对齐。允许不同区域有不同构图，不把整站统一成一个居中模板。
- **字重少而有职责。** 正文与强调两类优先，必要时保留清晰的第三层；复用现有字体角色和真实字体字重，不强改为 400/700。标题、正文、辅助信息用字号、间距与对比共同建立层级，不能只靠把辅助字变得很淡。
- 普通正文对比度以至少 4.5:1 为底线，大号文字按适用条件至少 3:1；检查实际前景/背景及照片叠字，不照抄 `#999`、`#EAEAEA` 或统一 opacity。标准与例外见来源文件。
- 中英文换行、长角色名、200% 缩放和窄屏都应保留任务顺序；不靠固定高度、隐藏溢出或整体缩小桌面画布解决拥挤。
- 品牌性格来自角色图像、构图和有原因的细微动效；不默认引入新字体、动画库、Toast 库或离线系统。

## 验证与交付

对实际涉及的页面/组件给一份紧凑记录即可，不为每次调用另建全套设计文件：

| 对象与触发条件 | 现状 / 问题及影响 | 目标与最小改动 | 证据 / 未验证项 |
| --- | --- | --- | --- |
| 例：提交写请求超时 | 只闪过错误，结果不明可能重复提交 | 持久提示；沿既有恢复链路核对结果 | 待模拟响应丢失验证 |

- 优先级先看无法操作、错误不可恢复、内容丢失或误触，再看层级与装饰。没有问题就不要硬凑 finding。
- 浏览器覆盖受影响的桌面/窄屏、鼠标/键盘/触控、focus、禁用/忙碌、慢请求/失败/恢复、reduced-motion，以及图片 decode、溢出和 console/network。不相关的项目写明不适用。
- 对照当前需求的视口与语言范围检查；公开中英界面均考虑长文本，中文后台不因此新增翻译。浏览器自动化先等待水合，不把尚未可交互的 SSR 控件当成最终行为。
- 执行 `CLAUDE.md` 要求的适用检查；只为高价值稳定行为留下最小回归检查，不锁死截图里的颜色、字数、毫秒、DOM 或 class。文档创建不运行应用全套测试。
- 报告里分别注明原则建议、已实施改动、自动检查、真实浏览器、独立 Review 与用户人工验收；未执行就直说。只读任务到建议为止，实施任务完成已授权修改后再交付。

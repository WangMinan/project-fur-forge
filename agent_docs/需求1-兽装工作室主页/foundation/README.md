# 兽装工作室主页 · 产品地基

> **角色**：定义长期稳定的产品目标、用户、范围和不可突破的边界。当前阶段和任务状态不在本文件展开，见 [`../STATE.md`](../STATE.md)。

## 1. 产品目标

为“有点小狗工作室”建设一个以兽装图片为主体的公开主页和轻量管理后台。

公开站首先服务于三件事：

1. 让访客连续、清晰地浏览作品；
2. 让访客理解自设委托和角色领养的当前状态与基本方式；
3. 让工作室能够维护作品、首页展示、业务状态、固定文案和品牌媒体，而不依赖开发人员逐次改代码。

管理后台面向单一工作室管理员，不追求通用 CMS、多人协作平台或交易系统。

## 2. 核心设计原则

景宸确认的长期原则保持不变：

> **网站要简洁，以图片为主；Logo、文字介绍和符号都只为兽装展示提供辅助。**

据此形成以下约束：

- 兽装图片始终是公开页的最高视觉层级；
- 文字只说明图片不能表达的事实、状态和行动方式；
- 不使用复杂装饰、密集卡片和过度动效抢夺注意力；
- 首页、列表、详情、委托和领养应使用同一视觉语言；
- 管理端强调清晰、可恢复和低误操作，不模仿公开站的摄影排版；
- 所有公开业务文案应便于非技术人员理解，不出现内部任务号和中英混杂术语。

## 3. 用户与访问面

### 3.1 公开访客

公开访客可以：

- 浏览首页代表作品和精选作品；
- 浏览作品列表并按用途、装型筛选；
- 查看作品详情、设定图、出厂照、属性和公开价格；
- 浏览当前常规领养；
- 查看委托范围、人工估价方式、营业状态和官方联系方式；
- 查看关于工作室、服务条款和隐私政策。

公开访客不能：

- 访问原图、私有处理源、后台预览或 Logo 私有源；
- 查看角色主人私密联系方式；
- 在线登记委托、支付定金、付款或自动获取报价；
- 修改站点内容。

### 3.2 唯一管理员

唯一管理员可以：

- 创建、编辑、发布、下架和删除作品；
- 管理设定图、出厂照、排序、主图和公开属性；
- 管理首页与委托页大图；
- 管理委托、领养营业状态和固定文案；
- 管理水印 Logo 候选和活动水印 profile；
- 查看长任务进度、失败原因和恢复入口；
- 修改密码并通过离线命令重置密码；
- 执行备份、恢复和部署维护。

管理员不能通过后台任意编辑数据库字段、输入任意 Object Key、上传任意脚本或绕过媒体角色约束。

## 4. P0 范围

P0 是可维护、可恢复、可部署的最小正式站点，包含：

- Nuxt 公开 SSR 与管理端 CSR；
- 公开域名和管理域名隔离；
- SQLite/Drizzle 与版本化迁移；
- 唯一管理员认证、Session、Origin、CSRF、限流和日志脱敏；
- 双 OSS Bucket：私有原图与公开衍生图分离；
- 作品、常规领养、首页、委托、关于、政策页和固定文案；
- 角色化媒体上传、服务端核验、公开派生、发布、下架和清理；
- 可配置活动水印 profile；
- 备份、验证恢复、空环境迁移和管理员初始化；
- 标准 Node 24 镜像、Compose、Nginx、健康检查和 CI；
- 三视口真实浏览器与全链验收。

P0 当前媒体保护边界以 [`../requirements/MEDIA-PUBLICATION-POLICY.md`](../requirements/MEDIA-PUBLICATION-POLICY.md) 为准。

## 5. P1 范围

P1 可以在 P0 总门禁后增加：

- 返图模型、授权记录和返图墙；
- 展会掉落、当前展会和完整状态矩阵；
- 在现有受限字段基础上的更多站点内容维护；
- 显式 slug 改址历史；
- 30 天回收站；
- 手机轻量维护闭环。

P1 不得削弱 P0 的私有/公开 Bucket、媒体身份、版本冲突、发布原子性和部署恢复能力。

## 6. P2 范围

P2 可以按实际价值选择：

- 邮件找回密码；
- 安全 CSV 导出；
- 永久原图档案 UI；
- 最小化访问统计；
- 高级媒体恢复和批量运维；
- CDN 专项优化。

这些能力不阻塞 P0 上线，也不得提前引入多租户、支付、排期和复杂订单系统。

## 7. 明确不做

当前可预见范围内不建设：

- 在线支付、定金、退款和结算；
- 自动报价；
- 委托排期与订单流转；
- 用户注册、访客账户和社交互动；
- 多工作室、多租户和角色权限矩阵；
- 任意页面搭建器或万能富文本 CMS；
- 公开原图下载；
- 依赖客户端查询参数临时加工图片的媒体方案。

## 8. 数据与隐私边界

- 公开 DTO 只包含公开展示所需字段；
- `ownerContact`、私有 Object Key、签名 URL、AK/SK、Session 和内部错误不得进入公开响应；
- 公开价格只使用人民币最小单位存储，网站不执行交易；
- 官方联系方式由管理员维护，但必须明确官方渠道和防诈骗边界；
- 管理响应、预览和错误页使用 `no-store`；
- 日志只记录必要的请求、任务和错误分类，敏感值统一脱敏。

## 9. 媒体边界

- 原图和处理源永久私有；
- 公开页只消费预生成、验证完成的衍生图；
- 站点展示位无水印，作品展示位使用活动水印；
- 公开图片身份不可变，配置变化生成新对象；
- 发布、profile 切换和清理失败不得破坏当前公开版本；
- 首页业务入口使用独立派生用途，不直接复用其他页面的公开 URL。

详细矩阵、迁移和验收只在媒体策略文档中维护，其他活文档不得复制完整规则。

## 10. 技术基线

当前技术基线：

- Nuxt 4、Vue 3、Nitro Node Server；
- Node.js 24、pnpm 11；
- TypeScript strict、Zod；
- SQLite、Drizzle；
- 阿里云 OSS 双 Bucket；
- FFmpeg 仅用于必要的私有预处理或经管理员确认的站点大图适配；
- Docker Compose 与 Nginx 作为正式部署入口；
- Playwright、Vitest 和 GitHub Actions 作为质量门禁。

技术方案的当前拆分和迁移顺序见 [`../planning/PLAN.md`](../planning/PLAN.md)。

## 11. 完成定义

P0 只有在以下条件同时满足时才可宣布上线就绪：

- 公开站和管理端业务链通过；
- 媒体保护矩阵与真实请求一致；
- 所有长任务可观察、可失败、可恢复，容器重启不造成永久卡死；
- 空数据卷能够执行迁移、初始化并进入 ready；
- Compose、Nginx、数据卷、备份、升级和回滚有版本化配置与演练记录；
- CI 核心门禁通过；
- 三个固定视口无坏图、异常裁切和横向溢出；
- 用户完成最终业务和视觉验收。

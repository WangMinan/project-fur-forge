## 1. 联调问题与修复

- 运行配置：命令脚本与服务端统一装载仓库 `.env`，仍保持进程环境变量优先；缺失公开/后台/媒体/上传 origin 时继续快速失败。
- 数据迁移：迁移期间按 SQLite 约束安全处理自引用 variant 外键，并在提交前执行外键检查；真实开发库完成增量迁移且无外键违规。
- Nuxt 启动：补齐 `compatibilityDate`，确认正确启动参数后 `/admin/site/branding` 进入生产页面而非框架欢迎页。
- 真实预览：GATE-07 不再循环依赖尚未实现的 T20 首页素材；有 READY 出厂照时可生成 3:4、原比例、16:9、9:16 四比例真实 OSS 预览。样张缺失或操作失败会落入可重试失败态，不留下永久进行中的僵尸操作。
- 版本冲突：409 后同时刷新 branding 和最近操作，成功保存/预览/应用/重试后清除旧冲突提示。
- 全站应用：确认后先返回持久化操作 ID，再在同进程后台完成公开图生成、核验、原子切换和清理；页面每 2 秒读取真实计数，并以原生进度条持续展示“正在统计 / 已生成 / 已核验 / 待清理 / 完成或失败”。

## 3. 固化的后续质量规则

1. 上传、处理、发布、全站重建、批量清理、导出、备份和恢复等长耗时任务必须提供持续、可访问、基于真实服务端状态的进度。总量未知时显示不定进度，总量确定后显示完成量/总量；失败持续可见，可恢复任务支持刷新后继续查看。
2. E2E 不是数量门禁。每条关键用例必须围绕真实用户路径验证前置、操作、中间状态、成功/失败、重载恢复和页面结果；图片解码、响应式溢出、焦点/键盘、关键请求和浏览器错误按风险检查。HTTP 200、元素/记录数量、选择器存在或总通过数都不能单独证明页面质量。

这些规则已同步到 Foundation、SPEC、PLAN、模型投影、设计契约、TASKS、STATE、执行路由和 Review。

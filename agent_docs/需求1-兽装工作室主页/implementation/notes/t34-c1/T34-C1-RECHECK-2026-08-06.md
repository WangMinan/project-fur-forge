## 5. 镜像构建问题收敛过程

### 5.1 依赖构建脚本被拒绝

首次镜像构建因 Dockerfile 没有复制 `pnpm-workspace.yaml`，pnpm 11 无法读取已经审查的 `allowBuilds` / `strictDepBuilds`，报 `ERR_PNPM_IGNORED_BUILDS`。

修复后，依赖 fetch、离线 install、better-sqlite3、ffmpeg-static、esbuild 和 unrs-resolver 脚本均成功。

### 5.2 workspace deploy 未选项目

随后 `pnpm deploy` 报 `ERR_PNPM_NOTHING_TO_DEPLOY`。原因是 deploy 面向 workspace package，必须显式选择根项目。

Dockerfile 改为：

```bash
pnpm --filter=project-fur-paws --prod deploy --legacy /app/deploy
```

### 5.3 deploy 目录与仓库部署配置碰撞

显式 filter 生效后，`pnpm deploy` 报 `ERR_PNPM_DEPLOY_DIR_NOT_EMPTY`：仓库已有 `/app/deploy/nginx`，不能把 production package 再输出到同一目录。

最终命令和 runtime copy 改为：

```bash
pnpm --filter=project-fur-paws --prod deploy --legacy /app/runtime-deploy
COPY --from=build /app/runtime-deploy/node_modules ./node_modules
```

# 需求2 · 产品地基

> **角色**：固定本轮增量需求的范围与不可突破边界。
> **基线**：继承 [`../../需求1-兽装工作室主页/foundation/README.md`](../../需求1-兽装工作室主页/foundation/README.md)；发生冲突时，需求1的安全、媒体和部署基线优先，本目录只覆盖本轮明确改变的产品行为。

## 1. 本轮目标

在不改变“图片优先、轻量后台、唯一管理员”方向的前提下，完成五组增量能力：

1. 合并公开导航中的委托入口；
2. 把官方平台联系方式扩展为可配置的 Logo、二维码和账号卡片；
3. 在委托 FAQ 中加入邮件估价标准模板；
4. 为作品、返图和领养增加按设定名称搜索；
5. 增加可由管理员维护的“最新动态”公开页与首页摘要。

## 2. 产品原则

- 公开页继续以兽装图片为最高视觉层级；搜索、Logo、二维码和动态只提供必要导航与信息。
- 优先复用既有导航下拉、公共筛选、分页、上传、媒体衍生、文案分区和管理列表模式。
- 平台账号、二维码和动态正文是数据，不在 Vue 模板里写死。
- 平台名称与 Logo 属于五种平台身份元数据，可由平台枚举统一映射；管理员只维护账号与二维码。
- 页面文字使用清楚中文，不向管理员暴露结构体、Object Key、迁移或媒体配方术语。

## 3. 模块边界

- `app/utils/public-nav.ts`、`app/components/PublicHeader.vue`、`PublicMobileNav.vue`：导航数据与现有下拉呈现。
- `shared/schemas/site-content.ts`、`server/utils/service/site-content.ts`、`site_content`：官方渠道与 FAQ 契约。
- 现有上传/资产/公开衍生链：二维码私有源图和无水印公开派生；不得建立第二套上传器。
- 公开作品/领养 repository 与公开返图 repository：服务端搜索、分页和公开 DTO。
- `/admin/site/content`：官方渠道与 FAQ；不承载最新动态。
- `/admin/updates`：独立维护最新动态，使用最小 `updates` 表。
- 新的 `/updates` 与首页聚合：只公开已发布动态。

## 4. 数据与安全边界

- 公开 DTO 只返回展示所需的平台、账号和 READY 二维码 SourceSet，不返回私有资产 Key、上传会话或签名 URL。
- 二维码源图保存在私有源图 Bucket；公开页只消费预生成、验证完成、无水印的公开派生图。
- 搜索只接受长度受限的纯文本 `q`，不记录查询词到访问统计、日志或数据库。
- 动态正文首版只允许安全纯文本，不接受任意 HTML、脚本、外链嵌入或富文本。
- 新数据继续使用显式版本和 409 冲突处理；不静默覆盖其它管理会话的修改。

## 5. 明确不做

- 不发送邮件，不接 SMTP，不建设站内估价表单；
- 不建设访客投稿、评论、点赞、订阅或消息推送；
- 不建设通用 CMS、页面搭建器或富文本编辑器；
- 不给平台卡片增加在线登录、好友添加或支付能力；
- 首版动态不增加封面图、附件、详情路由、定时发布、标签系统或全文检索；
- 不为搜索引入搜索引擎、索引服务或新依赖。

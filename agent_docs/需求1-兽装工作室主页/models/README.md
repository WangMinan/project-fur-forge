# 模型说明

> **角色**：记录领域/数据模型的迁移、新增、校准状态与字段处理规则。
> **写入时机**：阶段 1–3，随契约演进更新。
> **边界**：与 `requirements/SPEC.md` 的「数据模型契约」互补——SPEC 写契约，本文件写现状与处理细节。

## 新增模型

- 当前尚无业务源码或 Drizzle Schema；以下逻辑模型已经由 SPEC/PLAN 锁定，并映射到 TASKS T09–T12：
  - `works`：一件作品对应一个角色的统一聚合；委托、领养和展示作品不拆表。
  - `slug_redirects`：保存作品显式改址产生的旧 slug，并永久跳转到当前 `/works/{slug}`。
  - `assets` / `work_assets`：保存私有原图、网页衍生组、图片来源、焦点/裁切、人工顺序和主图关系。
  - `publication_operations`：保存一次发布/下架的意图、逐对象 ACL 进度、补偿状态与人工处置结果；只服务中断后的人工继续/回滚，不作为任务队列或自动 worker。
  - `events`：当前展会及展会掉落关联；不保存历次展会关系。
  - `users` / `password_reset_tokens`：唯一管理员、认证安全状态和单次找回令牌。
  - `commission_faqs`、`site_content`、`business_statuses`：站点级可维护内容。
  - `trash_entries`、`audit_logs`：30 天回收站与操作账号/时间记录。
  - `page_view_daily`、`referrer_daily`、`device_daily`：不建立访客身份的最小化汇总统计。

## 已校准模型

- 2026-07-28：数据栈由历史 Spring/JPA/MySQL 方案改为 SQLite/Drizzle/`better-sqlite3`；旧类名、JPA 实体和 Flyway 表设计不再具有实施效力。
- 2026-07-28：统一作品聚合保持不变；角色领养列表复用 `/works/{slug}` canonical，不建立独立领养详情模型。
- 2026-07-28：媒体资产从“处理完成即公开”校准为“处理完成保持私有 READY，作品发布后才公开，下架后撤销公开访问”。
- 2026-07-28：阶段 3 Reader Test 补齐发布/下架跨 SQLite 与 OSS 的中断边界；使用持久操作记录支撑人工继续或回滚，不改变“无队列、无 worker、无自动恢复”的既定范围。

## 字段处理规则

- `works.slug` 首次发布后默认冻结；显式纠错改址必须写入 `slug_redirects`，旧地址永久 301。
- 作品展示顺序、角色领养列表顺序和首页精选顺序分别持久化；其中任一排序变化不得覆盖另外两类顺序。
- 人民币价格以最小货币单位保存，美元价格使用独立的保留字段且一期禁用；未来启用美元或增加语言内容不得改变作品 ID、slug 和既有关系。
- 领养方式与业务状态是独立字段；公开投影不得包含价格、领养人联系方式、定金/付款备注、原图 Key 或认证数据。
- 原图 Key 每次上传新建且禁止覆盖；上传会话绑定期望字节数、`Content-MD5` 和 SHA-256。
- 焦点及 3:4、16:9、1:1 裁切以 EXIF Orientation 1–8 修正后的显示画布为基准，保存归一化坐标。
- 媒体处理失败保留可读状态，由管理员手动重试；一期不建立任务队列、自动重试或容器重启自动恢复模型。
- 具体列类型、索引、唯一约束和迁移文件位置按 TASKS T09–T12 实现；阶段 4 未获授权前不创建 Schema 或迁移。

## 1. 结论摘要

本轮在干净临时 clone、唯一临时空库和真实双 Bucket OSS 上重放了作品创建、私有直传、媒体核验、发布、公开详情/列表/精选、首页横竖轮播、活动水印、品牌候选预览、全站原子切换、失败保持、安全边界与精确清理。高分辨率作品发布、公开投影、两条首页轮播、36 个活动水印 variant 和品牌原子切换均得到真实链路证据。

门禁仍发现 **3 个 must-fix、1 个 should-fix**：

1. 管理端作品原图预览和首页横竖预览把 OSS V4 短时签名 URL 直接写入 DOM；作品预览 URL 的 pathname 同时包含私有 Object Key。它违反“浏览器不直接接收私有 Object Key/签名 URL”的地基约束。
2. 上传契约接受 480×640、状态为 `READY` 的作品图，但发布配方要求生成 768/1200/960/1600/2400 等更宽输出；真实 OSS 不上采样，导致这类合法上传稳定发布失败。
3. 已发布作品被启用首页轮播关联时，下架触发数据库保护异常；接口返回未处理 500，并在事务外留下永久 `COMMITTING` 操作，后续重试被活动操作阻断。
4. 首页私有水印预览对象没有持久化清单或删除生命周期；本轮两条轮播共遗留 4 个对象，只能依据生产 key 公式重建后精确清理。

因此没有执行 T21 勾选，也没有更新 `STATE.md`、`EXECUTION_ROUTING.md`、`ARTIFACTS.md` 或 `review/REVIEW.md` 的完成态。

## 2. Findings

### MUST-FIX-01：管理 DOM 暴露签名 URL 和私有 Object Key

**复现**

1. 登录管理端，打开已上传作品详情。
2. 检查出厂照 `<img src>`：可见 OSS V4 签名查询标记，URL pathname 与数据库中的 `private_object_key` 完整一致。
3. 打开首页编辑器并生成横竖私有水印预览；两个 `<img src>` 同样包含 OSS V4 签名查询标记。
4. 对照品牌页：品牌候选和四比例预览使用同源管理 API，DOM 不包含上述标记。

**影响**

- 任何能读取管理页 DOM、前端异常快照或浏览器扩展数据的代码都可获得短时直连地址；作品预览还泄漏存储路径身份。
- 公开页面未发现该泄漏，但这仍违反浏览器边界，而不只是“公开 DTO”边界。

**源码锚**

- `foundation/README.md:68`：管理端浏览器不直接接收私有 Object Key。
- `app/components/admin/StudioPhotoCard.vue:71-80`：把 `entry.previewUrl` 直接写入 `<img src>`。
- `app/components/admin/HomeSlideCard.vue:352-359`：把横竖 `preview.*.url` 直接写入 `<img src>`。
- `server/api/admin/v1/media/assets/[id]/preview.get.ts:27`、`server/utils/home-management.ts:309`：直接返回 `signPrivateGet` 结果。
- 品牌页安全基线见 `server/utils/watermark-branding.ts:263`，候选使用同源管理 API。

**修复要求**

作品与首页预览统一改为认证、`no-store`、同源流式代理；DTO 和 DOM 只保留 `assetId`/同源路由，不返回或持久化 OSS URL、Bucket 或 Object Key。补 DOM、响应快照、错误和日志回归。

### MUST-FIX-02：合法低分辨率 READY 媒体无法发布

**复现**

1. 通过页面创建作品，真实直传一张 480×640 PNG。
2. 完成服务端 HEAD、摘要、格式、尺寸核验，资产进入 `READY`，作品发布检查允许继续。
3. 连续两次发布均持久化为 `FAILED / APPLYING_WATERMARK / PUBLIC_MEDIA_GENERATION_FAILED`；安全日志定位到 `work-card`、宽度 768 的真实 OSS 生成/验证失败。
4. 在同一环境上传仓库内 4672×7008 JPEG，发布成功并生成 12 个 `READY` PUBLIC variant，排除凭据、Bucket 配置和通用水印链路故障。

**根因**

- `shared/schemas/upload.ts:77-78` 与 `:161-162` 只要求宽高至少为 1。
- `server/utils/media-recipe.ts:83-107` 对作品要求 `work-card` 480/768/1200 和 `detail` 960/1600/2400。
- 真实 OSS resize 不上采样；契约允许进入 `READY` 的素材集合大于发布配方可完成的素材集合。

**修复要求**

在上传/完成核验或发布检查阶段给出与角色配方一致的最小有效尺寸，并返回可操作的 4xx blocker；如果产品决定允许小图，则配方必须显式降档且公开 DTO/`srcset` 与实际输出一致。不得把确定性输入不兼容留到异步 500/失败操作。

### MUST-FIX-03：轮播关联作品下架返回 500 并留下不可恢复活动操作

**复现与状态**

1. 发布高分辨率作品；创建并启用两条首页轮播，其中一条链接该作品。
2. 从作品管理页执行下架。
3. 服务端返回安全 `500 / INTERNAL_ERROR`；管理页等待超过 180 秒，没有进入失败或完成状态。
4. 数据库仍为 `published`，12 个作品公开 variant 仍为 `READY`；最新 `UNPUBLISH` 操作为 `COMMITTING`，无 failure stage/code、无 cleanup manifest。
5. 再次操作会被“已有活动 publication operation”阻断。

**根因**

- `server/database/migrations/0000_sparkling_absorbing_man.sql:399-407`：启用轮播链接作品时，触发器拒绝把作品状态移出 `published`。
- `server/utils/work-publication.ts:249-280`：`createOperation()` 在事务外先创建 `UNPUBLISH / COMMITTING`。
- `server/utils/work-publication.ts:584-645`：随后事务更新作品；触发器异常没有进入 `failOperation()`，直接冒泡为 500，事务只回滚作品/variant/操作更新，事务外操作行仍存活。

**修复要求**

下架前显式校验启用轮播引用并返回稳定 409 blocker，或在契约确认后原子解除引用；无论哪种路径，都必须保证操作创建、业务更新和失败落盘的一致性。任何触发器/SQLite/OSS 异常都必须落为可恢复 `FAILED`，不能遗留活动 `COMMITTING`。

### SHOULD-FIX-01：首页私有预览无持久化/清理生命周期

**证据**

- 两条轮播各生成横竖预览后，真实私有 Bucket 留下 4 个 `preview/home` 对象。
- 数据库的 `assets`、`asset_variants`、`publication_operations`、`watermark_operations` 均不记录这些 key。
- `server/utils/home-management.ts:255-264` 通过环境前缀、slide id、orientation 生成确定 key；`:267-309` 生成并签名返回，但文件内没有对应 `deletePrivate` 路径。
- 独立清理只能用相同生产公式，从 slide id 和两个源 asset 的私有 key 重建 4 个精确目标；`listV2` 仅用于集合对账。

**建议**

为首页预览建立可审计 manifest/到期时间，并在重新预览、启用、停用、删除和定期清理时执行幂等精确删除。它没有进入公开投影，本轮未提升为公开泄漏。

## 5. 安全与一致性复核

- 管理 API：认证请求 200 且 `no-store`；缺 CSRF 写请求 403；正确 `expectedVersion` 更新成功，旧版本重放 409 且 `no-store`。
- Host/Origin：本轮浏览器按 public=`127.0.0.1`、admin=`localhost` 分离；匿名访问管理 API 被拒。一个原始 HTTP wrong-Origin 探针因没有形成有效认证 Cookie 返回认证失败，不能替代独立的已认证 Origin 403 证据；现有集成测试通过，但复审仍应补浏览器上下文内的已认证 wrong-Origin 探针。
- Logo 候选：品牌管理 DOM 使用同源管理 API；公开首页/作品列表/详情的媒体 URL 集始终只包含活动 PUBLIC variant，未出现 Logo 候选私有源或签名标记。**没有对 Logo 候选私有源单独执行匿名 GET**，因此“Logo 候选匿名读取失败”本轮未独立证明。
- 管理浏览器/HTML/DTO：作品和首页预览已因签名 URL/私有 key 暴露判为 MUST-FIX-01。检查过的页面和响应中未观察到密码或 Session 值，但本轮没有留下对实际 AK/SK、Session、密码完整值的独立扫描证据，因此这些字段不能宣称已全面证明无泄漏。

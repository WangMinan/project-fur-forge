# 规格说明：ESA 故障维护页

## 状态与授权

2026-09-25：用户授权通过已鉴权 Aliyun CLI 创建自动兜底资源、移除旧维护规则和页面；后续明确要求不替换业务 5xx，自定义等待改为 10 秒，并直接 main 提交推送、删除本地 codex 分支。继承部署、Host、认证、缓存与媒体边界。

2026-10-09：用户在镜像更新期间遇到 Nginx 纯文本 503，明确授权修复并在当前现网窗口操作。新增 Nginx 自身代理故障标记，补齐容器停机兜底，同时修复 Nginx 对业务 502/503/504 的拦截；不扩大为所有 5xx 维护页。

## 目标与契约

公开与管理站点 HTML 页面导航在 ESA 返回 521/522、Nginx 返回带 `X-Ditedog-Origin-Failure: backend-unavailable` 的 503、fetch 网络异常或 10 秒内未获得响应时返回独立静态 HTML 503；其他 HTTP 响应（含业务 500/502/503/504）均透传。无需浏览器预缓存；ECS 整机不可用与 Nginx 存活但应用容器不可用分别由上述连接异常和专用标记覆盖。

Nginx 关闭 `proxy_intercept_errors`，仅对自身代理故障生成带标记的 503；去掉应用响应中的同名标记，不信任请求头标记。故障响应保留安全头，带 no-store、Retry-After: 60，不暴露内网地址。API/写请求/非 HTML 资源故障仍为纯文本 503，业务错误的状态、正文、Cookie 和重定向保持。

仅覆盖 ditedog.com / admin.ditedog.com 的 GET/HEAD、Accept 含 text/html、非 /api 与 /api/ 路径。API、写请求、OSS、管理预览、Nuxt 资源原链路保持；已打开页面不会自动替换。正常响应、重定向、Cookie、401/403/404/429 保持。无数据库或应用镜像变更。

兜底不请求 ECS、OSS 或其他外部资源；返回 no-store、Retry-After: 60，HEAD 无响应体。页面等待上限 10 秒，路由平台等待 30 秒，不对写操作设置此上限。旧强制 503 规则在新流程验证后精确清理，先保存本地备份。不重启或停止生产服务做故障演练。

## 验收

- AC-01：正常公开与管理页面、跳转保持，媒体/API 不被接管。
- AC-02：隔离路径验证真实代理连接失败与维护页；本地遍历 500–599，只有 521/522 与带专用标记的 503 替换，其他透传；验证 Nginx 业务 502/503/504 原文保留与标记剥离，保留慢请求成功、网络异常、10 秒超时及恢复检查。
- AC-03：云端代码版本、路由范围与旧资源清理有实测记录；完整生产停机演练不能由隔离模拟代签。

## 开放问题

无产品范围未决问题。平台兼容性以隔离验证决定是否启用生产路由。

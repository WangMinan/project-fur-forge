# Information Architecture：兽装工作室公开站

## Site Map

- 首页 `/`
- 作品展示 `/works`
  - 作品详情 `/works/{slug}`
  - 旧作品 slug `/works/{old-slug}` → 永久 301 到当前 canonical
- 自设委托 `/commission`
- 角色领养 `/adoptions`
  - 兼容详情 `/adoptions/{slug}` → 永久 301 到 `/works/{slug}`
- 返图墙 `/returns`
- 关于我们与基本约定 `/about`
  - 历史约定入口 `/terms` → 永久 301 到 `/about#terms`
- 联系 `/contact`

后台、预览、API 和开发媒体路由不属于公开站信息架构，不进入公开导航或 Sitemap。

## Navigation Model

- **Primary navigation**：首页、作品展示、自设委托、角色领养、返图墙、关于我们。
- **Utility navigation**：联系作为独立强调入口；Logo/工作室名回到首页。
- **Contextual navigation**：作品详情提供返回作品列表、前后作品或相关列表入口；关于页内可定位到基本约定。
- **Mobile navigation**：折叠菜单包含全部一级页面和联系；打开后锁定背景滚动，关闭/跳转后恢复焦点。
- **禁止项**：公开站不显示后台登录、管理入口、原型切换、开发说明或访客账户。

## Content Hierarchy

### 首页

1. 全幅代表作品图与工作室身份 —— 先证明“做出来是什么样”。
2. 3–6 件精选作品 —— 让访客立即继续看实际成果。
3. 图片式自设委托/角色领养入口 —— 在作品证据之后分流真实业务。
4. 委托与领养营业状态 —— 说明当前是否值得继续联系。
5. 当前领养推荐和辅助信息 —— 只在有真实数据时出现。
6. 页脚与联系路径。

### 作品展示

1. 紧凑页名与筛选。
2. 当前结果数与等大 3:4 人工排序网格。
3. 空筛选结果和恢复筛选行动。
4. 未来分页位置；当前个位数内容不强制显示分页控件。

### 作品详情

1. 主图/设定图与角色名。
2. 有序图集和主要作品识别字段。
3. 适用的装型、物种、角色主人展示值、领养方式/状态/展会。
4. 相关浏览与返回列表。
5. 不显示价格、后台敏感资料、原图地址或交易控件。

### 自设委托

1. 代表作品宽图。
2. 委托营业状态与全装/半装制作范围。
3. 邮件人工估价行动和可复制邮箱。
4. 非穷尽的联系提示。
5. 五类已确认 FAQ。
6. 指向关于页基本约定。

### 角色领养

1. 领养营业状态。
2. 水印设定图/作品图列表。
3. 领养方式、业务状态与当前展会。
4. 卡片进入同一 `/works/{slug}` 详情。
5. 邮件/线下后续说明；无筛选、价格、登记和支付。

### 返图墙

1. 页名和短说明。
2. 有内容时的不等高照片墙；无内容时的真实空状态。
3. 每张返图关联作品；可选昵称、日期和主页链接只在有值时显示。

### 关于我们与基本约定

1. 工作室事实、所在城市和制作范围。
2. 制作理念与官方渠道。
3. 七类基本约定。
4. 适用性/法律审阅未完成的文本不得发布。

### 联系

1. 邮件主行动。
2. 可复制邮箱反馈。
3. QQ、抖音官方账号。
4. 防诈骗提示。

## User Flows

### 浏览者确认制作能力

1. 访客从主页链接、二维码或搜索进入首页。
2. 首屏看到真实代表作品和工作室名称。
3. 下滑进入精选作品，或点击“作品展示”。
4. 在作品网格筛选并进入 `/works/{slug}`。
5. 浏览主图、图集和必要资料，再返回作品列表或进入联系页。

### 自设委托咨询

1. 访客从首页图片入口或导航进入 `/commission`。
2. 先看代表作品、制作范围和营业状态。
3. 阅读必要 FAQ 与基本约定。
4. 点击邮件行动：
   - 邮件客户端可用 → 打开预填主题的邮件；
   - 不可用 → 复制邮箱并显示成功反馈。
5. 后续估价和资料沟通离开网站完成。

### 角色领养了解

1. 访客进入 `/adoptions`。
2. 查看真实营业状态、角色图片、方式、状态和展会。
3. 点击卡片进入 `/works/{slug}`。
4. 需要继续时按页面说明通过邮件或线下沟通；网站不出现登记或支付。

### 返图为零

1. 访客进入 `/returns`。
2. SSR 正常返回页面标题和说明。
3. 数据为空时显示经过设计的真实空状态，不显示假照片或“功能后续开放”。

## Naming Conventions

| Concept | Label in UI | Notes |
| --- | --- | --- |
| Standard portfolio | 作品展示 | 不用“案例库”“产品中心” |
| Commission | 自设委托 | 访客已有角色设定 |
| Adoption | 角色领养 | 方式再区分常规领养/展会掉落 |
| Customer photo | 返图 | 与工作室出厂照分开 |
| Design sheet | 设定图 | 领养角色正反面/局部/色板集中画布 |
| Studio photo | 出厂照 | 工作室自摄标准作品照 |
| Suit type | 全装 / 半装 | 半装由头、爪、尾巴组成 |
| Business availability | 委托营业状态 / 领养营业状态 | 不简称为作品状态 |
| Work status | 准备中 / 可领养 / 展会出售中 / 排期中 / 制作中 / 已完成交付 | 只在适用作品出现 |
| Contact action | 发送估价邮件 / 复制邮箱 / 联系工作室 | 不使用“立即提交”“在线申请” |

## Component Reuse Map

| Component | Used on | Behavior differences |
| --- | --- | --- |
| `PublicHeader` | 全部公开页面 | 首页首屏为图片覆盖态，内页为白底态 |
| `ResponsiveAsset` | 首页、作品、领养、返图、委托 | 首屏图高优先级；其余懒加载；设定图使用水印衍生组 |
| `WorkCard` | 首页精选、作品展示、相关作品 | 精选进入横向轨道；作品页进入规整网格 |
| `BusinessStatus` | 首页、委托、领养 | 同一视觉语法，不共享状态值 |
| `PageIntro` | 六个公开内页 | 有图片职责的页面保持紧凑；关于/联系可增加正文宽度 |
| `ContactChannels` | 委托、联系、页脚 | 委托突出邮件估价；联系页展示全部官方渠道 |
| `EmptyState` | 作品筛选、返图 | 文案与行动按页面职责变化 |

## Content Growth Plan

- 作品当前为个位数；数据/API/URL 不封死分页，达到实际需要时在 `/works` 增加分页，不迁移作品主键或详情路径。
- 首页精选始终限制 3–6 件并人工排序，作品总量增长不扩大首页轨道。
- 返图未来可增长为分页照片墙；一期不提供公开投稿或搜索。
- 角色领养当前不提供筛选；只有真实数量和运营需求增长后另行变更。
- 关于、联系、委托说明和 FAQ 是受限站点内容，不演进为万能 CMS 页面树。

## URL Strategy

- 唯一作品正文：`/works/{slug}`。
- Slug 首次发布后默认冻结；显式纠错保存永久重定向。
- 兼容入口 `/adoptions/{slug}`、`/terms` 不进入 Sitemap，不输出重复正文。
- 作品筛选是列表交互，不产生新的 canonical；若实现查询参数，canonical 仍固定为 `/works`。
- 所有内部导航使用普通 `<a href>` / `NuxtLink`，关键内容不依赖点击弹窗或滚动后才被搜索引擎发现。

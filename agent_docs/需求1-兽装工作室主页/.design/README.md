- 首页业务入口和状态已合并；
- 首页 Hero、委托 Hero 和两个业务入口使用无水印站点展示图；
- 作品与领养展示继续使用活动水印；
- 作品详情竖图使用独立限宽布局；
- 管理端文案拆为可理解、可独立保存的 Card；
- 保持摄影优先、白底、低装饰和清晰操作层级。

当前进入阶段 D 设计范围确认。首要候选为返图墙 T35–T36；展会、更多文字维护、回收站和手机闭环尚未自动纳入。

## 阶段 D 设计目标

返图墙应延续现有设计语言，而不是变成社交动态流：

- 公开端以返图图片为最高层级，文字只提供作品关联和必要说明；
- 返图墙与作品列表视觉相关，但通过页面标题、图片节奏和作品入口表达不同用途；
- 不增加点赞、评论、用户头像、时间线算法或公开投稿；
- 管理端使用独立“返图”入口，不把返图混入出厂照分区；
- 可选授权记录明确标注“仅后台可见”，不进入公开预览；
- 上传、处理、轻量水印、发布、失败和恢复使用真实持续状态；
- 手机优先完成查看、文字、单图和发布等轻操作，复杂批量排序可以提示使用桌面。

T38–T40 未确认前，设计稿和导航不得出现“更多内容”“改址历史”或“回收站”的可点击假入口。

## 通用原则

### 图片优先

- 公开页面首先展示兽装图片；
- Logo、标题、状态和行动文案均为辅助；
- 不以大面积色块、卡片边框和工具型状态区打断图片浏览；
- 站点 Hero 和业务入口使用无水印图片；作品档案和领养图片继续水印；
- 返图墙使用独立轻量水印配方，参数确认前不制作伪最终稿。

### 一致性

- 相同语义使用相同组件和视觉语言；
- 委托与领养两个业务入口保持对称；
- 状态作为入口内容的一部分，不单独复制一遍；
- 返图关联作品时复用已有作品名称和跳转语言，不复制完整作品卡；
- 公开站不混入管理端式的灰底工具 Card；
- 管理端不复制公开站的摄影叠字布局。

### 横竖图片

- 横图和竖图都保持完整、清晰、无异常裁剪；
- 作品详情竖图不放在满宽灰色舞台中；
- 卡片和返图墙缩略图可以按固定比例裁剪，但必须使用已保存焦点；
- 详情与设定图使用 contain 时，占位背景只覆盖实际图片矩形；
- 返图墙应根据真实样本决定规则网格、masonry 或有限比例卡片，不以假占位图做最终判断。

### 可访问性

- 交互目标在触控设备上至少接近 44 px；
- 焦点可见；
- 轮播支持键盘、按钮、触控、暂停和减少动效；
- 状态不能只用颜色表达；
- 一张业务卡只提供一个主链接，避免嵌套链接；
- 图片 alt 表达内容，不重复周围完整文字；
- 返图墙的浏览顺序必须与 DOM 顺序一致，不能只靠视觉重排。

## 固定验收视口

- `390×844`；
- `768×1024`；
- `1440×900`。

每次修改公开页面或管理页面，至少检查：

- 横向溢出；
- 图片自然尺寸和解码；
- 图片方向与请求资源；
- 文字重叠、截断和过密；
- 键盘和焦点；
- 减少动效；
- loading、empty、error、conflict 和 recovery 状态；
- 私有原图、授权记录和管理预览未进入公开 DOM、网络响应或缓存。

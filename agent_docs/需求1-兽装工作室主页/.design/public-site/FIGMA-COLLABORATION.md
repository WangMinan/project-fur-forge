# Figma 公开端设计协作

> **状态**：设计探索已获用户授权，Figma 工作区已创建，首次 Foundations 写入进行中。
> **角色**：规定当前公开端如何进入 Figma、景宸与外部设计师如何协作，以及设计稿与活文档、实现和验收之间的边界。
> **基线**：首次导入以 Git SHA `9c6e82f600251483642acad180ddbb797baaf099` 为代码事实源。

## 1. 目标与权威边界

本工作区用于把已实现公开端转换为可比较、可编辑的 Figma 视觉基线，并允许景宸邀请具备响应式网页经验的 UI/视觉设计师提出优化方案。

Figma 文件本身不是产品或实现权威：

- `Current UI` 只记录指定 Git SHA 与捕获时间下的页面事实；
- `Proposed` 是设计候选，不自动改变公开行为、数据事实、媒体策略或管理心智模型；
- 只有用户确认的 `Approved` 方案，且相应变化先同步到 SPEC、PLAN、TASKS 后，才能进入代码实施；
- Figma 原型、评论和设计走查不能代签独立 Review、用户浏览器验收或正式发布。

当前阶段 E/F 的既有冻结与上线收口不因设计探索自动重开。若用户决定实施某项 UI 优化，应建立新的授权范围和任务分支。

## 2. 免费 Starter 文件结构

首版只使用一个 Figma Design 文件和三个 Page，避免依赖付费 Team Library、Dev Mode 或 Code Connect：

| Page | 内容 | 编辑纪律 |
| --- | --- | --- |
| `01 Foundations + Components` | 设计原则、颜色、字体、间距、圆角、阴影和同文件本地组件 | Token 先于组件；组件绑定本地变量，不发布跨文件 Library |
| `02 Current UI` | 当前公开端三视口基线与捕获说明 | 作为锁定对照区；设计师不得直接覆盖 |
| `03 Proposed + Approved` | 探索稿、景宸评审区、批准稿和开发交付说明 | 用 Section 区分 `Exploration`、`Review`、`Approved`、`Handoff` |

每个 Page 内可放多个 Section 和 Frame。屏幕 Frame 按 `页面 / 视口 / 状态` 命名，例如：

```text
Home / 1440x900 / Current
Home / 768x1024 / Current
Home / 390x844 / Current
Works Detail / 1440x900 / Current
```

Figma 连接器创建的新文件最初位于所选计划的 Drafts。需要与设计师共同编辑时，由文件所有者把它移动到免费 Starter 团队文件夹，再授予协作者编辑权限。

Starter 的远程 MCP 工具调用额度与文件数量是两类限制。额度用尽时，现有文件、变量和样式仍保留；暂停连接器写入并在额度恢复后从状态清单续写，不为绕过额度重复创建文件或覆盖已验证内容。

## 3. 首轮范围

首轮先建立可验证的小型基线：

1. 在三个 Page 中写入用途、状态和协作说明；
2. 从代码 Token 创建本地颜色、间距和圆角变量，并设置对应 CSS 变量语法；
3. 建立最小本地组件种子：主要行动按钮、首页模块标题和图片卡片；
4. 捕获首页与作品详情的 `390×844`、`768×1024`、`1440×900` 当前视觉；
5. 保留源页面、Git SHA、捕获时间和数据状态说明。

首轮结构和捕获质量确认后，再扩展作品目录、返图墙/设定页、自设委托、设定领养、最新动态、关于我们、联系区、移动导航与页脚。管理后台不进入首轮公开端设计探索。

## 4. 视觉与交互约束

- 兽装图片始终是最高视觉层级；品牌、文字、符号和控件只做辅助；
- 公开导航中文品牌保持“有点小狗”，英文保持 `DITE DOG FURSUIT`；
- `Current UI` 使用代码中的真实 Token、字体回退、组件结构和三视口，不默认替换成 Inter；
- 首页固定 10 秒轮播、显式暂停、键盘/触控和 `prefers-reduced-motion` 属于实现契约；静态 Figma Frame 只能表达状态，不能证明交互通过；
- 设计师必须同时提供 390、768、1440 三档方案，不能只交付桌面海报；
- 视觉优化不得恢复已取消的入口、空页面、全站搜索、社交互动或通用 CMS。

## 5. 图片、隐私与第三方边界

Figma 是第三方云端协作环境，只允许写入公开展示所需内容：

- 只使用已经公开的 ESA HTTPS 衍生图片，或由公开页面捕获产生的图像；
- 不上传私有原图、私有适配源、后台私有预览、未发布素材或带签名的私有 URL；
- 不写入授权来源、确认时间、授权备注、联系人、Session、Object Key、AK/SK 或其它 Secret；
- 不以后台截图替代公开端占位素材；如后续设计管理端，必须另立范围并使用脱敏/合成数据；
- Figma 文件中发现不应公开的数据时停止协作，先清理并检查共享权限。

## 6. 设计师交付要求

外部设计师应熟悉 Figma Auto Layout、Components、响应式网页和开发交付。每个候选方案至少说明：

- 解决的问题与保持不变的产品边界；
- 390、768、1440 三档布局；
- 使用的字体及网页授权/回退策略；
- 图片裁切、安全区、横竖素材和文字对比度；
- Hover、Focus、Disabled、Loading、Empty、Error 等必要状态；
- 与 `Current UI` 相比的 Token、组件和页面变化清单。

## 7. 协作与备份

1. `Current UI` 只由项目维护者更新，并保留 SHA/日期；
2. 设计师在 `03 Proposed + Approved / Exploration` 中复制后修改；
3. 景宸通过评论或 `Review` Section 收口意见；
4. 用户确认后，把冻结副本移入 `Approved`，不覆盖历史候选；
5. 开始设计、用户批准和最终交付三个节点各保存一份本地 `.fig` 备份；
6. 代码实现完成后使用真实浏览器三视口重新对照，不能以 Figma 截图代替运行时验收。

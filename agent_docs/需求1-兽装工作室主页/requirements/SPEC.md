## 1. 产品目标

系统为“有点小狗工作室”提供图片主导的公开主页和唯一管理员后台。

阶段 C 已完成作品展示、常规领养、委托说明、首页维护、品牌水印、备份恢复和可重复部署配置。阶段 D 增加：

1. 独立一级导航 `/returns` 的无水印返图墙；
2. 复用现有作品与领养管理的轻量展会掉落。

系统不建设交易、订单、排期、多管理员、万能 CMS、访客投稿或社交互动。

产品阶段完成与正式发布就绪是不同结论：GitHub Actions 全绿、正式域名、TLS、线上 Compose、升级、回滚和恢复演练仍由 T49–T53 收口。

## 2. 访问面与路由

### 2.1 公开站

公开 Host 提供或在阶段 D 完成后提供：

- `/`：首页；
- `/works`：作品列表；
- `/works/{slug}`：统一作品详情；
- `/adoptions`：常规领养与展会掉落；
- `/adoptions/{slug}`：兼容永久重定向到统一作品详情；
- `/returns`：独立一级导航返图墙；
- `/commission`：自设委托；
- `/about`：关于工作室和官方联系方式；
- `/service`：服务条款；
- `/privacy`：隐私政策；
- `/contact`、`/terms`：兼容重定向；
- `/robots.txt`、`/sitemap.xml`：SEO 基础。

`/returns` 是独立公开页面，不是作品详情内部的 Tab，也不建设返图详情路由。返图项可以链接关联作品 `/works/{slug}`。

公开 Host 必须拒绝 `/admin/**`、`/api/admin/**`、认证接口、私有预览和其他管理路径。

### 2.2 管理端

管理 Host 当前提供：

- `/admin/login`；
- `/admin/works`；
- `/admin/works/new`；
- `/admin/works/{id}`；
- `/admin/site/home`；
- `/admin/site/content`；
- `/admin/site/branding`；
- `/admin/account`。

阶段 D 完成 T35–T36 后增加：

- `/admin/returns`；
- `/admin/returns/new`；
- `/admin/returns/{id}`。

展会掉落继续在现有作品列表和作品编辑页维护，不增加展会一级导航、展会管理页或展会详情页。

管理 Host 根路径进入登录流程。未登录访问受保护页面不得先显示任何私有数据。未实现功能不得出现可点击空入口。

### 2.3 媒体与上传 Origin

媒体公开 origin 和 OSS 上传 origin 与公开、管理 origin 必须互不相同。应用只在测试环境暴露假媒体端点；生产环境不得注册测试控制路由。

## 3. 作品领域

### 3.1 作品用途与装型

底层作品用途保持三种：

- `commission`：委托作品；
- `adoption`：领养作品；
- `showcase`：纯展示作品。

作品装型保持：

- `full`：全装；
- `partial`：半装。

管理端可以向景宸显示四个易理解的业务选项：

```text
委托作品    -> purpose=commission
常规领养    -> purpose=adoption, adoption_method=regular
展会掉落    -> purpose=adoption, adoption_method=event_drop
纯展示      -> purpose=showcase
```

不得为展会掉落新增第四种底层 purpose，避免复制领养价格、状态、设定图和发布规则。

### 3.2 基础字段

每件作品至少包含：

- 稳定 UUID；
- 唯一 slug；
- 角色名；
- 物种；
- 装型；
- 用途；
- 角色主人公开显示名；
- 可选私有联系人；
- 0–8 个短属性；
- 人工排序；
- 是否精选；
- 资源版本；
- 发布状态。

公开 DTO 必须把私有联系人固定投影为 `null` 或省略，不得因页面不同偶尔暴露。

### 3.3 领养方式、状态与展会字段

领养方式固定为：

- `regular`：常规领养；
- `event_drop`：展会掉落。

领养状态继续复用现有集合：

- `preparing`；
- `available`；
- `scheduled`；
- `in_production`；
- `delivered`。

展会掉落额外需要：

- `event_name`：展会名称，短文本；
- `event_time`：展会时间展示文本，可以表达单日、日期范围或已确认时段。

约束：

- `purpose=adoption` 且 `adoption_method=event_drop` 的**已发布**作品，
  两项均必须为非空；草稿允许暂时缺项，由发布检查
  （`EVENT_DROP_FIELDS_REQUIRED`）拦截，与 alt、设定图同一套心智；
- 其他作品的两项必须为空；
- 展会时间只用于公开展示，不触发定时任务，也不自动改变领养状态；
- 当前版本一件掉落作品只保存一组展会名称和时间；
- 不保存展会地点、摊位、主办方、封面、统一规则或展会历史。

领养价格可为空；存在时必须为正数人民币最小单位。网站只展示价格，不执行登记、抽选、定金、付款或退款。

### 3.4 发布状态

作品状态固定为：

- `draft`；
- `published`；
- `unpublished`。

已发布作品的事实字段和媒体关系不能直接修改，必须先下架。排序和精选等展示设置可以通过受限接口调整，但仍需资源版本校验。

已发布 slug 默认视为稳定公开地址。当前版本不建设 slug 改址历史；相关分享与长期 URL 策略记录在未来迭代备忘录中。

## 4. 返图领域

### 4.1 设定与返图

返图是与作品**完全独立**的模型：老作品没上过架、甚至没有建作品记录，也可以有返图。

层级只有两级：**设定**（`return_characters`）与其**返图照片**（`return_photos`）。一个设定可以有多张返图，横版竖版混放。不建设“批次”“相册”或第三级。

设定记录至少包含：

- 稳定 UUID 与公开 slug；
- 必填名称，例如“天暮”；
- 可选昵称，公开显示为 `@昵称`；
- 可选 `work_id`，关联一件已有作品。留空是正常状态，不影响返图发布；
- 主图指向该设定自己的一张返图；
- 资源版本与时间字段。

返图照片记录至少包含：

- 稳定 UUID；
- 必填 `character_id`，归属一个设定；
- 必填 `asset_id`，关联一张 `return_photo` 私有永久原图；
- 必填 alt；
- 是否为该设定主图；
- `draft | published | unpublished`；
- 资源版本与时间字段。

返图不设人工排序：公开返图墙每次请求随机打乱（见 11.1）。首版不维护返图长说明、返图者个人主页、社交账号或拍摄日期。

### 4.2 可选授权记录

返图可以保存以下可选后台字段：

- 授权来源或确认渠道；
- 授权确认时间；
- 内部备注。

这些字段：

- 只进入受认证的管理响应；
- 不进入公开 DTO、HTML、图片元数据、缓存、普通日志或公开导出；
- 缺失时可以显示后台提示，但不自动阻止保存或发布；
- 不形成法律审批流、附件上传或多级审核。

### 4.3 与作品解耦

返图的公开可见性只取决于自己：

- 设定的关联作品是可选的，留空时返图照常发布和公开展示；
- 返图能否发布**不取决于**关联作品是否已发布，也不取决于作品是否存在；
- 公开查询只要求返图照片本身为 `published`；
- 作品下架、重新发布或删除都不改变返图的公开可见性；
- 关联作品被永久删除时，设定的 `work_id` 置空，返图与私有原图保留。

设定页在有关联作品时给出一个作品入口，没有时不显示该入口。返图不改变作品发布状态，也不进入作品详情的出厂照图集或返图 Tab。

### 4.4 删除边界

阶段 D 不建设 30 天回收站，也不把通用 `deleted_at` 扩散到作品、返图和媒体。

- 已发布返图必须先下架；
- 首版必须完整支持下架；
- 永久删除不是阶段 D 的必做公开入口；
- 若实现草稿永久删除，只能使用明确影响说明和精确对象清理，不得假装可恢复；
- 删除设定前必须先处理它的返图照片；
- 不得因为没有回收站而删除私有永久原图生命周期保护或备份边界。

## 5. 媒体角色与上传

### 5.1 媒体角色

阶段 C 已实现：

- `design_sheet`：领养设定图；
- `studio_photo`：作品出厂照；
- 首页与委托页横竖 Hero 对应角色或 placement；
- `watermark_logo`。

阶段 D 增加：

- `return_photo`：返图私有永久原图。

角色必须与归属匹配：非领养作品不得绑定设定图；站点 Hero 与品牌 Logo 不得绑定到作品媒体关系；返图不得复用 `studio_photo` 冒充出厂照。

### 5.2 原图上传

浏览器通过条件 PUT 直传私有 OSS，Nitro 不代理图片二进制。创建上传会话时必须声明：

- MIME；
- 字节数；
- MD5；
- SHA-256；
- 宽高；
- 归属类型、归属 ID 和归属版本；
- 媒体角色。

上传会话有效期 5 分钟，Object Key 不可预测且禁止覆盖。服务端完成时重新验证 HEAD、摘要、真实 MIME、真实尺寸、EXIF 方向和角色约束。

支持 JPEG、PNG、WebP；原图最大 30 MB，最大边不超过 12000 px。水印 Logo 必须是带透明通道的 PNG。

失败重试创建新会话和新 Key，不原位覆盖。过期上传会话由主动清扫命令处理，OSS 生命周期只作为临时前缀兜底。

### 5.3 私有预处理

超过 OSS 图片处理输入限制的原图，或经管理员明确确认的低分辨率站点大图，可以生成私有 FFmpeg 处理源。处理源不能替代永久原图，也不能宣称恢复原图不存在的细节。

## 6. 公开媒体与水印

媒体公开行为只以 [`MEDIA-PUBLICATION-POLICY.md`](./MEDIA-PUBLICATION-POLICY.md) 为准。关键规则为：

- 首页 Hero、委托页 Hero和首页两个业务入口使用无水印站点展示衍生图；
- 作品列表、作品详情、常规领养和展会掉落使用活动 `brand-centered-v2` 水印；
- `/returns` 返图使用独立无水印公开衍生图；
- 永久原图、处理源、Logo 候选、管理预览和返图授权记录始终私有；
- 所有公开图片预生成、验证完成、去除不需要的 EXIF，并使用不可变 Key；
- 生成、验证和切换失败时保持当前公开版本。

返图公开变体使用独立用途和配方，例如：

```text
usage = return-wall
recipe_version = return-display-v1
protection_mode = none
```

返图不关联活动水印 profile，水印 profile 切换不得改变返图 URL、摘要或内容。

## 7. 作品与返图发布

### 7.1 作品发布前检查

普通委托和展示作品至少需要：

- 完整有效字段；
- 至少 1 张 READY 出厂照；
- 恰好 1 张主出厂照；
- 全部公开图片有 alt；
- 所需作品水印变体完整；
- 活动水印 profile 可用。

所有领养作品还需要：

- 合法领养方式和状态；
- 至少 1 张 READY 设定图；
- 设定图 alt 有效；
- 价格字段成组有效。

展会掉落额外要求 `event_name`、`event_time` 非空。不得以缺少独立展会表为由阻止掉落发布。

### 7.2 返图发布前检查

返图至少需要：

- 归属一个设定；
- READY `return_photo` 私有资产；
- 有效 alt；
- 完整、READY 的无水印 `return-wall` SourceSet；
- 资源版本匹配。

可选授权记录缺失不作为硬阻断。设定的关联作品是否存在、是否已发布，都**不是**返图发布条件。

### 7.3 原子发布操作

作品和返图发布均必须：

1. 固化请求版本；
2. 生成缺失公开变体；
3. 验证公开对象；
4. 原子更新业务状态和公开投影；
5. 写入审计记录；
6. 失败时只清理当前 attempt 新建对象，保留旧公开状态。

下架先撤销公开状态，再精确清理不再引用的公开对象。运行中的发布不得被普通删除操作破坏。

## 8. 公开首页

首页顺序固定为：

1. 代表作品 Hero；
2. 精选作品；
3. 统一业务入口区；
4. 当前领养。

### 8.1 Hero

- 1–5 项；
- 横版和竖版为独立资产；
- 当前项才渲染图片，后续项按需加载；
- 自动轮播默认关闭，开启时最短 6 秒；
- 悬停、焦点、页面隐藏和减少动效时暂停；
- 支持按钮、键盘和触控切换；
- 横竖图均使用无水印站点展示变体。

### 8.2 精选作品

最多展示 6 件已发布精选作品，按人工 `sort_order` 排列。这是全站唯一需要人工排序的位置。

精选顺序与精选勾选**在作品发布后仍可直接修改并立即生效**，不随作品字段一起被上架锁定：调整首页顺序不应要求先下架作品。

无精选时整区隐藏；精选接口失败不得导致首页 Hero 和导航整体 500，可以降级隐藏并记录安全日志。

### 8.3 统一业务入口

入口区最多包含两张统一卡：

- 自设委托；
- 角色领养。

每张卡包括独立无水印入口图片、业务标题、当前营业状态、一行短说明和明确行动入口。缺少可用图片时使用受控无图状态，不得泄漏私有原图或任意借用其他作品。

### 8.4 当前领养

展示最多 2 件当前已发布领养，可以同时包含 `regular` 与 `event_drop`，并提供查看全部入口。

展会掉落卡片必须明确显示“展会掉落”、展会名称和展会时间。无可展示领养时整区隐藏。不增加独立“当前展会”首页区块。

## 9. 作品列表和详情

### 9.1 作品列表

`/works` 支持用途和装型的交集筛选，显示结果数量、当前筛选状态和清除入口。非法筛选参数不得抛 500，应返回空结果和明确提示。

公开排序为**越新的越靠前**（按发布时间倒序，后接稳定 ID）。人工 `sort_order` 只服务首页精选，不影响 `/works` 与 `/adoptions`，因此景宸不需要为每次新作品重排整站顺序。

作品卡保持统一比例，消费作品水印衍生图。列表只展示具有公开作品媒体的已发布作品；只有设定图、没有出厂照的领养可以出现在 `/adoptions`，但不进入 `/works`。

### 9.2 作品详情

统一详情包含：

- 角色名、物种、装型、用途；
- 角色主人公开显示；
- 短属性；
- 可公开领养价格；
- 设定图分区；
- 出厂照图集；
- 前后浏览；
- 相关作品。

展会掉落详情额外显示展会名称和展会时间。

详情图集根据当前图片方向布局：横图可使用宽舞台；竖图完整显示并限制容器宽度；不以 `cover` 裁掉主体；缩略图选中状态保持一致；路由复用时重置到有效索引；图片声明固有宽高。

作品详情不增加返图 Tab，不嵌入完整返图墙。返图页面中的条目可以跳转到作品详情。

## 10. 领养页

`/adoptions` 展示所有已发布领养，包含 `regular` 与 `event_drop`。

页面提供轻量筛选：

- 全部；
- 常规领养；
- 展会掉落。

所有领养使用带活动水印的设定图，展示角色名、当前状态、可选价格和统一详情入口。设定图使用圆角矩形外框，与 `/works`、`/returns` 的图片处理一致。

公开排序与 `/works` 一致：越新的越靠前，不使用人工 `sort_order`。筛选条与作品筛选条使用同一套视觉。

展会掉落额外展示：

- “展会掉落”类型标签；
- 展会名称；
- 展会时间。

不建设独立展会列表、展会详情、地点地图、摊位或展会归档。

## 11. 返图页

### 11.1 返图墙

`/returns` 是一级导航中的独立返图墙，展示收到的真实穿着返图，与标准作品档案分开。

页面结构：

```text
紧凑页面标题与短说明
原比例返图瀑布流 / 真实空状态
底部编号分页（含上一页 / 下一页）
页脚
```

页面不设置大 Hero、搜索、筛选、统计或热门区。

墙上每一项是**一张返图照片**，不是一个设定：同一个设定的多张返图都会出现在墙上，横竖混排。每页默认 24 条。

排序为**每次请求随机打乱**：返图之间没有优劣顺序，也不给景宸增加排序维护负担。随机种子按页面请求确定，同一次请求内分页无重复无遗漏。

返图墙是**纯净瀑布流**：只有图片，不标设定名称或任何说明文字。

点击任意一张返图进入该照片所属设定的返图页 `/returns/{slug}`，**不跳转到作品详情**。

### 11.2 设定返图页

`/returns/{slug}` 展示一个设定的全部已发布返图：

```text
圆形主图 + 设定名称 + @昵称（有则显示）
该设定全部返图的原比例瀑布流
可选的关联作品入口（没有关联作品时不显示）
```

主图使用该设定自己指定的一张返图。页面不建设返图者个人主页、搜索、点赞、评论、公开投稿或访客账户。

### 11.3 瀑布流

`/returns` 与 `/returns/{slug}` 使用同一套瀑布流：

- 使用真实图片固有宽高维持原比例；
- 采用 masonry/瀑布流，而不是统一 3:4 强裁切；
- 图片统一圆角矩形，与 `/works` 保持一致；
- DOM 顺序、键盘顺序和屏幕阅读顺序保持一致；
- 图片加载前保留尺寸，避免明显 CLS；
- 使用底部编号分页，链接可在 SSR 和无 JavaScript 环境下工作；
  不使用自动无限滚动，也不以“加载更多”为默认交互；
- 单图失败显示受控错误状态，不使整页或导航 500。

### 11.4 公开数据边界

公开返图 DTO 只包含：

- 公开返图身份；
- READY 无水印 SourceSet、宽高和 alt；
- 所属设定的公开名称、可选昵称、slug 和 href。

设定页额外包含可选关联作品的公开名称、slug 和 href。

不得包含授权来源、授权时间、内部备注、私有联系人、私有 Object Key、签名 URL、原文件名或 EXIF。

首版不提供返图者主页、搜索、点赞、评论、公开投稿或访客账户。

## 12. 委托、关于与政策页

### 12.1 自设委托

`/commission` 展示独立无水印横竖 Hero、当前委托状态、全装与半装制作范围、人工逐单估价机制、邮件行动、已确认 FAQ 和服务条款入口。

不得提供自动报价、固定价目计算、委托登记和付款。

### 12.2 关于与官方渠道

`/about` 展示工作室事实、制作范围和官方联系方式。邮箱、QQ、抖音和防诈骗说明只来自管理端已保存值。

### 12.3 服务条款与隐私政策

`/service` 和 `/privacy` 使用独立、可阅读的正文布局。隐私政策必须与网站实际收集的数据一致，不复制与本项目无关的通用模板事实。

### 12.4 开源软件声明

`/licenses` 声明网站使用的开源软件，内容**写死在代码里**，不进文案编辑：这是许可证义务，不应被后台改错。页脚在 ICP 备案旁给出入口。

两类依赖的处理方式不同，因为义务不同：

- **copyleft（GPL）依赖必须内嵌许可证全文**，并给出对应源代码获取途径。
  当前唯一一项是 FFmpeg：本站分发的是 `ffmpeg-static` 提供的
  GPL-3.0 静态构建，页面给出构建版本、上游源码提交与许可证全文；
- MIT / Apache-2.0 依赖只需给出项目仓库地址，全文在其仓库内。

许可证全文以文件形式随仓库保存（`app/assets/licenses/`），原样取自我们实际分发的二进制所带的 LICENSE，不手工转述。升级依赖时同步本页与该文件。

### 12.5 管理端登录页

`/admin/login` 保留公开站页头与页脚，且只保留品牌（Logo 与工作室名称）与法务/备案信息，隐藏访客导航：该页面可能被 ICP 备案审核抓到，需要承载备案信息，但导航不应进入登录流程。其他管理端页面继续使用管理布局。

## 13. 管理端作品与展会掉落

管理员可以创建作品、修改未发布作品字段、管理设定图与出厂照、设置主图/顺序/alt/焦点、预览、发布、下架、恢复失败清理，以及调整排序与精选。

`/admin/works` 与 `/admin/returns` 列表都按 `updated_at` 倒序：最近改动的在最前。两个列表的删除入口都在表格行内，详情页不放危险操作区。

领养作品没有出厂照主图时，列表缩略图回落到设定图，不显示空占位。

作品编辑器在业务类型上显示四个选项。选择“展会掉落”时：

- 自动映射为 `purpose=adoption`、`adoption_method=event_drop`；
- 展示展会名称和展会时间字段；
- 继续展示领养状态、价格、设定图和出厂照；
- 发布检查明确列出缺失展会字段；
- 不跳转到另一套展会编辑器。

所有写操作携带资源版本。409 后重新读取服务端状态，前端不得自行递增版本或静默覆盖。

## 14. 管理端返图

### 14.1 设定列表

`/admin/returns` 列出**设定**（不是单张照片），至少提供：

- 新增设定；
- 按名称或昵称查找；
- 主图缩略图、名称、昵称、返图张数和已发布张数摘要；
- 编辑入口；
- 删除入口（在表格行内，与 `/admin/works` 一致）；
- 与 `/admin/works` 一致的分页控件与白底表格；
- 真实空态。

删除设定会连带删除它的全部返图：已发布的返图先自动下架并精确清理公开对象，再删记录。私有永久原图保留。景宸不需要先逐张处理返图。

### 14.2 设定编辑

设定编辑页分为：

- 名称、昵称、网址名称与可选关联作品；
- 返图图片：多张上传、逐张 alt、指定主图、逐张发布与下架；
- 授权记录（可选，仅后台可见，按设定保存）；
- 发布检查与 operation 状态。

页头结构与 `/admin/works/{id}` 一致：返回链接、标题与未保存标记同一行，主操作（保存修改）在右上角。删除入口只在设定列表，本页不放危险操作区。

页面不出现公开衍生预览：返图公开图无水印、与私有原图内容一致，再放一份预览没有信息量。也不出现作品水印参数、返图水印开关或返图排序输入。

手机端至少支持查看、编辑名称与 alt、上传返图、指定主图、发布和下架；复杂批量能力不属于本阶段。

## 15. 管理端首页、文案与品牌

首页和委托大图继续使用不同 placement；首页至少保留 1 个启用 Hero，委托页允许全部停用；启用时生成无水印站点展示变体。

## 16. 认证、安全与隐私

- 只允许一个活动管理员；
- 密码使用强哈希；连续失败可以锁定账户；
- 改密和离线重置使旧 Session 失效；Session 空闲上限 8 小时；
- 管理写请求验证管理 Origin、Session 和 CSRF；
- JSON 请求体限制 64 KiB；
- 登录与管理写入按可信主体限流；
- 可信客户端 IP 只从明确配置的反向代理链取得；
- 错误响应使用稳定 `code` 和业务 `reason`；
- 管理响应使用 `no-store`、`noindex`；
- 日志不得记录密码、用户名明文、邮箱、联系人、返图授权记录、Session、Cookie、签名 URL、AK/SK 或私有 Object Key。

返图公开衍生生成必须移除不需要的 EXIF，尤其不能公开拍摄位置和设备隐私信息。

## 17. 长任务与恢复

适用于作品、Hero、品牌 profile、站点展示 reconcile 和返图公开生成/发布。

每个 operation 至少包含：状态、请求版本、进度、失败阶段、稳定失败码、已创建对象清单、attempt、lease owner、lease 到期时间、heartbeat、recovery reason、必要的下一次重试时间和完成时间。

容器启动时扫描未终止 operation：可安全重放则重新取得 lease；不能安全重放则转为可恢复失败；已提交业务状态但未写终态时通过幂等核对收敛；清理失败保留精确对象清单；重复重启不得产生重复公开对象或破坏旧有效版本。

展会掉落只复用作品发布 operation，不增加展会长任务。

## 18. 数据库、备份与恢复

- SQLite 使用 WAL、外键、busy timeout 和 FULL synchronous；
- 生产数据库路径固定在持久卷；
- 不修改已执行历史迁移；
- 阶段 D 使用新的前向迁移；
- 迁移前创建验证备份；
- 恢复只写新路径，先执行完整性、外键和迁移匹配校验；
- 禁止在线覆盖当前活动数据库；
- readiness 比较迁移数量、顺序、folderMillis 与 hash；
- T40 已取消，不增加通用回收站表、统一 `deleted_at` 或跨 OSS 的 30 天清理调度。

## 19. 容器、CI 与发布边界

当前 Node 24 runtime 镜像已经由 GitHub Actions `image-build` 成功验证。版本控制内的 `docker-compose.yaml` 继续包含 app、migrate、nginx、持久卷、健康检查、受控网络、环境变量和单副本约束。

GitHub Actions 目标至少执行 frozen install、lint、typecheck、unit、integration、production build、production output verify、secret/content scan、Compose 静态检查、Docker build 和核心 E2E。

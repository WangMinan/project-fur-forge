## 2. 目标

1. 将公开站从“整洁的卡片化 CMS”升级为以兽装摄影为主角、具有明确品牌节奏的编辑式工作室网站。
2. 首页继续覆盖作品、自设委托和设定领养全部核心业务，但通过四幕层级引导用户，而不是将内容按同一尺寸和权重平铺。
3. 建立统一、克制、可解释的公开动效语言，形成从品牌图像到作品、委托和领养的连续浏览动线。
4. 保证 PC Web 的大图展示效果，同时让移动端以原生纵向滚动和等价重排完成同一信息任务。
5. 以低维护成本提供 Hero 九宫格焦点，减少 `object-fit: cover` 裁掉脸、耳朵和角色主体的问题。
6. 统一委托渠道口径：站内表单负责投递，工作室官方 QQ 私聊负责优先后续沟通和逐单确认，邮箱为备用。
7. 让申请页面与真实收集行为一致：明确处理者、用途、信息种类、保存规则、成年人限制、权利入口和提交非接单性质。
8. 提供可实际执行的委托申请删除能力，以人工周期复核代替自动定时清理，避免引入不必要的调度基础设施。
9. 重写默认关于我们、委托、隐私政策和服务条款，减少 AI 化、重复防御和不合理单方权利表述，同时补齐真正保护工作室的业务边界。
10. 由实际生产依赖生成第三方声明，并把开源软件、内部服务器工具和免费商用字体正确分层。

## 3. 非目标

- 不恢复返图墙、最新动态、FAQ、抖音、小红书或 Bilibili。
- 不建设通用 CMS、页面搭建器、海报生成器或每个断点独立的自由裁切编辑器。
- 不建设 scroll-jacking、强制横向滚动、长时间 pinned scroll、全屏视差、3D 场景、持续粒子或背景音效。
- 不要求复刻 Apple、渔屋或万物通行的品牌、素材、颜色和完整布局。
- 不引入在线合同、站内订单、定金、支付、退款、排期、申请公开查询或访客账号。
- 不抓取、存储或解析 QQ 聊天记录；逐单确认由工作室在 QQ 中完成。
- 不建设身份证/人脸/出生日期核验或未成年人监护人流程；首版只接受成年人。
- 不建设自动定时任务、Worker、数据库 TTL、通用数据生命周期引擎或管理端批量清空。
- 不强制启用 GitHub required check，不新增独立重型流水线。
- 不因 FFmpeg 服务器内部使用而虚构对访客的二进制分发或源码提供场景。
- 不把“免费商用”字体误标成开源软件，也不在仓库中新增授权不明的字体文件。

## 5. 品牌、渠道与信息架构契约

### 5.1 品牌

- 中文名称：`有点小狗工作室`。
- 短品牌：`有点小狗`。
- 英文名称：`DITE DOG`。
- slogan：`不只做小狗毛 | 只做海绵头`。
- 当前页面、SEO、JSON-LD、OG、README 和活文档不得称英文名为暂用名，也不得出现 `DITE DOG FURSUIT`。

### 5.2 联系渠道

- `/commission/apply` 是结构化申请入口。
- 后续评估、报价和逐单确认优先使用网站公布的工作室官方 QQ 私聊。
- 邮箱用于备用联系、隐私权利请求和 QQ 无法使用时的沟通。
- QQ群用于社群或一般交流，不作为默认订单确认渠道。
- 防诈骗文案必须清楚区分官方 QQ、邮箱和 QQ群，不把QQ群描述为订单唯一凭证。

### 5.3 首页四幕

首页顺序固定为：

```text
第一幕：品牌 Hero
第二幕：代表作品
第三幕：自设委托
第四幕：设定领养
```

四幕覆盖全部核心业务，但视觉权重不等：

- Hero 建立品牌和第一印象。
- 代表作品先展示精选顺序第一项的大图，剩余精选作为次级浏览。
- 自设委托是独立的大型视觉章节，不再放在带描边的 21:9 业务卡中。
- 设定领养用一大一小或同等克制的影像拼版；只有一件时自然扩大，零件时整幕隐藏。
- `/works` 与 `/adoptions` 继续承担完整目录、搜索和分页；首页不复制完整目录。

## 6. 视觉与动效契约

### 6.1 视觉原则

- 白底或极浅中性色继续作为主要内容底；摄影是最高视觉层级。
- 一个视口只建立一个主要注意力中心。
- 标题、说明和行动数量必须克制；大图不被厚边框、多个徽章或过多按钮分割。
- 模块面积交替形成节奏：全屏/大幅 → 次级轨道 → 大幅分栏 → 影像拼版。
- 不要求每个模块制作专用商业海报；优先让现有真实作品图通过排版产生层级。
- Header 可以在 Hero 上使用轻量透明/模糊材料，但不能用高成本全屏 blur 或多层玻璃叠加。
- 拼贴字体用于品牌与少量展示文字；正文保持系统中文无衬线/宋体层级，不让装饰字体承担长文阅读。

### 6.2 动效语义

Apple Design Skill 在本需求中只提供即时响应、空间一致性、可中断直接操作和克制原则；它不是新增依赖或对每段动效使用 spring 的要求。

- **纵向**：只表示阅读进程和区块进入，默认 8–12px。
- **横向**：只表示同一媒体序列的前后关系。
- **缩放**：只表示按压、选择、轻微媒体聚焦或共享对象连续性，常态不超过约 1.02。
- **淡化**：用于路由/媒体交叉、移动端等价替代和 reduced-motion。
- 操作反馈在 pointer/touch down 即出现；不等待请求完成才显示按钮按下状态。
- 可直接拖拽的元素必须从当前屏幕值继续、允许中断和反向；若本轮不实现连续拖拽，就不得伪造惯性物理。
- 普通 hover、揭示和页面切换不为“Apple 感”强行使用弹簧或 overshoot。

统一三档基础节奏，允许在设计验证后小范围校准：

- 反馈：100–160ms；
- 内容进入：360–480ms；
- 媒体交接：650–800ms。

### 6.3 对象连续性

优先建立三条共享对象动线：

1. 首页代表作品 → `/works/{slug}` 主图；
2. 首页自设委托大图 → `/commission` 大图；
3. 首页/领养卡图 → 对应作品详情同一媒体。

可以使用 View Transitions API 渐进增强；不支持时必须自然回落到现有页面淡入。不得为兼容该能力引入重型 polyfill 或破坏浏览器后退、锚点和焦点。

### 6.4 无障碍与偏好

- `prefers-reduced-motion`：关闭自动轮播、大位移、错峰、缩放和共享对象飞行，改为短淡化或静态。
- `prefers-reduced-transparency`（支持时）：Header/浮层使用更实的背景，关闭 blur。
- `prefers-contrast: more`（支持时）：提高背景不透明度与边界对比。
- 任何内容 SSR/无 JavaScript 默认可见。
- 动效不得阻断点击、键盘、后退、前进、锚点、焦点归还和错误页。
- 不自动播放声音，不调用振动 API。

## 7. 响应式契约

### 7.1 桌面

- 1440×900 为主要视觉评审基准，兼顾更宽屏。
- Hero 保持全视口冲击力，控制器降级为次要层；桌面箭头可在 hover/focus/边缘意图时增强显示。
- 代表作品大图建议占 70–90svh 的视觉高度，但不通过强制 pinned scroll 锁住用户。
- 委托幕采用图片与文案的非对称分栏，图片约占 65%–75% 可用宽度。
- 领养幕最多突出前两项，不把状态和价格叠成商品瀑布。

### 7.2 移动

- 保持原生纵向滚动和 `100svh/100dvh`、safe area、动态地址栏适配。
- 不依赖 hover，不强制横向滑动才能完成主要任务。
- 代表作品、委托和领养依次纵向堆叠；可选次级横轨必须有明确可见的“查看全部”替代入口。
- 大面积横向滑入、视差和长背景运动改为短淡化/轻微纵向进入。
- 输入法打开时，委托表单错误、勾选项和提交状态仍可见可达。
- 390px 和 430px 在每个组件完成时同步验收，不留到最终统一修补。

## 8. Hero 焦点契约

- 焦点只用于首页/委托 Hero 横版和竖版媒体。
- 首版 UI 为九宫格预设：左上、上、右上、左、中、右、左下、下、右下。
- 默认 `center`；未配置等同 `(0.5, 0.5)`。
- 底层继续保存归一化 `focal_x/focal_y`，UI 预设映射为 0 / 0.5 / 1；已有任意坐标保留并在 UI 映射到最近预设，不收紧数据库 CHECK。
- 只允许未启用 Hero item 修改焦点；已启用项先通过现有替换/下架流程变成未启用，再修改并重新发布。
- 预览必须使用目标横/竖比例和公开裁切逻辑，而不是原图完整缩略图。
- 焦点变化使旧站点展示变体失效；重新发布验证新变体后才清理旧对象。
- 作品卡、作品详情和领养自然比例图片不增加焦点编辑。

## 9. 委托申请告知与成年人契约

### 9.1 处理者

- 公开隐私页面必须显示实际经营主体名称和隐私联系邮箱。
- 经营主体名称不得用仓库假值默认填充；生产启用申请前必须由操作员配置。
- 联系邮箱复用现有官方邮箱，可作为隐私权利请求入口。

### 9.2 提交确认

表单提交前必须分别确认：

1. 已满 18 周岁，并有权提交该设定图；
2. 已阅读当前版本隐私政策，理解信息用于评估、联系、接单后的履行与售后；
3. 理解提交仅进入评估，不代表接单、最终报价、排期或合同确认。

确认不得预勾选。服务条款可以链接查看，但不把网站申请伪装成逐单合同签署。

服务器记录：

- intake contract version；
- 成年确认；
- 隐私政策版本；
- 申请告知版本；
- 确认时间。

不记录 IP、User-Agent、设备指纹或完整 Referer 作为确认凭证。

### 9.3 版本一致性

- 页面取得当前 intake metadata 后显示告知。
- 提交携带页面所见版本；服务器与当前版本不一致时返回稳定 409。
- 访客的字段和已选图片保留，重新阅读并确认后再提交。
- 历史申请保留 legacy 状态，不回填虚假确认。

## 10. 保存、复核与删除契约

### 10.1 保存规则

- 上传会话继续在 10 分钟内失效；未消费对象只用于本次申请，不作其它用途。
- 失效/失败/取消的未消费上传至少每月由人工运行既有清理工具。
- pending 申请至少每半年人工复核；不因时间到达自动接受、拒绝或删除。
- rejected（含明确放弃）在 `handled_at` 满 180 天后进入删除候选。
- accepted 在委托履行、1 年保修、争议处理与法律法规要求的必要期限均结束后，由工作室人工确认进入删除候选。
- 存在投诉、争议、执法要求或其它合法保留理由时，只延长相关数据并限制非必要使用。
- 第一方访问统计继续按现有 90 天规则。
- 真正匿名化、无法回链个人的月度数量统计可以长期保留；原手机号、QQ、体型和私有图不得以“统计”名义永久保存。

### 10.2 人工流程

- 未消费上传：至少每月。
- 委托申请：至少每半年。
- 用户删除请求：单独处理，不等待周期批次。
- 人工流程由文档/SOP 和 CLI 支撑，不建设 cron、Worker 或自动规则引擎。

### 10.3 删除范围

一次删除必须覆盖：

- `commission_submissions` 目标行；
- 对应 `commission_upload_sessions`；
- 委托私有 `assets` 关系；
- 私有原图、preprocess、preview、失败/待清理对象及其版本/delete marker（若启用）；
- 非必要内部备注和直接关联的临时文件；
- 未来若引入持久化制作单文件，也必须纳入；当前按请求生成、不持久保存的 PDF 无对象可删。

删除不影响独立作品记录、公开作品媒体或 QQ 中由工作室另行保存的逐单确认；这些拥有自己的业务和保存边界。

### 10.4 删除工具

- 默认 dry-run，只输出脱敏数量和状态。
- 单条必须显式 submission ID/receipt；批量必须显式 status + before。
- 正式执行要求 `--execute` 和固定强确认短语。
- DB 关系存在时先枚举精确 Key；对象删除/验证后再事务删除行。
- 对象已经不存在视为幂等成功；其它失败停止并允许按同一 ID 重入。
- 审计只记录操作者、时间、结果、计数和不可逆 ID 摘要。
- 应用备份不作普通查询；删除数据可能留在受限备份直到轮换，任何恢复在重新开放服务前必须再次执行当前删除/保留复核。

## 11. 服务条款与 QQ 确认契约

- 申请不等于接单；形成委托以工作室官方 QQ 中双方逐单书面确认的范围、价格、付款和排期为准。
- 网站服务条款是一般规则；QQ 中针对某笔委托的特别约定优先，未约定部分由一般条款补充。
- 网站必须提示并公平表述与客户有重大利害关系的取消、费用、修改、延期、运输、保修、公开展示和知识产权条款，不以单方免责替代业务流程。
- 客户已有角色设定权利仍归原权利人；工作室保留自己创作的版型、结构方案、工艺资料和工作室拍摄图片的权利。
- 客户取得实体所有权和个人穿戴、展示、拍摄、合理维修及非商业配件使用权。
- 未经书面许可禁止商业复刻、批量复制或授权第三方商业生产；正常维修不被笼统禁止，但第三方不当拆改造成的损坏可排除保修。

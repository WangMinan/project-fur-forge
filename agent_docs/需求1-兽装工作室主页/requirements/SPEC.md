# 需求规格：兽装工作室主页

> **角色**：当前功能、业务规则、安全边界和验收标准的权威规格。
> **状态**：阶段 C 已于 2026-08-07 经用户浏览器人工验收；阶段 D 正在确认返图墙范围。
> **关联**：产品边界见 [`../foundation/README.md`](../foundation/README.md)；媒体规则见 [`MEDIA-PUBLICATION-POLICY.md`](./MEDIA-PUBLICATION-POLICY.md)；实施方案见 [`../planning/PLAN.md`](../planning/PLAN.md)。

## 1. 产品目标

系统为“有点小狗工作室”提供图片主导的公开主页和唯一管理员后台。

当前已完成的核心范围包括作品展示、常规领养、委托说明、首页维护、品牌水印、备份恢复和可重复部署配置。系统不建设交易、订单、排期、多管理员或万能 CMS。

阶段完成与正式发布就绪是两个不同结论：阶段 C 已完成；GitHub Actions 全绿、正式域名、TLS、线上 Compose、升级、回滚和恢复演练仍由后续任务收口。

## 2. 访问面与路由

### 2.1 公开站

公开 Host 当前提供：

- `/`：首页；
- `/works`：作品列表；
- `/works/{slug}`：统一作品详情；
- `/adoptions`：当前常规领养；
- `/adoptions/{slug}`：兼容永久重定向到统一作品详情；
- `/commission`：自设委托；
- `/about`：关于工作室和官方联系方式；
- `/service`：服务条款；
- `/privacy`：隐私政策；
- `/contact`、`/terms`：兼容重定向；
- `/robots.txt`、`/sitemap.xml`：SEO 基础。

公开 Host 必须拒绝 `/admin/**`、`/api/admin/**`、认证接口、私有预览和其他管理路径。

阶段 D 的返图墙路由尚未确认，不在当前路由事实中。实施前必须明确独立页面和作品详情入口。

### 2.2 管理端

管理 Host 当前提供：

- `/admin/login`；
- `/admin/works`；
- `/admin/works/new`；
- `/admin/works/{id}`；
- `/admin/site/home`；
- `/admin/site/content`；
- `/admin/site/branding`；
- `/admin/account`。

管理 Host 根路径进入登录流程。未登录访问受保护页面不得先显示任何私有数据。

返图入口只在 T35–T36 实现后进入管理导航。未实现的阶段 D/E 功能不得显示可点击空入口。

### 2.3 媒体与上传 Origin

媒体公开 origin 和 OSS 上传 origin 与公开、管理 origin 必须互不相同。应用只在测试环境暴露假媒体端点；生产环境不得注册测试控制路由。

## 3. 作品领域

### 3.1 作品用途与装型

作品用途固定为：

- `commission`：委托作品；
- `adoption`：领养作品；
- `showcase`：纯展示作品。

作品装型固定为：

- `full`：全装；
- `partial`：半装。

### 3.2 基础字段

每件作品至少包含：

- 稳定 UUID；
- 唯一 slug；
- 角色名；
- 物种；
- 装型；
- 用途；
- 角色主人公开显示名；
- 可选私有联系人；
- 0–8 个短属性；
- 人工排序；
- 是否精选；
- 资源版本；
- 发布状态。

公开 DTO 必须把私有联系人固定投影为 `null` 或省略，不得因页面不同偶尔暴露。

### 3.3 领养字段

领养方式：

- `regular`：常规领养；
- `event_drop`：历史展会掉落兼容值；完整展会模型只有 T37 被用户保留后才实施。

当前常规领养状态允许：

- `preparing`；
- `available`；
- `scheduled`；
- `in_production`；
- `delivered`。

领养价格可为空；存在时必须为正数人民币最小单位。网站只展示价格，不执行登记、定金、付款或退款。

### 3.4 发布状态

作品状态固定为：

- `draft`；
- `published`；
- `unpublished`。

已发布作品的事实字段和媒体关系不能直接修改，必须先下架。排序和精选等展示设置可以通过受限接口调整，但仍需资源版本校验。

## 4. 媒体角色与上传

### 4.1 当前媒体角色

阶段 C 已实现：

- `design_sheet`：领养设定图；
- `studio_photo`：作品出厂照；
- `home_hero_landscape`；
- `home_hero_portrait`；
- 委托页横竖 Hero 的对应角色或 placement；
- `watermark_logo`。

角色必须与归属匹配：非领养作品不得绑定设定图；站点 Hero 与品牌 Logo 不得绑定到作品媒体关系。

阶段 D 返图必须使用独立 `return_photo` 角色或语义等价的严格枚举，不得复用 `studio_photo` 冒充返图。

### 4.2 原图上传

浏览器通过条件 PUT 直传私有 OSS，Nitro 不代理图片二进制。创建上传会话时必须声明：

- MIME；
- 字节数；
- MD5；
- SHA-256；
- 宽高；
- 归属类型、归属 ID 和归属版本；
- 媒体角色。

上传会话有效期 5 分钟，Object Key 不可预测且禁止覆盖。服务端完成时必须重新验证 HEAD、摘要、真实 MIME、真实尺寸、EXIF 方向和角色约束。

支持 JPEG、PNG、WebP；原图最大 30 MB，最大边不超过 12000 px。水印 Logo 必须是带透明通道的 PNG。

失败重试创建新会话和新 Key，不原位覆盖。过期上传会话由主动清扫命令处理，OSS 生命周期只作为临时前缀兜底。

### 4.3 私有预处理

超过 OSS 图片处理输入限制的原图，或经管理员明确确认的低分辨率站点大图，可以生成私有 FFmpeg 处理源。处理源不能替代永久原图，也不能宣称恢复原图不存在的细节。

## 5. 公开媒体与水印

媒体公开行为只以 [`MEDIA-PUBLICATION-POLICY.md`](./MEDIA-PUBLICATION-POLICY.md) 为准。当前关键要求为：

- 首页 Hero、委托页 Hero 和首页两个业务入口使用无水印站点展示衍生图；
- 作品列表、作品详情、领养列表和领养设定图使用活动 `brand-centered-v2` 水印；
- 首页委托和领养入口使用独立派生用途，不直接复用 Hero 或设定图公开 URL；
- 永久原图、处理源、Logo 候选和管理预览始终私有；
- 公开衍生图不可变，身份变化生成新 Key；
- 生成、验证和切换失败时保持当前公开版本。

阶段 C.1 的站点无水印迁移、既有素材 reconcile 和真实双 Bucket 验证已经完成，并经用户浏览器人工验收。

返图墙轻量水印尚未确认。实施者不得在 SPEC 更新前自行决定位置、不透明度、缩放、是否随活动 profile 切换或是否允许关闭。

## 6. 作品发布与下架

### 6.1 发布前检查

普通委托和展示作品至少需要：

- 完整有效字段；
- 至少 1 张 READY 出厂照；
- 恰好 1 张主出厂照；
- 全部公开图片有 alt；
- 所需作品水印变体完整；
- 活动水印 profile 可用。

常规领养还需要：

- 领养方式和状态有效；
- 至少 1 张 READY 设定图；
- 设定图 alt 有效；
- 价格字段成组有效。

`event_drop` 在完整展会矩阵落地前不得通过新的常规发布流程。

### 6.2 发布操作

发布必须：

1. 固化请求版本；
2. 生成缺失公开变体；
3. 验证公开对象；
4. 原子更新业务状态和公开投影；
5. 写入审计记录；
6. 失败时只清理当前 attempt 新建对象，保留旧公开状态。

### 6.3 下架与删除

下架先撤销公开状态，再精确清理不再引用的公开对象。发布中的作品不得删除。删除作品不得影响其他作品、首页、委托页、Logo profile 或共享源资产。

T40 未确认前，不假定全站已经存在 30 天回收站。返图的删除语义应在 T35 前单独确定。

## 7. 公开首页

首页顺序固定为：

1. 代表作品 Hero；
2. 精选作品；
3. 统一业务入口区；
4. 当前领养。

### 7.1 Hero

- 1–5 项；
- 横版和竖版为独立资产；
- 当前项才渲染图片，后续项按需加载；
- 自动轮播默认关闭，开启时最短 6 秒；
- 悬停、焦点、页面隐藏和减少动效时暂停；
- 支持按钮、键盘和触控切换；
- 横竖图均使用无水印站点展示变体。

### 7.2 精选作品

最多展示 6 件已发布精选作品，按人工顺序排列。无精选时整区隐藏；精选接口失败不得导致首页 Hero 和导航整体 500，可以降级隐藏并记录安全日志。

### 7.3 统一业务入口

入口区最多包含两张统一卡：

- 自设委托；
- 角色领养。

每张卡包括：

- 独立无水印入口图片；
- 业务标题；
- 当前营业状态；
- 一行短说明；
- 明确行动入口。

两张卡使用一致的比例、留白、文字层级和状态表达。缺少可用图片时，可以使用受控无图状态；不得泄漏私有原图或任意回退到其他作品。

### 7.4 当前领养

展示最多 2 件当前常规领养，并提供查看全部入口。无常规领养时整区隐藏。

## 8. 作品列表和详情

### 8.1 列表

`/works` 支持用途和装型的交集筛选，显示结果数量、当前筛选状态和清除入口。非法筛选参数不得抛 500，应返回空结果和明确提示。

作品卡保持统一比例，消费作品水印衍生图。列表只展示具有公开作品媒体的已发布作品；只有设定图、没有出厂照的常规领养可以出现在 `/adoptions`，但不进入 `/works`。

### 8.2 详情

统一详情包含：

- 角色名、物种、装型、用途；
- 角色主人公开显示；
- 短属性；
- 可公开领养价格；
- 设定图分区；
- 出厂照图集；
- 前后浏览；
- 相关作品。

详情图集必须根据当前图片方向布局：

- 横图可以使用宽舞台；
- 竖图完整显示并限制容器宽度，不在两侧显示横向灰色填充区；
- 不以 `cover` 裁掉竖图内容；
- 缩略图选中状态始终与主图一致；
- 路由复用或切换作品时重置到有效索引；
- 图片声明固有宽高，避免明显 CLS。

返图与出厂照是不同对象。阶段 D 实施后，作品详情可以提供关联返图入口，但不得把返图直接混入出厂照图集而失去语义。

## 9. 委托、领养与信息页

### 9.1 自设委托

`/commission` 展示：

- 独立无水印横竖 Hero；
- 当前委托状态；
- 全装与半装制作范围；
- 人工逐单估价机制；
- 邮件行动；
- 已确认 FAQ；
- 服务条款入口。

不得提供自动报价、固定价目计算、委托登记和付款。

### 9.2 常规领养

`/adoptions` 只展示已发布 `regular` 领养，使用带活动水印的设定图。空状态真实反映当前数据，不编造“即将上新”等承诺。

### 9.3 关于与官方渠道

`/about` 展示工作室事实、制作范围和官方联系方式。邮箱、QQ、抖音和防诈骗说明只来自管理端已保存值。

### 9.4 服务条款与隐私政策

`/service` 和 `/privacy` 使用独立、可阅读的正文布局。隐私政策必须与网站实际收集的数据一致，不复制与本项目无关的通用模板事实。

## 10. 管理端作品与媒体

管理员可以：

- 创建作品；
- 修改未发布作品字段；
- 管理设定图与出厂照；
- 设置主图、顺序、alt、焦点和裁剪；
- 查看私有原图预览和活动水印预览；
- 发布、下架和恢复失败清理；
- 调整已发布作品的排序与精选。

所有写操作必须携带资源版本。409 后重新读取服务端状态，前端不得自行递增版本或静默覆盖。

长操作必须展示基于服务端记录的持续状态；Spinner、按钮禁用或最终 Toast 不能单独充当任务进度。

## 11. 管理端首页与委托大图

首页和委托页大图使用同一管理能力但不同 placement，数据和操作不得混淆。

管理员可以：

- 上传横竖资产；
- 创建、编辑和删除停用项；
- 预览；
- 确认低分辨率适配；
- 启用、停用和排序；
- 查看发布、适配、失败和恢复状态。

首页必须保留至少 1 个启用 Hero；委托页允许全部停用。启用时生成无水印站点展示变体，不生成活动水印变体。

## 12. 管理端文案与营业状态

### 12.1 页面结构

`/admin/site/content` 按独立 Card 维护：

1. 委托基础文案；
2. 委托 FAQ；
3. 关于工作室与制作范围；
4. 服务条款；
5. 隐私政策；
6. 官方联系方式与防诈骗提示；
7. 委托、领养营业状态。

营业状态仍按业务分别保存。

### 12.2 独立保存与并发

每个内容分区：

- 只提交当前分区字段；
- 使用独立版本；
- 保存一个 Card 不阻塞和覆盖其他 Card；
- 409 后保留当前草稿，同时显示最新服务端值或明确重载选择；
- FAQ 行使用稳定 ID，不使用数组下标作为持久身份；
- 空字段按规格决定隐藏，不自动填充 Agent 编造内容。

邮箱、QQ、抖音和防诈骗说明统一在“官方联系方式”区域维护，不再分散在首页设置和文案配置两个入口。

T38 的“受限站点文字内容扩展”只允许增加经过确认的预定义字段或分区，不允许任意 HTML、页面树、脚本或通用页面搭建器。

## 13. 品牌水印管理

管理员可以上传受控 PNG Logo 候选、创建草稿 profile、预览、应用和恢复失败操作。

要求：

- 只能通过 `assetId` 选择 Logo；
- position 固定为 center；
- 不透明度和缩放受限；
- profile 不可变；
- 活动切换在所有作品保护变体完整后原子完成；
- 影响摘要明确排除无水印站点展示变体；
- 活动源和仍被引用 profile 不得普通删除。

## 14. 认证、安全与隐私

### 14.1 唯一管理员

- 只允许一个活动管理员；
- 密码使用强哈希；
- 连续失败可以锁定账户；
- 改密和离线重置使旧 Session 失效；
- Session 空闲上限 8 小时。

### 14.2 请求边界

- 管理写请求验证管理 Origin、Session 和 CSRF；
- JSON 请求体限制 64 KiB；
- 登录与管理写入按可信主体限流，不使用所有请求共享的单一全局计数器；
- 可信客户端 IP 只从明确配置的反向代理链取得；
- 错误响应使用稳定 `code` 和业务 `reason`，不向客户端返回堆栈或内部消息。

### 14.3 Host 与响应头

- 公开、管理、媒体和上传 origin 显式配置；
- 错误 Host 返回 421；
- 私有响应使用 `no-store`、`noindex`；
- Nginx 在正式环境提供 TLS、HSTS、CSP/`frame-ancestors`、基础安全头和请求体边界；
- 应用 Host 策略与 Nginx 路由保持一致。

### 14.4 日志与隐私

日志不得记录密码、用户名明文、邮箱、联系人、返图授权记录、Session、Cookie、签名 URL、AK/SK 或私有 Object Key。允许记录 request ID、动作类型、资源 ID、状态、失败阶段和脱敏主体摘要。

返图授权来源、确认时间和备注如被 T35 保留，只能进入受认证管理响应，不进入公开 DTO、HTML、图片元数据或普通日志。

## 15. 长任务与恢复

适用于：

- 作品发布与下架；
- Hero 发布与低分辨率适配；
- 水印 profile 全站应用；
- 站点展示 reconcile；
- 后续返图公开生成与发布；
- 其他需要跨多个 OSS 对象的操作。

每个操作记录至少包含：

- 状态；
- 请求版本；
- 进度；
- 失败阶段和稳定失败码；
- 已创建对象清单；
- attempt；
- lease owner 与到期时间；
- heartbeat；
- recovery reason；
- 必要的下一次重试时间；
- 完成时间。

容器启动时扫描未终止操作：

- 可安全重放的阶段重新取得 lease 并继续；
- 不能安全重放的阶段进入可恢复失败；
- 已提交业务状态但未写终态的操作通过幂等核对完成收敛；
- 清理失败保留精确对象清单；
- 运行中操作不得永久阻塞新请求；
- 重复重启不得产生重复公开对象或破坏旧有效版本。

## 16. 数据库、备份与恢复

- SQLite 使用 WAL、外键、busy timeout 和 FULL synchronous；
- 生产数据库路径固定在持久数据卷；
- 应用启动前确认迁移历史完整匹配；
- 迁移前对已有数据库创建验证备份；
- 恢复只写新路径，先执行完整性、外键和迁移匹配校验；
- 禁止在线覆盖当前活动数据库；
- 部署升级和回滚记录镜像版本、数据库备份和迁移边界；
- readiness 比较迁移数量、顺序、folderMillis 与 hash，不只比较数量。

## 17. 容器与目标环境

### 17.1 镜像

- 使用标准 Node 24 基础镜像；
- 通过 frozen lock 安装和构建；
- 不手工遍历、拍平或复制单个依赖闭包；
- 运行产物包含应用、生产依赖、数据库迁移和运维命令；
- 非 root 运行；
- 不包含 `.env`、开发数据库、测试夹具、截图和私有素材；
- 基础镜像固定到可审计版本或 digest。

当前 Node 24 runtime 镜像已经由 GitHub Actions `image-build` 成功验证。

### 17.2 Compose

版本控制内的 `docker-compose.yaml` 至少包含：

- `app`；
- 一次性 `migrate`；
- `nginx`；
- 持久数据库卷；
- 可选独立备份卷；
- 健康检查；
- restart、stop grace、只读根文件系统或等价收缩；
- 显式环境变量和 secret 注入；
- 明确单副本约束；
- app 的受控外部 egress 与不发布宿主机端口。

生产服务器默认拉取固定镜像标签或 digest，不在目标机用工作区源码构建。

### 17.3 健康检查

- `live`：Node 进程可响应；
- `ready`：运行配置有效、数据库可打开、迁移严格匹配、关键站点记录存在；
- OSS 和 Bucket 权限在启动 preflight 或部署门禁检查，不作为高频健康探测；
- 旧 `/api/health` 不得在未就绪时固定返回 ok。

## 2. 目标

1. 先消除公开端按钮、管理端按钮、上传反馈和长任务进度的重复实现，为后续页面改版建立统一地基。
2. 将公开站升级为以兽装摄影为主角、具有品牌节奏与角色生命感的编辑式工作室网站。
3. 首页继续覆盖作品、自设委托和设定领养全部核心业务，通过四幕引导用户，而不是将内容按同一尺寸和权重平铺。
4. 首页设定领养按既有排序投影最多三项当前 `available`，一次完整展示一个角色并提供真实切换；不足三项按真实数量退化，无可领养项时隐藏整幕。
5. `/adoptions` 只公开 `available`，按最近修改时间倒序并以 ID 稳定排序；`adopted` 继续保留在 `/works` 归档中。
6. 建立“简洁底盘 + 灵动角色感”的动效语言：既保持清晰和性能，也允许有节制的轻弹性、媒体聚焦、遮罩揭示和图文错峰。
7. 保证 PC Web 的大图效果，同时让移动端以原生纵向滚动和等价重排完成同一任务。
8. 保留横版/竖版 Hero 独立素材和独立集合，通过更清楚的管理信息架构降低维护成本。
9. 所有管理端耗时操作均提供诚实、统一的进度反馈；OSS 上传显示真实百分比，FFmpeg/operation 不伪造精确进度。
10. 将测试体系收缩为“稳定不变量 core + 少量主流程 smoke + 显式 release 验证”，移除对临时文案、DOM 和动画时长的过度耦合；真实视觉最终由用户人工验收。
11. 以轻量方式完成委托申请确认：使用现有隐私/联系文案，增加两个未预勾选确认和服务端字面量校验，不建设新的法律证据系统。
12. 提供人工复核驱动的单条申请精确删除能力，不引入 scheduler、批量自动删除或通用生命周期平台。
13. 重写默认关于我们、委托、隐私政策和服务条款，并从当前生成环境安装的 production dependencies 生成第三方声明快照；目标 Linux runtime closure 在发布产物阶段单独核对。
14. 代表作品收敛为最多五件竖版出厂照的 Type × Media 单幕，一次展示一件真实作品；多项时提供循环切换，角色名、物种与目录行动形成信息组，摄影与背景 Typography 建立明确关系。`/works` 使用角色等权的四列目录，有出厂照优先出厂照，完全没有时才回落领养封面或设定图。
15. 对公开站全部 11 个独立视觉状态完成美术覆盖：目录、统一详情、委托、申请、关于/联系、法务/许可证和 404/500，以及目录/表单/媒体失败状态。
16. `/adoptions/[slug]`、`/contact`、`/terms` 继续复用既有重定向终点，不创建重复页面模板；Footer 内容、布局、样式、响应式和交互完全冻结。

## 3. 非目标

- 不恢复返图墙、最新动态、FAQ、抖音、小红书或 Bilibili。
- 不建设通用 CMS、页面搭建器、海报生成器或每个断点独立的自由裁切编辑器。
- 不建设全站 scroll-jacking。首页按用户 2026-08-21 新确认，只在 `min-width: 1024px` 提供逐幕 wheel 导航；1023px 及以下不拦截原生滚动。仍不建设强制横向滚动、长时间 pinned scroll、全屏视差、3D 场景、持续粒子、持续角色摇摆或背景音效。
- 不要求复刻 Apple、渔屋或万物通行的品牌、素材、颜色和完整布局。
- 不把“Apple 式克制”理解成所有页面只剩淡入淡出，也不把“灵动”实现为处处弹跳。
- 不引入在线合同、站内订单、定金、支付、退款、排期、申请公开查询或访客账号。
- 不抓取、存储或解析 QQ 聊天记录；逐单确认由工作室在 QQ 中完成。
- 不建设身份证/人脸/出生日期核验或未成年人监护人流程；首版只接受成年人。
- 不新增 `privacy_controller_name`、intake metadata API、申请 contract version、确认持久字段、客户端版本握手或 stale 409。
- 不建设自动定时任务、Worker、数据库 TTL、通用数据生命周期引擎或时间条件批量删除。
- 不强制启用 GitHub required check，不让每个普通提交执行镜像/恢复/完整历史 E2E。
- 不为每次视觉修正增加永久回归用例，不以机械修正老测试作为功能完成证明。
- 不合并 Hero 横版和竖版数据，不要求数量、排序或图片一一配对。
- 不因网页没有 FFmpeg 下载入口就把公开容器发布写成“未分发”；镜像发布方式或仓库可见性变化后重新核对实际义务。

## 5. 品牌、渠道与信息架构契约

### 5.1 品牌

- 中文名称：`有点小狗工作室`。
- 短品牌：`有点小狗`。
- 英文名称：`DITE DOG`。
- slogan：`不只做小狗毛 | 只做海绵头`。
- 当前页面、SEO、JSON-LD、OG、README 和活文档不得称英文名为暂用名，也不得出现 `DITE DOG FURSUIT`。

### 5.2 联系渠道

- `/commission/apply` 是结构化申请入口。
- 后续评估、报价和逐单确认优先使用网站公布的工作室官方 QQ 私聊。
- 邮箱用于备用联系、隐私权利请求和 QQ 无法使用时的沟通。
- QQ群用于社群或一般交流，不作为默认订单确认渠道。
- QQ/QQ 群直达链接由服务端解析 READY 官方二维码派生，只接受无额外 query/hash 的 `https://qm.qq.com/q/*`；解析失败时保留二维码扫码兜底，不猜测链接。
- 不再维护独立防诈骗提醒；官方 QQ、邮箱和 QQ群的用途继续由联系说明与服务条款清楚区分。

### 5.3 首页四幕

首页顺序固定为：

```text
第一幕：品牌 Hero
第二幕：代表作品
第三幕：自设委托
第四幕：设定领养
```

- Hero 建立品牌和第一印象。
- 代表作品只占一个停靠幕，按管理端顺序展示最多五件；每件必须至少有一张 READY 竖版出厂照，优先使用竖版主图、其次使用顺序最前的竖版出厂照。
- 代表作品使用当前 Type × Media scene：一次展示一件真实作品，摄影为主要 anchor，背景 `SELECTED WORKS` 基本静止；多项时提供循环上一项/下一项与连续编号，单项隐藏伪控制和孤立编号。
- 名称、物种与“浏览作品展示”组成独立信息组；切换时只让摄影和名称/物种承担分层方向运动，CTA、controls、媒体外框与背景 Typography 保持稳定。Mobile 独立重排为摄影、切换器、信息的清楚顺序。
- Hero 与代表作品在手机/平板上以整幕为横向滑动命中区；轻微纵向漂移不取消横向切换，纵向意图继续交给原生页面滚动。代表作品图片轻触进入详情，横向滑动只切换作品且不得误导航。
- 自设委托是独立大型章节，不再放在带描边的 21:9 业务卡中。
- 首页自设委托幕与 `/commission` 均不显示“从角色设定出发”，也不增加替代 slogan；阅读顺序由标题、真实营业状态、说明和行动建立。
- 首页自设委托幕在 `767px` 以下竖屏按内容高度收束，不再用接近一屏高的容器把 stage 垂直居中；标题、背景字、摄影和信息组自然衔接，行动后只保留短呼吸。
- Hero 后三幕标题保持同一标题层级，但各幕使用不同 Composition；不能把共享标题、圆角或 wayfinding 解释为同一页面模板。
- 代表作品当前摄影与行动进入对应详情或 `/works`；自设委托提供 `/commission` 与 `/commission/apply`，设定领养提供 `/adoptions` 与当前角色详情。
- 自设委托主图只承担展示与共享对象连续性，不作为整图链接；导航只由两个明确行动承担。
- `/commission` 在 `1023px` 以下继续使用独立竖版素材，但媒体框改为 `4:5` 编辑式裁切且不高于 `50svh`，不得以完整 `9:16` 大图把核心文字推离第一视口；`1024px` 及以上保留左侧叙事、右侧横图的非对称分栏。
- 全局领养营业状态已退役；委托营业状态只保留“开放 / 暂停”两种语义和单条标签，不再有 `limited` 或独立短说明。
- 设定领养最多投影三项 `available`，一次完整展示当前一项并提供循环切换；媒体、名称、物种、价格和详情行动按方向分层切换，无可领养项时隐藏整幕。
- `/works` 与 `/adoptions` 继续承担完整目录、搜索和分页；`/works` 为角色等权四列目录，存在出厂照时优先出厂主图，完全没有出厂照的领养作品才回落领养封面或设定图；`/adoptions` 只公开当前 `available`。
- 领养作品统一详情必须显示真实领养状态；`available` 保留“联系咨询领养”，`adopted` 将该行动替换为不可导航的禁用按钮“已被领养”。
- `/works`、`/adoptions` 与 `/about` 的页名区复用 `/adoptions` 的高度、标题尺度和下方分割线；三者均保留浅色英文背景字与右上工作室 Logo 背景标记。`/commission` 保持自己的特殊构图。

## 6. 领养排序契约

### 6.1 `/adoptions`

服务端先过滤 `available`，再在搜索与分页前形成唯一有序集合：

```text
updated_at DESC
id ASC
```

- `adopted` 不进入公开领养集合，但仍保留在 `/works` 归档。
- 将作品修改为已完成会使它立即退出首页领养与 `/adoptions`。
- 名称搜索只做过滤，不重新排序。
- 分页在过滤后的有序集合上执行。
- 页面不增加状态分组标题，也不重复显示领养状态文字；物种与价格继续显示真实值。

### 6.2 首页

- 首页从同一排序口径中选择前三项 `available`。
- 首页聚合最多返回三项当前领养；不足三项时按真实数量返回两项或一项，不新增后台手动精选字段。
- 无 `available` 时整幕隐藏，即使存在 adopted。
- 首页精选仍可以包含 adopted，不受本节影响。

## 7. 视觉与动效契约

### 7.1 视觉原则

- 白底或极浅中性色继续作为主要内容底；摄影是最高视觉层级。
- 一个视口只建立一个主要注意力中心。
- 标题、说明和行动数量保持克制；大图不被厚边框、多个徽章或过多按钮分割。
- 模块面积交替形成节奏：全屏/大幅 → 次级浏览 → 大幅分栏 → 单幅领养收尾。
- 不要求每个模块制作专用商业海报；优先让现有真实作品图通过排版产生层级。
- 拼贴字体用于品牌与少量展示文字；正文保持系统中文无衬线/宋体层级。

### 7.2 动效定义

DITE DOG 的动效不是科技产品展示页的机械减法，也不是娱乐场景的无边界热闹，而是：

> **画面安静，角色会回应；布局克制，关键动作有生命感。**

允许的角色感手段：

- Hero 英文品牌与 slogan 可以使用遮罩/clip 揭示和 70–130ms 错峰；中文主标题从首次绘制起保持最终字号与位置，不在刷新时缩放、clip 或先大后小；关键拼贴字体预加载。
- 大图进入可从 `scale(0.985–0.995)` 回到 1，并带 12–24px 轻位移；
- 可点击作品在 fine pointer hover 时可上移 2–4px、图片放大约 1.02–1.04、轻微旋转不超过约 0.8°；
- CTA 箭头、下划线、分页点和图标可移动 3–6px 或有一次轻回弹；
- 成功、选择完成和轮播控制可以使用一次、低幅的 overshoot；
- 图像与 caption 可以使用不完全同步的进入时序，形成有呼吸的交接。
- Hero 静默态只保留低权重分页/进度；左右方向和暂停/继续不常驻，但在键盘焦点、fine pointer 边缘/控制区或触控显式唤起时可立即获得。暂停状态与恢复入口持续可见。

禁止：

- 空闲状态持续摇摆、呼吸缩放或循环漂浮；
- 所有按钮都弹、所有区块都从同一方向飞入；
- 多个大图在同一视口同时大幅运动；
- 为动画推迟导航、API 或可点击状态；
- 用随机粒子、全屏 blur/filter、长视差或高频阴影动画制造“灵动”。

### 7.3 动效语义与预算

- **反馈**：90–160ms，按下立即响应；允许一次轻回弹。
- **内容**：320–520ms，纵向/遮罩进入；移动端减少约 30%–50% 位移和错峰。
- **媒体**：600–850ms，crossfade + 方向/轻缩放；同一时刻只突出一个大媒体。
- **页面**：普通公开路由只使用 120–180ms、不阻塞的短 opacity 入场；不使用全站统一纵向位移、命名 View Transition 或跨页媒体 morph。
- 允许 `--motion-ease-playful` 一类轻 overshoot easing，但只用于图标、控制器、选择和短成功反馈；正文/法务/表单错误不用弹性。
- 一个视口默认只有一个“主要动效事件”；其余元素只提供辅助反馈。

### 7.4 输入模态

- Hero autoplay 固定为 3s；Featured 与 Homepage Adoption 保持 4s。鼠标/触控点击先提供 90–160ms 即时反馈，再执行更短媒体交接。
- keyboard 导航即时生效，图片只允许即时替换或约 120–180ms 的短 crossfade，不让键盘用户等待完整媒体动画。
- Hero drag 只有在 1:1 跟手、可反向、可中断、释放速度连续且不抢占纵向滚动时才允许实施；否则继续使用离散切换。首页桌面逐幕 wheel 是页面级章节导航，不等同于 Hero drag。
- 同一命令被再次触发、反向触发或路由离开时，动画必须可中断，不锁住焦点或控制器。

### 7.5 响应式与偏好

- 1440×900 为主要视觉评审基准，兼顾更宽屏。
- 首页在 `min-width: 1024px` 时，每次纵向 wheel 只移动到相邻完整幕；顺序为 Hero → 代表作品 → 自设委托 → 设定领养 → Footer，向上按相反顺序返回，动画进行中不重复吞入下一步。
- 首页 Header 在逐幕滚动期间固定于视口顶部；滚动容器只应用一次 Header 高度的 `scroll-padding-top`，当前幕不得被覆盖，也不得露出上一幕残片。
- 代表作品幕从固定 Header 下方开始，Type × Media scene、角色信息、切换控制与 `/works` 行动在同一动态视口内完成；没有第二屏或第二个停靠点。
- 1023px 及以下继续原生纵向滚动；Hero 仍按现有方向逻辑选择横/竖素材，不照搬外部站点的 768px 断点。
- 移动端保持原生纵向滚动、safe area 和动态地址栏适配。
- 1023px 以下不显示任何“下一幕”导线或文案；Safari 动态工具栏改变可视高度时，不据此连续切换整幕布局或最小高度。
- 窄屏 Homepage Adoption 的角色名保持单行，主行动保持至少 44px 命中区但使用紧凑字号和内边距。
- 移动端不依赖 hover；不使用 tilt；按压反馈和短淡化承担等价作用。
- `prefers-reduced-motion` 关闭自动轮播、大位移、错峰、tilt 与 overshoot，直接进入可靠终态；普通路由仍只允许必要的短淡化。
- `prefers-reduced-transparency` 关闭 blur，使用更实背景。
- `prefers-contrast: more` 提高背景与边界对比。
- 任何内容 SSR/无 JavaScript 默认可见。
- 公开非 hash 路由在导航完成第一帧位于页面顶部；再次点击当前页的品牌/导航入口也回到该页页头；浏览器返回/前进等待目标页加载完成后恢复历史位置，真实 hash 继续按统一 Header offset 定位。

### 7.6 路由与场景连续性

- 正式公开路由统一使用短 opacity 入场，不启用命名 View Transition、跨页媒体 morph 或共享对象飞行；V13 的 shared-media Evidence 仅作为历史实现记录保留。
- 连续性由相同摄影来源、焦点、圆角、页面标题和返回路径建立，不依赖媒体在两个页面之间移动。
- Homepage 内部的 Hero、Featured 与 Adoption carousel directional motion 继续有效；它们是页面内状态切换，不属于跨页媒体 morph。
- Footer 不做整体滚动入场，首页各幕不复用同一种 section reveal，次级卡片不批量飞行。

## 8. 行动、上传与长任务反馈契约

### 8.1 公开行动

统一三种公开行动：

- `primary`：每个章节最多一个；
- `secondary`：低强调辅助行动；
- `text`：文字 + 箭头/图标。

不得在 about、commission、adoptions、首页和空态中分别复制胶囊/边框 CSS。组件要保留 NuxtLink/button 的正确语义、focus、disabled/loading 和触控尺寸。

### 8.2 管理端行动

- 管理端保持独立视觉 token，但按钮形态、danger、loading、disabled、确认和反馈必须统一。
- 不把每个业务组件中的局部 `button` CSS 当作长期方案。
- 上传、保存、发布、下架、重试、删除的动作层级保持一致。

### 8.3 统一进度

通用进度组件至少支持：

| 模式 | 适用 | 显示 |
| --- | --- | --- |
| determinate | OSS XHR、可计数的变体生成 | 真实值/总量、百分比或数量 |
| stage | publication/Hero operation | 当前服务端阶段、已完成计数、终态 |
| indeterminate | 单图 FFmpeg、无法估算的服务端处理 | 阶段、经过时间、仍在处理 |

- 不把阶段常量映射成 12/35/56/91 之类伪精确百分比。
- 任何 OSS upload 必须在客户端已有 progress callback 时显示真实进度。
- FFmpeg 若没有可验证的总帧/总工作量，只显示 indeterminate；不得为了进度条解析不可靠百分比。
- 长 operation 刷新页面后应恢复服务端状态；短时 XHR 页面离开后可明确终止。
- 所有进行中状态立即可见，成功/失败/重试/取消使用同一组件语义。

### 8.4 公开媒体处理

- 后台不再提供自动图片叠加配置、Logo 上传、预览或全站重建入口。
- 当前作品公开图统一生成无叠加 `recipe-v4`；公开投影优先且最终只保留 v4。
- 当前数据库不得存在对应 profile/operation/branding 表、媒体身份列或上传角色。
- 0051 只向前迁移；部署必须停写并使用同一冻结镜像显式备份、migrate、dry-run/强确认退役旧 v1-v3 媒体、再次 migrate 和 ready。失败时原命令幂等重试，不进入容器手改 SQLite。
- 页面中的浅色工作室 Logo 是 CSS 背景标记，不进入图片派生链。

## 9. Hero 管理契约

### 9.1 数据模型保持独立

- 首页横版、首页竖版、委托横版、委托竖版四集合继续使用各自 version、items、顺序和发布 operation。
- 横竖素材数量和顺序可以不同。
- 不新建配对表，不强制同一角色图片或同一 sort order 一一对应。
- 焦点继续复用 `assets.focal_x/focal_y`；未启用 item 通过目标画面内拖动焦点与水平/垂直滑杆编辑，不再使用九宫格预设。

### 9.2 管理信息架构

现有四个扁平 Tab 改为：

1. 一级：`首页大图` / `委托页大图`；
2. 二级：`横版` / `竖版`，同时显示另一个方向的就绪摘要；
3. 首页和委托页均通过横/竖二级 Tab 只显示当前方向；顶部持续显示两方向计数摘要，首页为 `横版 X/5 · 竖版 Y/5`，委托为 `横版 X/1 · 竖版 Y/1`。

还应提供：

- 桌面/手机画框预览切换；
- 当前方向、启用数量、缺图/处理中状态；
- 同一通用 editor/card 驱动四集合；
- 操作进度使用统一组件。

管理 UI 的统一不能改变四集合的独立 CAS、上传 owner、发布和清理边界。

## 10. 轻量委托确认与隐私契约

### 10.1 处理者和政策

- 用户已确认个人信息处理者的精确名称为“有点小狗工作室”。
- 该名称通过现有 `privacy_policy` 文本和只覆盖空值/精确历史默认的前向迁移维护；不增加结构化字段，不覆盖管理员自定义政策。
- 隐私联系邮箱复用现有 `contact_email`。
- 隐私政策必须描述站内表单真实收集的称呼、物种、手机号、QQ、身高、体重和私有设定图。
- 同一就绪校验用于生产 readiness/live preflight、匿名上传会话创建、submission 创建和申请页可提交状态；空白、占位、旧“不收集联系方式/设定图”、处理者/收集范围不完整或未引用当前有效邮箱时，委托申请 fail closed，管理端仍可编辑政策。

### 10.2 提交确认

表单仅保留两个未预勾选确认：

1. 已满 18 周岁，并有权提交该设定图；
2. 已阅读隐私政策，并理解信息用途以及提交不代表接单、最终报价、排期或合同确认。

请求新增：

```ts
adultConfirmed: true
privacyNoticeAcknowledged: true
```

- 服务端使用 `z.literal(true)` 或等价严格校验。
- 校验在 upload session 被消费之前完成。
- 不新增确认数据库列、管理展示、申请版本、独立 metadata API、客户端 policy version 或 stale 409。
- 本确认是提交门槛，不是逐单合同签署或电子签名。

### 10.3 制作单导出

- 制作单 PDF 默认完整嵌入离线派生的常用简体中文 Noto Serif SC；任一单据文本缺字时完整回退仓库内原字体，不使用已知会导致部分阅读器方框的运行时 CJK 子集。
- 私有设定图保持既有原始像素和画质路径，不为减小 PDF 做缩放、降质或有损转码；JPEG/PNG 直接嵌入，WebP 沿既有无损 PNG 解码路径进入 PDF。
- 导出按钮先显示真实“正在生成”阶段；响应开始后只根据 `Content-Length` 与实际已读字节显示下载字节和百分比，不伪造服务端生成进度。

## 11. 保存、人工复核与删除契约

### 11.1 保存规则

- 上传会话继续按现有 TTL 失效。
- 失效/失败/取消且未消费上传至少每月人工运行现有清理。
- 委托申请至少每半年人工复核。
- rejected（含明确放弃）一经拒绝即进入人工删除候选，不再等待 180 天。
- accepted 在委托履行、1 年保修、争议处理与法律必要期限结束后，由工作室人工判断。
- 存在投诉、争议或合法保留理由时，只延长直接相关信息。

### 11.2 工具边界

- Review 可以列出脱敏候选和状态。
- `/admin/commissions` 与 CLI 使用同一单条 dry-run/execute 能力；列表与详情入口不得引入批量删除。
- 正式执行每次只允许一个 submission ID/回执，不提供按日期批量 execute。
- 默认 dry-run；execute 需要固定强确认。
- 一次删除覆盖 submission、upload session、私有 asset/variants/current/version/delete marker/preview/pending 和非必要备注。
- DB 关系存在时先枚举精确 Key；对象验证后再删行。
- 不影响作品、Hero 或其它申请。
- 用户删除请求单独处理，不等待周期批次。

## 12. 测试与门禁契约

### 12.1 原则

- 需求文档和用户确认定义业务；测试不能反向锁死临时实现。
- 测试失败后先判断是稳定不变量回归，还是测试绑定旧文案/DOM/动画时长；不得直接把旧断言改成新数值以追求全绿。
- 同一不变量只保留最合适的一层测试；不默认 unit + integration + E2E 三重覆盖。
- 每个历史 bug 不自动获得永久测试。只有高影响、易复发且可稳定断言的问题进入 core。

### 12.2 Core

日常自动验证只保留少量稳定不变量：

- Host/session/CSRF/Origin、限流和匿名上传 token/TTL/一次消费；
- PII/私有媒体不进入公开投影和普通日志；
- migration、foreign key、integrity 和前向重入；
- publication/deletion 的状态机、精确对象和幂等；
- 公开排序等明确业务契约；
- production build/readiness 的基础可用性。

### 12.3 Smoke

Playwright 精简为少量用户旅程，不断言审美和内部 DOM：

- 首页可加载和主要入口可达；
- works/adoptions 目录与详情；
- 委托申请成功/主要失败；
- admin 登录；
- 一条上传与长任务进度；
- 作品发布/下架；
- privacy/service/licenses 可读。

不得把精确 transition duration、全文文案、局部 class、卡片数量的历史实现或每个断点的像素结果写成普通 smoke 门禁。

### 12.4 Release 与人工门禁

- 默认 push/PR workflow 只运行快速 checks；文档改动不触发应用全量套件。
- 镜像、Compose、恢复、Nginx、destructive drill 和历史全量套件移入显式 release/manual 流程。
- 旧全量测试完成分类后，稳定不变量提升为 core、主旅程提升为 smoke，其余实现型覆盖物理删除；不保留平行 legacy 套件。
- 王旻安/景宸对真实图片、页面层级、动效节奏、文案和手机体验拥有最终验收权。

## 13. 服务条款与第三方声明契约

- 网站服务条款是一般规则；具体范围、价格、付款、排期、修改、交付和特殊约定在官方 QQ 中逐单书面确认。
- 工作室在确认接单或收取约定款项前，应在官方 QQ 中提供或明确引用当时适用的服务条款，并提示取消、费用、责任限制、公开展示等重大事项；不能只依赖网页公开可读来推定客户接受。
- 条款不得以“所有解释权归工作室”或不合理单方免责兜底。
- 客户角色设定、实体所有权、工作室版型/工艺/照片、合理维修和商业复刻边界按 `COPY.md`。
- npm 声明从当前生成环境的 lockfile/安装结果确定性生成，并明确平台可选包只代表该生成环境；它不是目标 Linux runtime closure。跨平台 drift 在显式 release 检查中处理，不进入日常 `check:fast`。
- FFmpeg 在自有服务器容器内运行，但当前 release workflow 会把包含 FFmpeg 的镜像发布到公开 Docker Hub；按二进制分发场景保存并向镜像接收者提供精确版本/摘要、许可证、可访问的对应源码、补丁与构建配置。网页不提供单独下载入口不改变该事实。
- Noto Serif SC 按 SIL OFL 1.1。
- `zhuohei-collage.ttf` 来源为 Lemi Font 免费商用声明，作为第三方授权资产，不称为开源软件。
- 不新增 required check 或独立重型许可证 workflow。

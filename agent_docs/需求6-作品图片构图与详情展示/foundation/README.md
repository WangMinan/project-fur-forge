# 阶段 0 · 地基：作品图片构图与详情展示

## 模块边界

本需求在既有作品媒体链路中增加按用途构图、领养封面选图和详情显隐；维持页面排版、画框、响应式栏目结构与既有业务资格。用户已确认这些产品方向，本次执行限于文档准备。

| 模块 | 本需求职责 |
| --- | --- |
| `app/components/admin/` 与作品编辑页 | 复用现有保存、未保存提示和媒体区域，接入构图编辑器、来源选择、详情开关 |
| `shared/schemas/` | 管理输入、明确用途/显示模式、公开 sources 与 thumbnailSources |
| `server/database/` | 新增前向迁移与约束，不重写历史迁移 |
| `server/utils/service/work-management.ts` | 版本校验、作品偏好保存、图片关联与构图保存 |
| `server/utils/recipe/`、`runner/work-publication.ts` | 精确选区、处理源几何、不可变身份、完整成套生成与验证 |
| `server/utils/repository/public-site-repository.ts` | 各用途取图、领养来源、详情显隐、完整构图集合读取 |
| 公开作品/领养组件 | 对应用途显示、方形缩略图尺寸、可见图库初始选图 |

排除首页/委托 Hero 资产及其四集合管理、委托私有设定附件、二维码、SMTP、站点部署拓扑。共享代码调整不得改变这些范围的运行行为。

## 接口口径

- 管理继续使用 `/api/admin/v1/works` 下既有版本化接口，公开继续使用现有首页聚合与作品/领养 DTO。
- Host、Session、Origin、CSRF、body 校验与 `no-store` 沿用现有边界。
- 显示开关只筛选详情；封面来源只控制领养目录与首页当前领养；不得从共享快照提前删除图片。
- “不在详情显示”不表示撤销公开文件或转为私有。所有图像角色保持真实身份。

## 数据库口径

- 沿用 SQLite、works、work_assets、asset_variants 与持久发布操作；不新增通用媒体 CMS 或外部处理服务。
- 构图唯一性为作品图片关联与用途；原图身份不可变。具体模型和兼容映射见 [models](../models/README.md)。
- 数据库迁移只加配置默认值和必要约束，不联机重建图片、不写生产库、不自动删除旧对象。
- 删除重插关联的旧保存方式必须适配构图保留；顺序、说明、主图改变不构成构图重置。
- 源图与手动选区变化纳入派生身份，公开读取必须选择与已生效配置匹配的完整变体集合。

## 安全约定

- 管理编辑器使用认证同源预览，不下发私有 OSS GET 签名地址；固定预览规格与会话规则沿用 [当前部署文档](../../../docs/DEPLOYMENT.md)。
- 构图坐标相对方向一致的完整源图，不相对 CSS 画框、已裁卡片或私有 Hero 居中中间图。
- 公开端仅消费验证为 READY 的派生物，不接收私有 Key 或客户端 OSS 转换参数。
- 不记录凭据、签名 URL、生产 PII；测试使用合成图片与虚构作品。
- 继承 [需求3退役边界](../../需求3-站点业务简化与委托投递/foundation/README.md) 和 [需求4 SPEC](../../需求4-站点视觉升级与内容合规/requirements/SPEC.md)：不恢复返图、自动水印或其他退役能力。

## 编码与命名约定

- 管理端名称使用“作品目录”“首页代表作品”“详情缩略图”“领养目录”“首页当前领养”，不向管理员展示配方版本和内部 usage。
- 优先复用现有组件与服务，Cropper.js 仅包一层后台适配；不自建裁切引擎。
- 无关业务契约保持现状，包括出厂照最多五张、主图选择、代表作品资格、领养发布素材要求与公开排序。
- 不擅自扩大 main 小修例外；本需求涉及 Schema 与媒体契约，使用独立任务分支。

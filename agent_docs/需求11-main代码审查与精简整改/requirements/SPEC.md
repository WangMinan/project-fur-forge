## 目标

1. 修复审查发现的数据丢失、安全匹配和任务恢复问题。
2. 移除无效输入和无业务调用的旧链路，统一已经出现漂移的业务规则。
3. 对确定重复的职责做小范围复用，减少同一行为多处维护。

## 契约与逐项验收

## 接口契约

- F02 不增加公开能力，只让已有安全边界覆盖等价路由。
- F06 涉及表单状态与请求冗余字段；先区分写入字段、读取字段及旧调用兼容，不删除真实排序机制。
- F08–F12 以行为等价为目标，不增加外部接口、选项或依赖；重构不能削弱现有验证。

## 数据模型与存储契约

- 模型现状和拟处理方式见 [models](../models/README.md)。首轮没有模型迁移；PR #41补修新增0056前向字段，尚未应用到实际业务库，见文末。
- F01 的删除互斥需覆盖版本/状态核验与首次外部删除之间的异步窗口，不能仅把进程内锁的 key 换成 ID。
- F03/F05 的“过期”与“失去执行者”须有可验证依据；不能把单次请求慢直接视为可删除。
- 精简不删除用户数据，不改写旧 migration，不撤回已发布不可变媒体。

## 非目标

- 不新增产品能力、统一所有页面布局、重做组件库或进行全仓库格式化。
- 不恢复已退役能力，不删除历史兼容保护、迁移校验和隐私断言。
- 不修改测试时限或 required checks 来掩盖失败。
- 不执行 Git 发布流程、真实邮件、OSS/ESA 操作或生产部署。

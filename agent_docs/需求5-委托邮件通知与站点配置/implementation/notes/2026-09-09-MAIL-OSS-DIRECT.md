# 邮件发送与后台图片直读修复

用户授权在 `codex/admin-oss-direct-mail-timeouts` 实施，并通过 PR 合入 `main`。本次不新增依赖、迁移、ESA 函数或云配置，不发布生产环境，不发送真实测试邮件。

## 行为

- SMTP 的建连、问候、连接空闲超时均为 600 秒，每个收件人首次失败等待 60 秒，最多尝试两次。正常失败与过期任务恢复均遵守上限，已成功收件人不重发。
- 原 Nodemailer 普通传输器的 `close()` 不关闭在途连接，现通过可取消 TCP 连接中断发送；TLS 仍由 Nodemailer 验证。停止信号立即取消工作，落库先于关闭 SQLite，Nitro 停止超时 4 秒、容器宽限 5 秒。
- 中断且可能已传输的邮件记为 `failed + UNKNOWN`，需先核实收件箱再人工重试；硬退出后过期恢复采用相同规则。不承诺 SMTP 恰好一次交付。
- 既有管理图片入口支持 `delivery=url` 返回 `{ data: { url, expiresAt } }`，默认返回不缓存的 302。只对登录管理员按资源 ID 签名，固定 320/640 缩略参数或显式原图。原图与缩略字节由浏览器从 OSS 读取。
- 浏览器签名使用已有公网客户端，服务端内网读取不变；Hero 临时预览同时受自身到期时间限制。邮件附件与工作单继续消费原始图片。
- 已显示图片不会随签名到期重新下载。恢复可见、焦点、页面恢复及重联网事件合并处理，失败自动重新签名一次；持续失败提供可键盘操作的重载按钮，按钮不被焦点编辑覆盖层遮挡。
- 图片请求和 `GET /api/auth/session?touch=0` 不更新活跃时间或续 Cookie；无定时保活。签名只在当前页面内存中使用，退出/卸载清理，晚到响应不覆盖新资源。

## 本地配置排障

用户本地上传失败的原因是 `OSS_UPLOAD_BASE_URL` 仍指向未配置的 `upload.localhost`。
仅在忽略的 `.env` 修正为既有私有 Bucket 的 HTTPS 公网地址；真实 CORS 预检返回 200。
后续发布失败来自公开媒体占位域名无法解析，以及媒体 Origin 与后台 Origin 重复。
现场确认现有 ESA 可读取开发前缀衍生图后，修正本地 `MEDIA_BASE_URL`；未修改 ESA 规则或 Bucket 权限。
通过原有服务层重试用户已发起的本地开发大图发布任务，任务完成、图片启用，10 个开发衍生文件均返回 200；用户重启服务后确认首页正常。

本地 Origin 必须分别配置：公开站、后台、公开媒体、浏览器 OSS 读写不能混用。
`media.localhost`/`upload.localhost` 只是无云环境的占位值，不代表可用的媒体服务。
是否允许开发前缀由目标 ESA 实际规则决定，不能用本地验证代签生产边界或 CPU 降幅。
真实站点 ID 和凭据不写入此记录；合入与 CI 结果以该分支的 GitHub PR 为准。

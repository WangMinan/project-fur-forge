> **角色**：记录当前模型、人员与工作轨道的可变执行安排。

> **生效日期**：2026-07-30。

## 1. 当前角色

| 角色 | 当前责任 | 当前安排 |
| --- | --- | --- |
| `UI_PRIMARY` | 生产视觉、Vue 页面与组件、响应式、前端交互、浏览器状态和视觉证据 | Kimi K3 |

## 4. 分支与批次策略

不建立从 T06 延续到上线的长期 Kimi 分支。每个前端批次必须从已合并、已验证的最新 `main` 创建，并在对应依赖稳定后尽快合并：

```text
feature/t06-t07-kimi
feature/t19-t20-kimi
feature/t24-t30-kimi
feature/t36-t41-kimi
feature/t51-kimi
```

批次之间不得依赖长期未合并的 mock 或过期 DTO。若候选实现需要比较，不直接合并两套完整视觉系统；以选定方案为主，只移植另一方案中边界清楚、确有优势的局部组件，并统一 Token、命名和间距。

## 5. 路由维护规则

- `TASKS.md` 继续只描述产品任务、依赖、验收和完成状态，不在每个任务标题中写模型名。
- 当前批次或模型发生变化时，先更新本文件，再同步 `STATE.md` 的当前阶段与下一步。
- `artifacts/ARTIFACTS.md` 只登记本文件的存在与当前效力，不把执行路由提升为产品契约。
- 模型能力、订阅或工作方式变化不触发 SPEC/PLAN 变更；只有业务、数据、接口或体验契约变化才走上游文档流程。

# Design Brief：兽装工作室管理端

## Problem

景宸需要在不了解 SQLite、OSS、SEO 和发布边界的情况下维护作品、首页轮播与站点内容。首要风险是误公开私有资料、误删原图、把横版设定图和竖版出厂照混成一个“主图”、只上传首页一个方向、发布无水印图片，或被一套远超实际业务的 CMS/Dashboard 淹没。

## Solution

把管理端设计为“安静的内容工具”：登录后直接进入作品管理；页面按作品、媒体角色、首页轮播、营业状态和站点内容等真实对象组织；保存、处理、发布和失败状态持续可见。首页使用专用轮播编辑器，每项明确配对横版/竖版；作品编辑器按设定图、出厂照分组，P1 再增加返图；公开预览显示真实比例和水印。P0 只显示已实现核心入口，P1/P2 功能实现后再进入导航。

## Experience Principles

1. **发布确定性高于操作速度**：草稿、处理中、READY、已发布、已下架和失败必须清楚区分。
2. **媒体角色高于通用上传器**：首页横版、首页竖版、设定图、出厂照和返图必须有清楚用途与数量约束，不允许所有文件落入同一列表。
3. **业务对象高于万能 CMS**：用“作品、首页轮播、返图、营业状态、站点内容”等直白名称，不用含义模糊的页面树。
4. **最小上线范围高于功能堆积**：P0 不显示邮件找回、原图档案、导出、统计等 P2 假入口。
5. **私有信息最小暴露**：浏览器以 `assetId` 操作媒体，不展示私有 Object Key；联系人和返图授权记录不进入公开预览。
6. **原图保护高于视觉捷径**：私有原图无水印、不可覆盖；水印预览代表公开衍生结果，不修改原图。
7. **高频轻操作优先**：PC 完成横竖配对、复杂裁切和水印安全角；手机完成登录、查看、状态、文字、单图和发布。
8. **长任务进度高于等待猜测**：上传、处理、发布、全站重建、批量清理、导出和恢复等操作持续显示真实阶段与进度，失败可读，刷新可恢复。
9. **E2E 页面结果高于通过数量**：端到端测试必须认真验证用户实际看到和操作到的页面；数量、状态码或元素存在不能替代图片、布局、焦点、中间状态与错误恢复检查。

## Aesthetic Direction

- **Philosophy**：Quiet Editorial Tool。
- **Tone**：平静、清楚、可靠，不做企业销售化 Dashboard。
- **Canvas**：白色与浅灰工作区；品牌蓝只用于主行动、焦点和当前导航。
- **Color ratio**：管理端不要求公开站的摄影面积，但仍禁止大面积深蓝侧栏或整页蓝色卡片；蓝色应是局部操作色。
- **Media previews**：预览区域用中性棋盘/浅灰安全画布区分“完整 contain”和“裁切 cover”，并叠加真实水印结果，不以假占位冒充已处理图片。

### Anti-references

- 默认 Dashboard、KPI、图表、消息中心和动态公告；
- 把公开站的大字、图片叠加和装饰动效搬进后台；
- 用全屏弹窗承载完整作品编辑或轮播编辑；
- 超长万能表单、所有控件都胶囊化；
- 把所有媒体塞进一个“图片”区，只提供一个“上传出厂照”按钮；
- 用一个焦点控件声称已经完成首页横版/竖版适配；
- 用 CSS 预览水印却发布无水印文件；
- 用模拟成功 Toast 掩盖 OSS、数据库或发布失败；
- 在 P1/P2 未实现时展示可点击空入口。

## Scope by Phase

### P0 Navigation

- 作品；
- 首页内容（能力接通后显示，包含首页轮播与精选）；
- 营业状态；
- 必要站点文字内容；
- 账号（改密、退出）。

登录后直接进入作品列表，不设置 Dashboard。首页内容入口在 T20 完成前不得以假页面出现。

### P1 Navigation

- 返图；
- 当前展会；
- 回收站；
- 更完整站点文字内容。

### P2 Navigation

- 原图档案；
- 完整导出；
- 访问统计；
- 登录页可用的邮件找回入口（不是主导航项）。

P2 未实现前不出现。

| `HomeHeroEditor` | 1–5 项排序；每项横版/竖版双上传、alt、启用、可选作品关联、方向预览和自动轮播开关 |

## Key Interactions

- 未认证只渲染登录；P0 密码重置通过受保护命令，不制造无法使用的找回链接。
- 创建作品按小步保存草稿；现有作品使用快速编辑，不强迫重走向导。
- 联系人字段明确标注“仅后台可见”；不提供定金/付款备注字段。
- CNY 价格只在领养/掉落作品出现，清空表示公开端整个价格区域隐藏。
- 选择领养用途后出现单独“设定图”区，最多 1 张并提示横版完整画布；“出厂照”区最多 5 张并提示作品墙 3:4/详情原比例。
- 出厂照文件控件不直接暴露浏览器原生样式：使用统一的“选择照片”按钮、文件名提示和独立上传按钮；刷新后通过 `assetId` 短时预览继续显示私有原图。
- 摘要、PUT 百分比和服务端校验状态显示在上传按钮附近，不能因状态卡位于长列表上方而离开当前视口；关系保存成功后立即清除“出厂照有未保存更改”。
- 页面有未保存修改时，“发布”仍可触发；界面先完成现有修改的保存，再刷新发布待办并决定是否继续发布，避免管理员在顶部和媒体分区之间反复找保存按钮。
- 作品列表为未发布作品提供删除入口；确认框必须说明公开衍生图清理、私有原图保留、已发布作品需先下架和不可撤销范围。
- 首页轮播每项同时显示横版和竖版两个明确槽位；缺失任一项、alt 或 READY variant 时阻止启用/发布，不静默回退到另一方向。
- 首页横/竖预览使用实际 `<picture>` 选择与水印结果；管理员可从四角选择安全锚点，但不能关闭 P0 必须水印。
- 返图授权来源、确认时间、备注均为可选，界面标题使用“授权记录（可选）”，不形成发布阻断清单。
- 上传状态按“计算摘要 / 私有上传 / 校验 / 处理 / 水印 / READY / 公开生成 / 失败”展示。
- 发布不显示“切换 ACL”；应显示“生成并验证公开图片”。
- 发布期间显示“已生成 / 总数 / 剩余”的原生进度条；失败信息持续可见，不要求管理员刷新页面判断进度。
- 其他长耗时操作沿用同一反馈模式：总量未知时显示不定进度，总量确定后展示真实完成量/总量；操作标识和服务端状态允许页面重载后恢复。不得只改变按钮文字、只显示 Spinner 或等请求结束后再展示结果。
- 手机遇到横竖配对、复杂裁切、批量排序、水印安全角或原图档案时明确提示使用桌面，不提供半成品控件。

## Responsive Behavior

- 桌面 ≥1280px：侧栏 + 主工作区；编辑与预览/发布检查可并列；首页轮播横竖预览并列。
- 平板 768–1279px：折叠导航；编辑和预览切换显示；横竖槽位上下排列但角色标题始终可见。
- 手机约390px：单列；登录、查看、状态、文字、单图上传和发布完整可用；复杂横竖配对和水印锚点给出桌面提示。
- 常规编辑使用页面；对话框只处理确认和短流程。

## Accessibility Baseline

- 标签、帮助、错误和字段程序化关联；
- 横版/竖版、设定图/出厂照不能只靠缩略图比例区分，必须有文字标签；
- 错误汇总可定位首个问题；
- 表格、菜单、步骤、上传、排序和对话框键盘可达；
- 状态同时使用文字、图标和颜色；
- 主要触控目标至少 44px；
- 减少动效设置得到尊重。

## Out of Scope

订单、支付、排期、合同、客户生命周期、多管理员、RBAC、OAuth、二次验证、自动媒体队列、worker、任意 CMS、公开投稿、由管理员上传脚本/任意 Logo，以及手机端复杂裁切、横竖批量配对和批量原图维护。

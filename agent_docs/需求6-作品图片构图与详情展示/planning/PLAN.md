# 计划：作品图片构图与详情展示

## 执行结论

产品 OQ 已答，采用三段可分别验证的增量：显示设置 → 方形缩略图与媒体基础 → 各展示用途。2026-09-10按用户后续授权完成本地实现与验证，待人工验收；没有镜像或生产部署。

## 执行顺序

### 1. 作品显示设置

扩展作品 Schema、管理读写与 presentation 接口，增加来源和两个开关；使用前向迁移的默认值保留历史效果。在现有作品编辑页提供实际来源预览与文案，不解除媒体只读锁。

公开 repository 只在详情投影筛选附加图；领养两处选图使用同一个来源偏好。调整详情初始选图到最终可见图片。保存/移除/发布三个入口均验证非空图库、指定来源和活动发布冲突；显示设置不改变领养排序时间。

该增量仍使用现有图片，完整源图和自由裁切随后续增量接通，不能提前声称已实现完整封面显示。

### 2. 按用途模型与 1:1 缩略图

建立 models 中的有限用途表、模式版本与旧调用兼容。先补齐关联保存，避免删除重插把构图一起清除。同步数据库、管理 Schema 和严格公开 DTO。

按models的默认表生成居中选区或完整显示；旧作品首次启用时把未被本次编辑覆盖的出厂照卡片实际可见范围初始化为显式选区，仅继承一次旧crop/gravity，不持续绑定旧焦点。

后台按需加载官方 Cropper.js，薄组件只处理图片加载、选区坐标映射、用途比例、预览、应用/取消与键盘可达性；不再引入第三方 Vue 包装库。复用认证同源预览；坐标以原图几何归一化，前后端共用像素取整约定。关闭本轮未支持的旋转/翻转/倾斜。

媒体链路增加独立 1:1 输出，详情大图和缩略图分离；先用该垂直流程证明框头部、保存还原和发布可靠，再扩展其他用途。修正 WorkDetailGallery 的移动 min-height 冲突，保持至少 44px 点击目标。

### 3. 作品卡与领养构图

目录按 4:5、代表作品按 3:4 生成，完整模式用 contain。两类领养位置各有自由选区，默认完整显示，不为 PC/手机增加规格。

横版封面完整详情从源图派生；不能复用旧16:9结果。更新五个公开组件、首页聚合及后台用途预览；公开读写采用明确 fit。保留实际封面角色及既有主图/代表作品资格。

两个候选领养素材均具备对应默认或已保存构图的合格输出后，才能支持在线切换来源；不要只生成当时选中的素材，导致另一个选项无法生效。相同完整构图可以复用输出，不重复处理。

### 4. 发布与存量兼容

扩展 publicationTargets、所需变体数、缺失判断、生成、验证、公开取图及关联清理调用方；检索所有 workAssetPublicUsages / buildPublicMediaProcess / sourceSupportsPublicUsages 调用，兼顾运维读取而不启动运维操作。

旧配方保持语义；新配方验证精确用途与选区身份的整套图片。保留 lease、版本 CAS、不可变 Key、重试、失败清理，不新建队列服务。逐件 opt-in 规则见 models。

特别检查 minimumDimensionsForUsages：旧算法只找第一个 cardUsage，新模式必须按各用途真实选区分别计算所需几何，不能用一套 crop 代表所有输出。全图放大不应被极小选区推到无限尺寸；遵守既有像素、字节及 OSS 输入上限，并在保存/预检给出可执行反馈。

### 5. 验证与交接

优先扩展现有 work-management、media-recipe、work-publication、public-site-contracts 集成测试和已有浏览器设施，不新建测试框架。

| 层次 | 必要验证 |
| --- | --- |
| 几何 | 合成边缘标记图，方形/4:5/3:4/自由选区，靠边主体，保存还原与 EXIF 方向一致 |
| 数据/并发 | 空图库、指定缺图、版本冲突、活动发布、关联重排、字段省略/重置、历史升级 |
| 媒体 | 完整详情不裁，独立 thumbnail，重复生成幂等，新旧集合不混用，失败不提前发布 |
| UI | 390×844、430×932、768×1024、1023×900、1024×900、1440×900；键盘/焦点、触控、hover、reduced-motion/transparency/contrast |
| 页面健康 | console/network、decode、LCP/CLS、safe area、无水平溢出、SSR 默认可见 |
| 回归 | Hero 四集合、私有委托附件、无水印、封面素材角色、原发布资格与排序 |
| 跨平台/实际服务 | Windows/Ubuntu 迁移和图像处理；真实 OSS 精确选区与输出头信息，不代签生产部署 |

文档-only 不跑全量代码检查；代码实施后运行 lint、typecheck、受影响 core，本需求触及运行时媒体代码还需 build。真实浏览器、手机与用户验收分别登记。Release/manual 和生产操作不从本计划自动获得授权。

## 技术决策

- 官方 Cropper.js 2.2.0：复用选区交互，已锁定并同步Linux许可证与notices；[官方 API](https://fengyuanchen.github.io/cropperjs/v2/api/)、[选区文档](https://fengyuanchen.github.io/cropperjs/v2/api/cropper-selection.html)。已按后台路由按需加载并通过浏览器保存/还原验证。
- 构图为原图上的非破坏性矩形；固定比例按像素校验。前端预览与服务端共用几何取整，避免九宫格焦点分支再次改变人工选区。
- 缩略图工程默认宽度 96/192/288，覆盖现有最大 88px 控件的三倍密度；卡片优先复用既有 480/768/1200 档位，其他完整输出复用现有档位。变更档位需同步配方、验证和读取，不要求用户决策技术参数。
- 清晰度以选区原始有效像素提示，不宣称放大恢复细节；保留低分辨率素材既有受限适配能力。合法选区与资源上限是硬约束，清晰度提示不新增全站原图分辨率门槛。
- 无需将所有用途图片装入每个公开 DTO，也不必重构图库为新的通用媒体 CMS。现有五张出厂照数组与附加字段可继续沿用。
- 不增加后台列表/上传队列专属用途、不更改 Hero 配方；共享函数变化必须有隔离回归。

## 已确认结论

- 发件地址与两位默认收件人区分明确，真实授权码未写入文档。

## 主要风险

- 公开投影共用管理内容加载 → 显式映射内部字段边界，补公开 DTO 回归。
- 20 MB 源图编码后邮件更大，SMTP 限制尚未验证 → 实施阶段用上限图联调；失败不能静默省略附件或降低用户上传限制。
- SMTP 部分拒收与确认后中断 → 逐收件状态、有限重试与稳定委托编号，不承诺严格恰好一次或收件箱到达。
- 委托删除/移除邮箱与发送竞争 → 未进入网络发送的通知取消，已领取项在发送前复核；已进入网络发送的邮件不能保证撤回，邮箱副本由工作室处理。
- `.env` 文本已写但容器未注入 → 实测 runtime/Compose 配置，避免输出含秘密的完整配置。

## 实现核对

- 公开提交只返回原 receiptCode；SMTP 副作用在事务外，事务内创建逐收件通知，拒绝/回滚不会发邮件。
- 收件列表只进入管理 DTO，公开投影显式保留原字段；旧 contact 请求省略新字段时保留已有列表，空数组则确实清空。
- TLS/端口/发件身份校验隔离，错误只使用稳定类别；真实授权码未进入变更文件与构建产物。
- 唯一通知身份、租约 token、续租、传输前复核、删除屏障和状态 CAS 均核对；已完成行不能经普通重试再次发送。
- 发现旧库只读列表因新增表缺失失败，已修复兼容并复跑通过；未删除或弱化原有滚动读取测试。
- 发现非池 SMTP transport.close 不保证中止活动 socket，已移除假取消，使用网络超时与续租等待实际结果。
- 首次 core 并发及一次浏览器冷编译出现超时；串行复跑与最终浏览器证据记录真实结果，不将超时视为业务回归。
- SMTP 自发自收只采用用户授权目标，两封邮件均获用户确认；默认其它接收者、真实手机及生产状态留待对应验收。

## 2. 前端架构

- `app/composables/useAdminAuth.ts`：唯一认证状态来源。只在内存保存管理员公开字段（`id`/`username`/`version`）、CSRF token 和 session 状态（`unknown/loading/ready/guest/error`）；不写 localStorage、sessionStorage、IndexedDB 或 URL。所有请求显式 `credentials: 'same-origin'`。401 清空内存并置 `guest`；403/409/500/网络错误置 `error`（未确认时）或保持 `ready`（已确认后的后台重检），不误判为未登录。模块级 in-flight Promise 去重并发 session 检查；已知 `ready`/`guest` 结论时不重复发请求（否则「401→guest→重定向→再检查」链路会反复取消导航无法收敛）。
- `app/middleware/admin-auth.global.ts`：登录页先确认 Session，已登录直接回 `safeAdminRedirectTarget`；非登录管理路由不阻塞渲染，触发 revalidate 后交给布局门禁，避免首屏白等。
- `app/layouts/admin.vue`：Session 门禁。loading 显示「正在确认登录状态…」纯文本（不依赖动画）；error 显示持久错误与「重试」；只有 `ready` 才渲染 slot，受保护夹具内容不会先渲染再跳转。
- `app/app.vue`：全局 guest watcher。会话在使用中失效（退出、改密、SessionVersion 变化）时，无论当前页用哪种 layout（含 `layout:false` 的 `/admin` 过渡页），都立即回登录页并带 `redirect` 参数。
- `app/utils/admin-navigation.ts`：回跳目标只接受站内 `/admin/**` 路径，拒绝外部 origin、协议相对地址与登录页自身，防开放重定向。
- 改密 401 歧义（当前密码错误 vs 会话已失效）由客户端额外探测一次 session 区分，不解析错误文案。

## 3. 页面与交互

- `/admin/login`：真实 `POST /api/auth/login`；删除 setTimeout 模拟与「接口尚未接入」文案；字段固定为「用户名」；401 统一显示「用户名或密码不正确。」，不区分账号不存在、密码错误或锁定；删除 `state=locked` 及「15 分钟」文案；403 显示「请求被安全校验拒绝」，500/网络显示「服务暂时不可用」，均为持久 alert 并与字段 `aria-invalid`/`aria-describedby` 程序化关联；提交中禁用表单防重复提交；成功进入 `/admin/works` 或安全回跳目标；`?state=password-changed` 显示改密成功提示；保留 `autocomplete=username/current-password`；无邮件找回入口。
- `AdminShell`：导航为「作品」「账号」（P0 已锁定范围，无 Dashboard、无 P1/P2 入口）；桌面侧栏显示当前用户名（窄屏隐藏以杜绝横向溢出，用户名以 `/admin/account` 为准）；真实退出按钮调用 `POST /api/auth/logout`（浏览器同源自动携带 Origin，内存 CSRF 经 `x-csrf-token` 发送）；成功清空内存并回登录页；失败显示持久 alert，退出中禁用按钮。
- `/admin/account`：显示当前管理员用户名；修改密码表单（当前密码/新密码/确认新密码，`autocomplete=current-password/new-password`）；客户端校验（必填、≥12 字符、两次一致）并在校验失败时聚焦首个错误字段；以内存中的 `version` 作为 `expectedVersion` 调用 `PUT /api/admin/account/password`；401（当前密码错误）显示字段级错误且不清除会话；409 显示持久冲突面板与「刷新登录状态」动作；成功后服务端清除 Session，前端同步清空内存并进入带提示的登录页；未实现邮件找回、第二管理员或账号列表。

## 4. 真实浏览器验证（Playwright + 真实 Chrome，`channel: 'chrome'`）

E2E 夹具：`playwright.config.ts` 的测试库改为固定临时路径（端口 3100 已保证互斥，且 globalSetup 在 webServer 之后运行，复用旧服务器时仍落到同一库）；`tests/e2e/setup/global-setup.ts` 迁移并初始化固定凭据管理员；`tests/e2e/helpers/` 提供登录、会话读取与管理员重置（锁定/改密用例收尾必调，避免污染同库其他用例）。全部使用真实浏览器 Cookie jar，没有手动复制 `Set-Cookie`。

`tests/e2e/admin-auth.spec.ts` 22 项：

- Cookie 契约：真实 jar 接受 `__Host-fur-forge-session`；原始 `Set-Cookie` 含 Secure、HttpOnly、SameSite=Strict、Path=/ 且无 Domain；jar 属性复核一致；`document.cookie` 读不到；登录成功与 401 响应均带 `no-store`、`noindex`、`Vary: Cookie`；认证状态不进入 localStorage/sessionStorage/IndexedDB/URL。
- 登录与恢复：UI 登录成功进作品区且壳层显示用户名；提交期间重复点击只产生一次请求；刷新后 session 恢复；已登录访问登录页回作品区；未认证访问 `/admin/account` 先落登录页、登录后回到账号页；`redirect=https://evil.example/` 被回退到 `/admin/works`。
- 未认证保护：直接访问 `/admin/works`、`/admin`、`/admin/account` 只显示登录页，夹具内容（如「蓝莓」）与壳层不渲染；session 接口瞬时 500 显示持久错误与重试，不回落登录页、不渲染内容，恢复后重试成功。
- 统一提示与锁定：错误密码与不存在账号的提示逐字相同；连续 5 次失败后即使用正确密码登录，页面仍只显示统一提示，无「锁定/分钟」字样（收尾重置管理员解锁）。
- CSRF/Origin：退出与改密在缺失/错误 token 下均 403 且会话不受影响，正确 token 成功；错误 Origin 的登录 403。
- 退出与改密：退出后 session 401，原页面回登录页且内容不再可用；客户端校验拦截过短密码与不一致确认；当前密码错误显示字段错误且会话保留；改密成功进入带提示登录页，旧 Session 401，旧密码登录 401，新密码可登录；过期 `expectedVersion` 被真实服务端拒绝 409 且会话保留。
- 公开 Host 隔离：`127.0.0.1` 公开 Host 的 `/api/auth/session`、`/api/auth/login`、`/admin/works` 全部 404。

说明：T13 把资源版本与 `session_version` 绑定递增，活动 Session 在实际使用中不可能遇到 409（版本变化即会话失效）。界面的冲突面板与刷新恢复链路因此通过拦截一次 409 响应验证；真实服务端 409 用过期 `expectedVersion` 在 API 层验证。

既有 `admin.spec.ts`、`t08-selfcheck.spec.ts`、`t09-ui.spec.ts` 已适配真实认证（管理页先登录、登录页断言更新、导航新增「账号」）；`access-surfaces.spec.ts` 零修改通过。

# 居中可配置品牌水印地基增量（2026-08-01）

> **角色**：这是 `foundation/README.md` 在品牌水印范围内的当前增量地基。仅当既有文件中的水印位置、尺寸、来源管理或执行顺序与本文件冲突时，以本文件为准；其他产品边界不变。
> **来源**：景宸在 T14–T18 收口后明确要求，将现有小型角落水印调整为大尺寸居中水印，并允许在管理端选择后续使用的 Logo 水印源。

## 不可绕过的产品决定

- P0 公开衍生图继续强制烘焙品牌水印，私有永久原图和私有预处理源继续保持无水印且不可覆盖。
- 标准作品水印继续使用不可变 profile `brand-centered-v2`：默认透明度为 50%，管理端保留受限缩放参数；`recipe-v2` 将实际图形边长统一调整为上一版的 1.6 倍。设定图按角色固定为左右两枚不重叠的等大水印，其他 P0 图片保持单枚居中；不恢复逐图四角控件。
- 当前 `brand-standard-v1` 的 18% 宽度、70% 不透明度和四角锚点只作为历史已生成 variant 的身份保留，不再作为后续发布目标，也不回写覆盖旧对象。
- 水印源属于站点级品牌资产，不属于单件作品。景宸可以在管理端上传受限 PNG Logo、从已验证候选中选择一项并预览；浏览器始终只使用 `assetId`，不得填写或接收文件系统路径、OSS Object Key、Bucket 名或签名 URL。
- 当前仓库随附 Logo 只作为初始候选源导入，不再由服务端硬编码本地文件路径作为唯一水印来源。后续更换 Logo 不需要重新构建镜像。
- 水印源必须保存在与待处理原图相同的私有 Bucket 内，由服务端核验后参与 OSS 图片处理；水印和最终格式仍由 OSS 完成，不能退回 CSS 叠层或第二套生产像素处理链。
- Logo 摘要、profile ID/版本、透明度、缩放比例、配方版本和角色化布局必须进入 variant identity。任一项变化都生成新 Key，不得原位覆盖。
- 修改水印配置必须采用“草稿预览 → 生成并验证完整新 variant 集合 → 原子切换活动 profile → 精确清理旧公开对象”的顺序。失败时继续使用上一活动 profile，不允许同一公开版本混用两套水印。
- 水印不构成访问控制；私有素材安全仍由私有 Bucket、认证、服务端同源代理和最小权限保证。签名 PUT 只用于当前上传动作，签名 GET 不进入浏览器 DTO/DOM。

## 阶段门禁

- 保留 T14–T18 的历史完成状态；新需求不是对既有验收的追溯否定。
- 在 T19 开始前新增 `GATE-07 · 可配置居中水印迁移`。该门禁必须完成数据迁移、受限管理 API、真实 OSS 预览、活动 profile 切换、既有已发布作品再生成、管理端配置界面和回归证据。
- T19/T20 公开页面只能消费当前活动 profile 的 `PUBLIC + READY` variant；旧 `brand-standard-v1` variant 不能继续满足新的发布检查。
- T51 继续负责正式 Logo 使用范围和跨素材视觉校准，但不再决定“是否居中、是否支持后台换 Logo”这两个已经确认的产品事实。

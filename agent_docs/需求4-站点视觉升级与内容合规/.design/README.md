# 需求4 · 公开站设计与动效说明

> **角色**：把“Apple 式简洁优雅 + 国内兽装站完整业务地图”转成可实现、可验收、可维护的视觉契约。
> **状态**：方向已锁定；实现前先做页面骨架/真实素材原型，再进入组件代码。
> **参考原则**：参考 Apple、渔屋、万物通行和 Apple Design Skill，但不复制任何品牌资产或完整页面。

## 1. 设计定义

DITE DOG 的公开站定位为：

> 以作品摄影为主角的影像编辑型工作室站。首页完整呈现作品、委托和领养，但每一屏只建立一个主要注意力中心；文字负责命名和行动，动效负责把注意力交给下一幕。

不是：

- 电商商品宫格；
- 通用 CMS 卡片集合；
- 每个区块都套灰底/描边/大圆角；
- 用大量动画模拟“高级感”；
- 复制 Apple 产品页或其它兽装工作室海报。

## 2. 设计系统

### 2.1 色彩

- 主背景：白与极浅中性色。
- 主文字：接近黑的中性色，不使用纯黑铺满大段。
- 品牌蓝继续作为链接、焦点和少量状态强调，常态面积保持克制。
- 大图上的文字使用局部、确定性的对比保护；不默认给整张图覆盖重黑蒙层。
- available 使用绿色并带文字；adopted 使用中性非绿色并带文字。

### 2.2 字体

- `ZhuoHei Collage`：仅品牌名、slogan 和少量大展示文字；不承担正文、表单、长标题和法务文本。
- 展示标题：中文宋体/展示字体，按字号设置 tracking 和 leading，不统一套一个负字距。
- 正文与 UI：系统中文无衬线。
- 大标题行高更紧，正文行高更松；所有空间使用 rem/em，放大文字后布局不溢出。
- 法务文档保持易读宽度，不用装饰字体和全大写英文压迫阅读。

### 2.3 圆角与容器

- 图片圆角可继续使用统一 token，但大幅章节不必被“卡片外壳”包住。
- 主要章节通过留白、面积、对齐和图片本身分层；边框只用于真实控件/边界。
- 胶囊只用于行动、筛选或状态，不把每个导航和文字链接都做成浮起胶囊。
- 不叠加多层半透明玻璃；Header/浮层使用材料时只保留一层。

### 2.4 行动层级

统一三类：

- `primary`：每幕最多一个主要行动；
- `secondary`：边框或低强调的辅助行动；
- `text`：普通文字 + 箭头/图标。

按钮按下立即缩放/变色，反馈 100–160ms。Hover 不超过 2px 位移，不使用大阴影和弹跳。

## 3. 首页四幕

### 3.1 第一幕：品牌 Hero

目标：第一眼只看到作品图与 DITE DOG 品牌。

桌面：

```text
┌────────────────────────────────────────────────────────────┐
│ Header（图片覆盖态）                                       │
│                                                            │
│                       全屏摄影                              │
│                                                            │
│                 有点小狗工作室                             │
│ DITE DOG                     不只做小狗毛 | 只做海绵头      │
│                                   轻量页码/暂停/方向控件    │
└────────────────────────────────────────────────────────────┘
```

- 延续需求3的桌面/移动不同排版。
- 图片始终先可见；品牌文字和控制器按层级进入。
- 桌面常态控制器弱化：页码/进度可见，方向箭头在 hover、focus 或边缘意图时增强；键盘和触屏始终有替代。
- 移动端不靠 hover，保留明确的分页和暂停；控件不压住 slogan/safe area。
- 自动轮播仍为 10 秒，页面隐藏和 reduced-motion 停止。
- 图片切换保留轻微方向感，缩放不超过约 1.01；避免大幅背景持续移动。
- 九宫格焦点仅在后台设置，公开端自然消费生成结果。

### 3.2 第二幕：代表作品

目标：让一件真正有冲击力的作品接住 Hero，而不是立即进入小卡轨道。

结构：

1. `featured` 顺序第一项作为 lead work；
2. 一张接近内容宽度/视口高度的大图；
3. “名称 · 物种”与一个文字行动；
4. 剩余精选进入次级轨道或简化网格。

桌面建议：

```text
章节标题/短引导
┌──────────────────────────────────────────────────────┐
│                                                      │
│                    代表作品大图                      │
│                                                      │
└──────────────────────────────────────────────────────┘
名称 · 物种                                  查看作品 →
[剩余精选：等高次级轨道]
```

约束：

- Lead 不要求新增文案字段；使用现有精选排序、名称、物种和卡图/详情图。
- Lead 高度建议 70–90svh，但不 pinned，不劫持滚轮。
- 横竖素材按自身比例和安全最大高度处理；不把竖图粗暴裁成横幅。
- 移动端 lead 为全宽自然比例，剩余精选可最多展示 1–2 项并提供“查看全部作品”；主要任务不依赖横向滑完。
- 无精选时整幕隐藏，不用占位示例图。

### 3.3 第三幕：自设委托

目标：把“业务入口卡”升级为完整章节。

桌面：

```text
┌───────────────────────────────┬──────────────────────┐
│                               │ 自设委托             │
│        委托代表大图           │ 一句真实说明         │
│        65%–75%                │ 当前营业状态         │
│                               │ [提交委托申请]       │
│                               │ 了解制作范围 →       │
└───────────────────────────────┴──────────────────────┘
```

- 移除当前 21:9 描边卡片外壳。
- 复用委托 Hero 横版源及现有 `home-entry-commission` 公开变体，不要求景宸另做海报。
- 图片和文案可以左右交替，但一个版本内保持稳定。
- 主行动只有“提交委托申请”；“了解制作范围”是文字行动。
- 营业状态必须有文字，不只用颜色。
- 移动端图片在上、文字在下，主按钮全宽或自然宽；不将图片与按钮并排挤压。

### 3.4 第四幕：设定领养

目标：作为首页收尾制造新的影像节奏，同时把可领养内容带到目录。

桌面：

- 两项可用时：第一项占较大面积，第二项占较小面积或并排同高；不做商品促销墙。
- 一项可用时：单幅完整展示。
- 零项可用时：整幕隐藏，首页自然进入 Footer。
- 卡图按当前 cover → design sheet 回落规则。
- 图片下只保留“名称 · 物种”、状态、可选价格与“查看全部设定”。
- adopted 不进入此幕；仍可进入代表/精选作品。

移动端：

- 按顺序纵向堆叠，最多突出两项；
- 不在图上叠加多个徽章/按钮；
- 状态和价格在图下保持清楚层级。

## 4. 内页连续性

### 4.1 Works

- `/works` 继续是完整目录，不强行改为故事页。
- 等高铺满混排规则保留；视觉升级集中在标题、留白、hover 和首图进入。
- 卡片点击时选中媒体可以渐进增强为详情主图 shared transition。
- 详情继续只显示名称、物种和单一图集，不恢复事实表、related 或前后导航。

### 4.2 Commission

- 首页委托幕与 `/commission` 使用同一视觉源和相近裁切。
- 进入后不应再次先显示一套无关封面；大图、状态和主行动位置形成连续关系。
- 正文保持制作范围 + 估价/联系两栏；文案按 `requirements/COPY.md` 更新。
- QQ 是后续主沟通，邮箱降为备用。

### 4.3 Adoptions

- 首页领养图片、`/adoptions` 卡图和详情查看序列使用同一媒体身份。
- 共享过渡只作为增强，不能改变按来路返回逻辑。
- 搜索和“联系我们申请领养”操作带保持功能性，不使用复杂进入动画。

## 5. 导航与 Footer

### 5.1 Header

- 首页覆盖态可使用一层 `backdrop-filter` 或半透明背景，在实际图片上验证对比。
- 内页 sticky Header 保持稳定；可用轻量滚动边缘/阴影，不堆厚边框。
- 当前导航项通过字重、颜色或极浅底稳定识别。
- hover/focus 反馈克制：不再让每一项都明显上浮并投射大阴影。
- 下拉仍从触发项的空间原点出现，进出路径对称。
- reduced-transparency 时回退到高不透明实底。

### 5.2 Footer

- 保留品牌、备案、法务链接和设计署名。
- 视觉上降低导航重复感，让首页第四幕到 Footer 的留白自然收尾。
- 不新增社交平台图标或退役渠道。

## 6. 动效语言

### 6.1 Token

建议统一：

```css
--motion-feedback: 140ms;
--motion-content: 420ms;
--motion-media: 720ms;
--motion-page-in: 280ms;
--motion-page-out: 160ms;
--motion-distance: 0.75rem;
--motion-ease-standard: cubic-bezier(0.22, 1, 0.36, 1);
--motion-ease-exit: cubic-bezier(0.4, 0, 1, 1);
```

精确数值以真实浏览器视觉评审为准，但组件不得重新发明独立 620/680/750ms 常量。

### 6.2 即时响应

- `:active`/pointer down 立即显示按压反馈。
- 提交/上传操作开始后立即锁定重复提交并显示真实阶段。
- 不加人为延迟，不为展示动画推迟导航或 API。
- 长操作仍使用进度、终态和可恢复错误，不用无限 spinner。

### 6.3 区块进入

- 只在首次入屏执行一次。
- 标题先于媒体 caption，图片本身不必全部从 opacity 0。
- 位移 8–12px，错峰 60–100ms。
- IntersectionObserver 成功挂载前内容保持可见。
- 移动端减少错峰数量，避免用户快速滚动时连续闪动。

### 6.4 媒体切换

- 同一序列可以横向 2%–3% + crossfade；大图移动期间可轻微降低不透明度。
- 主图/缩略图切换继续从当前状态 retarget，不等待上一段 keyframe 完成。
- 没有连续拖拽时不模拟 momentum、rubber-band 或 bounce。
- 未来若实现 1:1 swipe，才引入 Pointer Events、捕获、速度历史、投影和可中断 spring，并单独立项。

### 6.5 页面与共享对象

- Header/Footer 稳定，主内容继续使用 Nuxt `pageTransition`。
- View Transitions API 只用于同一媒体从列表/首页到详情的渐进增强。
- 共享名称在同一时刻唯一，避免多个同图卡片争抢。
- 路由失败、后退、锚点或 reduced-motion 时回退普通淡化。

## 7. 焦点 UI

后台卡片示意：

```text
目标裁切预览（16:9 或 9:16）
┌────────────────────────────┐
│             ●              │
│                            │
│                            │
└────────────────────────────┘

焦点位置
[↖] [↑] [↗]
[←] [·] [→]
[↙] [↓] [↘]

说明：默认居中；只有主体被裁掉时才调整。
```

要求：

- 仅未启用项可编辑。
- 横/竖分别预览。
- 选择后焦点标记立即移动，预览用与生产相同的 cover 逻辑。
- 保存使用集合级 expectedVersion/CAS。
- 不显示原始小数坐标，不要求景宸理解裁切算法。
- 不提供自由拖拽框、缩放滑杆、断点列表或 AI 主体识别。
- 若当前值不是九宫格点，显示最近预设并提示“历史自定义焦点”，保存后才吸附。

## 8. 移动端与触控

- 触控目标至少 44×44 CSS px。
- 点击反馈在 touch down，允许拖离取消原生点击。
- 不用 `hover` 暗示唯一功能。
- Hero 手势与浏览器垂直滚动不冲突；`touch-action: pan-y`。
- 输入、选择图片、勾选声明和提交在 390/430 宽度不横向滚动。
- 键盘弹出后，当前字段错误和提交状态能滚入视口。
- 图片不一次性全部 eager；方向切换不重复下载无关大图。

## 9. 无障碍与性能

- 颜色不是状态唯一载体。
- 对比度在每张真实 Hero 图上验证；不能只用测试渐变图。
- alt 描述角色/画面，不重复“图片”“照片”。
- 大标题放大 200% 后不截断；法务文档保持可阅读行长。
- 动画只改 `transform`/`opacity`；全屏 blur、filter 和 box-shadow 动画禁止。
- 无空闲持续 rAF；滚动观察使用 IntersectionObserver。
- LCP Hero 第一帧继续 eager/high priority；其它大图 lazy。
- 保留图片 width/height/aspect placeholder，CLS < 0.1。
- 导航、表单、轮播、图集和确认项完整键盘可达。

## 10. 视觉验收方法

每个阶段使用真实或接近真实的兽装素材，不用纯色 fixture 代替最终判断。

至少截图/录像：

- 1440×900：首页四幕首尾、Header、hover/focus、页面连续性；
- 1024×900：断点切换；
- 768×1024：平板重排；
- 430×932、390×844：移动 Hero、四幕、申请确认、输入法；
- reduced-motion：Hero 静态、区块静态、共享过渡回退；
- 高对比/减少透明度（浏览器支持时）；
- 九宫格九个预设中至少四角、中心的真实裁切；
- 低速设备/网络下的占位、解码、LCP 和白闪检查。

用户验收必须由王旻安和景宸确认图片、裁切、层级、动效节奏和文案；自动截图不能代签审美判断。

# 规格说明：兽装工作室主页

> **状态**：2026-07-31 首页媒体、图片角色与品牌衍生契约修订版。旧版 118 项 OQ 的讨论历史保留在 Git 历史中；OQ-119 已由用户回答，当前无开放 OQ。
> **边界**：本文件定义“做什么、验收什么”，技术实现由 `planning/PLAN.md` 决定。

## 1. 产品目标

1. 为“有点小狗工作室”建立以真实作品为核心的公开展示网站，让首次访问者迅速理解制作风格和完成能力。
2. 让访客能够连续浏览作品、了解自设委托与角色领养的真实营业状态，并通过邮件、QQ 或抖音继续沟通。
3. 为每件作品建立稳定、可分享、可索引的 `/works/{slug}` 档案。
4. 提供与公开站隔离的唯一管理员后台，使景宸可以维护作品、图片、首页轮播、状态与必要站点内容。
5. 在不建设站内交易、委托表单或客户管理系统的前提下，形成可靠的内容发布、品牌水印和原图保管链路。

## 2. 品牌与视觉结果

- 正式中文名：“有点小狗工作室”。
- 英文暂用 `dite dog`，后续允许从统一站点设置整体替换。
- 首版面向中国大陆，以简体中文为默认语言。
- 业务邮箱为 `3114559925@qq.com`，官方 QQ 为 `3114559925`，抖音为 `to3114559925`；例图中的个人 QQ 二维码一期不使用。
- `agent_docs/materials` 已提供当前工作室 Logo 源图。完整组合标用于页头；从同一源图受控导出的图形标用于 favicon、Apple Touch Icon、水印和必要的社交分享品牌标。不得继续把 Logo 记为“尚未交付”，也不得把其他例图中的非正式狗头闪电替代为品牌源。
- 网站整体应是图片大底/白底的编辑型摄影作品集；Logo、文字和符号只为作品展示服务。
- 首页首屏由 1–5 项获授权代表作品轮播占据首个主要视口，不使用文字与图片等权的左右分栏。
- 明显蓝色面积常态 5%–10%，单页不得超过约 15%；不得出现连续蓝底区块、蓝色卡片墙或大面积渐变营销面板。

## 3. 公开页面与 URL

固定一级页面：

- 首页 `/`；
- 作品展示 `/works`；
- 作品详情 `/works/{slug}`；
- 自设委托 `/commission`；
- 角色领养 `/adoptions`；
- 返图墙 `/returns`；
- 关于我们与基本约定 `/about`；
- 联系 `/contact`。

兼容规则：

- `/adoptions/{slug}` 永久 301 到 `/works/{slug}`；
- `/terms` 永久 301 到 `/about#terms`；
- 首次发布后 slug 默认冻结；显式纠错时保存旧 slug 并永久 301；
- 后台、预览、API 与开发媒体路由不进入公开导航或 Sitemap。

## 4. 公开内容与行动

### 4.1 首页

首页首屏包含站点级代表作品轮播、工作室名称/Logo、最多一句短口号、一个进入作品展示的主要行动和向下提示。首屏之后优先展示 3–6 件精选作品，再展示自设委托与角色领养入口，之后才是营业状态和辅助信息。

首页轮播契约：

- 至少 1 项、最多 5 项，按管理员顺序展示；禁用项不进入公开投影。
- 每项必须同时配置横版与竖版两份独立原图。横版用于横屏桌面/平板，竖版用于竖屏手机；两者可以表达同一作品的不同构图，但不得用同一文件只改焦点冒充双源。
- 每项包含非空 alt、排序和启用状态，可选关联一件已发布作品；工作室身份、口号和主行动仍是站点级内容，不复制进每张图片。
- SSR 必须输出可用的第一项和 `<picture>/<source>` 选择信息；关闭 JavaScript 时第一项仍可浏览，浏览器不得同时下载隐藏的横版与竖版全尺寸图片。
- 必须提供上一张/下一张、分页指示、触控滑动和键盘操作。自动轮播默认关闭；开启时切换间隔不得短于 6 秒，提供可见暂停控制，在 Hover/焦点进入时暂停，并在 `prefers-reduced-motion` 下停用。

精选区域最终采用 T08 已确认的横向轨道，不自动播放；首页首屏轮播与精选轨道是两个不同组件和内容对象。

### 4.2 作品展示与详情

- 作品列表按人工顺序显示，并提供“作品用途 × 装型”的交集筛选和结果数；一期不提供全文搜索。
- `/works` 的主视觉优先使用出厂照 `studio_photo` 的 3:4 卡片衍生图。尚无出厂照的领养作品可以使用“完整设定图置入 3:4 安全画布”的明确 fallback，不得把横版设定图直接裁掉大部分内容。
- 作品详情至少显示角色名、物种、装型、非空的角色主人展示值、适用业务状态、展会、作品短属性和价格。工作室作品显示“有点小狗工作室”，隐私作品显示“不公开”。
- 领养作品详情把“设定图”和“出厂照/作品图集”分为两个有标题的媒体区；设定图保持横版完整画布，出厂照按原比例浏览。普通展示/委托作品只显示适用的出厂照图集。
- 每件作品可保存 0–8 条有序短属性；单条去首尾空白后 1–24 个字符，同件作品内不得重复。
- 价格仅在领养/掉落作品已录入人民币金额时显示，格式如 `¥15,600`；未录入时删除整个价格区域，不显示零价、“请咨询”或空标签。
- 公开页面不得包含联系人、返图授权记录、私有 Object Key、后台备注或交易控件。

### 4.3 自设委托

- 展示代表作品宽图、全装/半装制作范围、委托营业状态、人工估价说明、邮件行动、可复制邮箱、已确认 FAQ 和基本约定入口。半装由头、爪、尾巴组成；一期不宣传其他配件或服务。
- 不提供站内表单、自动报价、统一公开价目、固定排期、付款比例或其他未确认逐单规则。
- 邮件行动必须明确打开邮件客户端或复制邮箱，不模拟站内提交成功。

### 4.4 角色领养

- `/adoptions` 以横版设定图 `design_sheet` 作为每个角色的主图，完整展示正面、侧面、背面、色板等设定信息；不得套用作品墙的竖版出厂照卡片模板。
- 展示领养营业状态、领养方式、业务状态、当前展会、作品短属性和已录入人民币价格。
- 一般领养与展会掉落都进入统一作品详情；不建设第二套详情页。
- 领养作品发布到 `/adoptions` 前必须有 1 份设定图；后续已有出厂照时可在统一详情页追加，不替代设定图角色。
- 网站不接受登记、定金、付款或签约。
- 展会掉落既可以是已完成头部、成交后继续制作，也可以是已完成全装并即买即穿；通过装型、状态与短属性表达，不建设全站制作进度字段。

### 4.5 返图墙

- 每张返图必须关联已有作品；每件作品最多 5 张返图。
- 返图保持原比例并以竖版/照片墙浏览为主，不复用横版设定图布局。
- 可公开显示返图者昵称、日期与主页链接；均为可选。
- 后台可额外保存三个可选私有授权记录：授权来源、确认时间、简短备注。全部为空仍可发布，不形成刻板审批流。
- 当前没有真实返图时，SSR 页面显示经过设计的真实空状态，不使用假图，也不写“功能后续开放”。

### 4.6 关于与联系

- 关于页承载工作室事实、制作范围、官方渠道和基本服务约定；不虚构品牌故事。
- 联系页以 `3114559925@qq.com` 为主要业务行动，并展示确认后的 QQ、抖音和防诈骗提示。
- 基本约定至少覆盖：工作室与制作范围、逐单沟通原则、作品著作权与实体所有权、个人非商业使用、商业用途另行沟通、作品展示与完工前不公开请求、二次转让通知与反炒卖、基本售后、官方联系与防诈骗。
- 服务约定与法律文本在正式上线前由工作室确认和审阅，不复制竞品原文。

## 5. 管理端需求

### 5.1 访问与账号

- 后台使用独立 Host，公开站不显示后台入口。
- 一期只有一个管理员，不提供注册、第二管理员或账号管理列表。
- P0 提供登录、退出、修改密码和受保护命令重置密码；邮件找回属于 P2，不阻塞核心上线。
- 未认证时只显示登录或明确启用的找回页面，不渲染后台内容。

### 5.2 P0 管理能力

- 作品列表、新建、编辑、草稿、预览、发布、下架；
- 基础信息、作品短属性、适用人民币价格、营业状态；
- 按媒体角色分开的“设定图”和“出厂照”上传区、处理状态、主图、必要裁切/焦点、排序和水印预览；
- 首页 `/admin/site/home`：维护 1–5 项轮播，逐项上传横版/竖版图片、填写 alt、排序、启用/停用、可选关联已发布作品；启用前可用当前活动 `brand-centered-v2` 在私有 Bucket 生成横竖两种方向的真实烘焙预览；
- 首页精选、委托/领养营业状态与必要站点内容；
- SQLite 一致性备份和恢复命令/说明。

首页轮播和作品媒体不得混成一个“通用图片上传”列表。管理端必须清楚显示每个媒体角色将出现在哪个公开页面、采用什么比例、是否应用水印，以及缺失哪一份横竖图片会阻断发布。

### 5.3 P1 管理能力

- 返图上传、可选授权记录、排序、轻量水印预览和发布；
- 当前展会及作品关联；
- 完整多图、裁切和水印配置工作流；
- 受限站点文字内容编辑；首页轮播媒体继续由 P0 专用编辑器管理，不并入万能 CMS；
- 30 天回收站、slug 显式改址；
- 手机完成登录、查看、状态切换、文字修改、单图上传和发布。

### 5.4 P2 管理能力

- 邮件找回密码；
- CSV 导出中心；
- 永久原图档案 UI 与批量下载；
- 最小化访问统计；
- CDN 与复杂媒体失败恢复。

P2 页面在实现前不得以空导航或假功能出现。

## 6. 数据模型契约

### 6.1 作品

`works` 是统一聚合；委托、领养和展示作品不拆成不同核心表。字段至少覆盖：

- 稳定 ID、slug、角色名、物种、装型、非空的角色主人公开显示值；
- 可选业务用途、领养方式、业务状态、当前展会；领养方式固定为“常规领养/展会掉落”，业务状态固定为“准备中/可领养/展会出售中/排期中/制作中/已完成交付”；
- 0–8 条有序短属性；
- 可选 `priceAmountMinor` 与固定 `priceCurrency = CNY`；
- 发布状态、人工排序、首页精选；
- 后台私有联系人。

明确禁止保存：

- 禁止保存 `depositNote`、`paymentNote` 或等价定金/付款备注；
- 一期禁用的美元价格字段；
- 通用 EAV、制作进度、订单或支付记录。

### 6.2 图片资产与角色

原图和网页衍生图必须分离。图片角色固定为：

- `design_sheet`：领养作品独有，最多 1 份；横版优先，公开时保持完整画布；
- `studio_photo`：每件作品最多 5 张；作品列表优先生成 3:4 卡片，详情保持原比例；
- `return_photo`：P1，每件作品最多 5 张；保持原比例进入返图墙；
- `home_hero_landscape` / `home_hero_portrait`：站点级轮播配对资产，不计入作品的 5 张出厂照上限。

同一原图不能同时属于设定图、出厂照与返图；横版/竖版首页图必须是两个独立资产。网站不保存视频、制作过程图或独立制作完成度。

- 永久私有原图最大 30,000,000 字节，最长边 12,000；
- 原图 Key 每次上传新建且禁止覆盖；
- 大于 OSS 图片处理 20 MB 上限的合规原图必须保留原件，并生成私有、可追溯的预处理源；预处理源不公开、不加水印，最大 20,000,000 字节、最长边 4,096 px，其身份必须覆盖原图摘要、FFmpeg 版本和预处理参数；
- 私有 `preprocess` variant 直接以同一资产的永久原图为输入；公开 variant 若引用预处理源，必须引用同一资产下 `READY + PRIVATE + preprocess` 的 variant，且源输出 SHA-256 等于下游输入 SHA-256。超过 20,000,000 字节的原图不得绕过该来源关系直接生成公开 variant；
- 数据库存相对 Key、摘要、宽高、媒体角色、EXIF 修正后的焦点/裁切、水印锚点、配方版本和状态，不存环境相关完整 URL；
- 管理端 DTO 使用 `assetId` 等业务标识，不直接向浏览器暴露私有 Object Key；
- 原图下载与后台刷新预览由认证管理员使用 `assetId` 换取短时签名 GET。
- 管理端上传必须在当前操作区持续显示摘要、PUT 进度和服务端校验状态；发布期间按服务端 `missingVariantCount` 显示“已生成 / 总数 / 剩余”原生进度条；出厂照关系保存成功后以服务端响应重建版本与 dirty 基线，不继续误报未保存更改。
- 所有由用户触发的长耗时操作都必须在原操作区域提供持续进度反馈：至少包含当前阶段、可得时的真实已完成/总数、完成或失败结果；可跨请求执行的任务还必须返回可查询的操作标识并支持刷新恢复。总量未知时使用可访问的不定进度，不得让管理员只能通过按钮长期禁用、加载动画或最终 Toast 猜测任务是否仍在运行。

P0 作品删除是 T40 回收站之前的受限永久删除：只允许删除未发布作品；先清理该作品已生成的公开衍生对象，再删除作品关系和作品记录；永久私有原图资产继续保留。已发布作品必须先下架，界面在确认前明确说明不可撤销范围。

### 6.3 首页轮播

`site_hero_slides` 至少覆盖：稳定 ID、版本、横版 `assetId`、竖版 `assetId`、非空 alt、人工顺序、启用状态、可选已发布作品关联，以及站点级自动轮播开关。数据库不得保存完整媒体 URL。

启用项必须同时具备两份已校验 READY 资产，并且每个方向都具备 `recipe-v1` 规定宽度的 `PUBLIC + READY` WebP 与 fallback variant；variant 的 usage、当前活动 `brand-centered-v2` profile、配置与 Logo 摘要、居中参数、输出摘要和字节数必须完整。至少保留 1 个启用项，最多 5 个。删除或下架关联作品不得静默删除轮播图，应把关联置空或阻止操作并给出明确影响。

停用轮播项的真实水印预览使用当前活动 profile 和同一 `recipe-v1` 像素配方，只生成横版 768 px、竖版 480 px 的私有 WebP 代表图并返回 5 分钟签名 URL；预览不得启用轮播项、不得生成或暴露公开 variant，也不得通过放宽管理 Host 边界访问公开投影。

### 6.4 返图授权记录

返图记录可包含：

- `consentSource`: `qq | email | other | null`；
- `consentConfirmedAt`: 时间或 `null`；
- `consentNote`: 简短文本或 `null`。

这些字段仅作圈内轻量备忘，不是合同系统，不进入公开投影，不作为发布必填项。

### 6.5 公开投影

公开投影只返回已发布内容和公开衍生图，类型上排除：

- 联系人；
- 返图授权记录；
- 私有 Object Key；
- 密码、Session、找回令牌；
- 审计、内部错误和运维字段。

首页投影只包含启用轮播项的公开横竖 variant、alt、顺序和安全的可选作品链接；不得返回私有原图、草稿 URL 或管理状态。

T19/T20 的服务端公开读取契约固定为：按 slug 读取已发布作品详情；按人工顺序读取已发布作品列表、用途与装型交集筛选、精选列表；首页读取启用轮播、站点口号和自动轮播设置。所有公开媒体只选择当前活动 `brand-centered-v2` profile 的完整内容寻址 URL；非法筛选返回安全空结果，草稿与已下架作品按不存在处理。公开 SSR/API 每次请求读取当前 SQLite，不启用共享 HTML 或数据结果缓存。

### 6.6 OQ-119 · `ownerDisplay` 空值语义（已答）

用户于 2026-07-30 确认：

- `ownerDisplay` 始终为去首尾空白后非空的公开显示值；
- 工作室作品填写并显示“有点小狗工作室”；
- 不公开角色主人时填写并显示“不公开”；
- 一期不增加 `ownerType`，也不以空值承载工作室作品语义。

因此管理端必须把 `ownerDisplay` 作为必填项，并删除“留空表示工作室作品”的提示。T12 建模时保留非空约束，不新增 `owner_type` 列；不得为漏填值提供会把作品静默归类为工作室作品的默认值。

## 7. 媒体结果契约

- 私有 Bucket：`project-furry-forge-private`；公开 Bucket：`project-furry-forge-public`。
- 浏览器只向私有 Bucket 上传；公开 Bucket 只含已发布网页衍生图。
- 发布时由 OSS 图片处理从私有原图或其私有预处理源生成确定性结果并 `sys/saveas` 到公开 Bucket；首次冷生成发生短暂 OSS 失败时，同一发布请求只补偿重试一次，第二次仍失败才进入失败与精确清理；不通过 Object ACL 切换公开性。
- 草稿预览使用私有衍生图和短时签名 GET；公开页面永不读取原图。
- 随应用安装的固定版本 FFmpeg 只为超过 OSS 20 MB 输入上限的原图生成私有预处理源；OSS 是公开 variant、最终格式和水印的唯一配方权威，`@nuxt/image` 不进行第二次动态转换。
- `recipe-v1`：
  - 3:4 作品卡：480 / 768 / 1200；
  - 16:9 首页横版：768 / 1280 / 1920；
  - 9:16 首页竖版：480 / 768 / 1080；
  - 横版设定图完整画布：960 / 1600 / 2400；
  - 原比例详情/返图：960 / 1600 / 2400；
  - WebP + 一种源兼容 fallback。
- 只生成实际页面使用的比例和宽度，不做组合爆炸。
- 私有原图永不加水印。`home_hero_*`、`design_sheet`、`studio_photo` 的公开衍生图必须烘焙版本化品牌水印；`return_photo` 在 P1 使用更轻的独立 profile。水印不能只靠 CSS 叠层，因为公开图片被直接访问时也应保留品牌标识。
- 水印 profile 至少包含 Logo 摘要、版本、比例、透明度、边距和四角锚点；默认左上，管理员可按资产选择安全角。T51 正式校准前，`brand-standard-v1` 水印图按最终输出宽度的 18% 显式缩放，不使用按高分辨率处理源放大的顶层比例参数。profile 或锚点变化必须产生新 variant Key，不得原位覆盖。

## 8. 非功能需求

- 公开页面 SSR，可索引；关键标题、正文、链接、图片 alt 与作品元数据存在于服务器 HTML。
- 390 × 844、768 × 1024、1440 × 900 三个固定视口的主要路径完整，无横向溢出。核心浏览器为 Android Chrome、iPhone Safari、Windows Chrome/Edge 当前稳定版；前一个大版本尽力兼容。
- 首屏轮播第一项提供宽高/比例并避免 CLS；横竖资源由 `<picture>/<source>` 或等价原生机制选择，禁止用两个同时加载的隐藏 `<img>` 实现。
- 所有管理写操作具备服务端认证、校验、幂等或资源版本、可读错误和集成测试。
- 普通页面错误渲染 Nuxt 错误页；API 错误返回统一 JSON，不把页面请求统一转成 JSON。
- 日志不得记录凭据、签名 URL、联系人、返图授权备注或私有 Object Key；OSS 处理失败只记录脱敏后的阶段、错误码、HTTP 状态与 requestId。
- SQLite 使用 WAL、外键、busy timeout 和一致性备份；单进程单写入者。
- 非测试环境的公开、后台、媒体和 OSS 上传 origin 必须通过 `.env`、进程环境变量或活动配置文件显式提供；应用与运维脚本不得硬编码 `localhost`、`127.0.0.1` 或部署域名 fallback。
- 运行配置在进程启动时读取；修改 `.env` 或活动配置后必须重启应用进程再验证，不把旧进程结果当作新配置证据。
- 所有配置项均适用同一规则：除测试文件中的隔离测试值外，具体配置值不得硬编码在应用代码、脚本或版本化文档/模板中，必须由 `.env`、进程环境变量或不入库的活动配置文件注入。产品不可变约束不是配置项，继续由版本化契约或常量固定。
- 委托/领养营业状态、作品状态和首页轮播发布后，下一次正常打开或刷新对应页面必须读取新状态，不要求管理员手动清缓存。
- 站点必须提供由当前 Logo 图形标生成的 favicon 与 Apple Touch Icon；浏览器标签页不得继续使用框架默认图标或空图标。

## 9. 验收门禁

1. T04–T08 完成生产视觉样张并由用户确认；
2. 第一条垂直切片可由管理员创建一件作品、上传私有原图、生成带品牌水印的公开衍生图、发布并在 `/works/{slug}` SSR 展示；
3. P0 首页可由管理员维护至少一组横版/竖版轮播图，横屏与竖屏分别请求正确资源，轮播控制、无 JavaScript首项和减少动效行为通过验证；
4. 领养设定图、出厂照和返图在公开端与管理端按角色分区，不被同一套比例和主图语义混用；
5. 私有 Bucket 匿名读取失败，公开 Bucket 只有网页衍生图且可按预期匿名读取；私有原图无水印且不被覆盖；
6. 公开 DTO、HTML、日志和错误响应不泄露私有字段；
7. favicon、触控图标和水印均可追溯到 EXT-01 确认的同一品牌源；
8. P0 全链 E2E、备份恢复和三视口回归通过后可形成首个可部署版本；E2E 必须覆盖有业务意义的用户路径、中间状态、失败/恢复和页面结果，并检查图片解码、溢出、焦点及关键请求。通过数量、HTTP 200、元素数量或选择器存在不能单独作为页面质量结论；
9. P1 完成后再宣布一期功能闭环；正式上线仍需正式素材、部署和实际使用验收；
10. EXT-01 正式素材门禁与实际用户内容维护验收通过后方可正式上线。

## F-01 · 作品分享与长期 URL 策略

### 当前决定

当前版本不实现 slug 显式改址历史。已发布作品的 slug 默认视为稳定公开地址；草稿和未发布作品的可编辑规则继续以当前 SPEC 为准。

### 重新讨论的触发条件

在明确作品分享的实际形式后，再统一设计 URL 与改址策略。需要先回答：

- 分享入口是复制链接、系统分享面板、社交平台卡片、分享海报、二维码，还是其中的组合；
- 分享对象只包括作品，还是还包括返图、领养和展会掉落；
- Open Graph 图片和分享文案如何生成、由谁维护；
- 是否需要稳定短链接或二维码长期有效；
- 作品改名是否必须同时改变 URL；
- 已发布 slug 是永久不可改，还是允许显式改址。

### 若未来允许改址，需要一起设计

- 旧 slug 到新 slug 的永久重定向；
- 旧 slug 保留与禁止复用；
- 多次改址时直接收敛到最新地址，避免重定向链；
- 循环检测和冲突校验；
- canonical、Sitemap、结构化数据和分享卡片同步；
- 作品下架、删除、恢复时旧地址的行为；
- 批量导入、备份恢复和迁移边界；
- 对搜索引擎与既有外部分享链接的兼容测试。

在分享形态未确定前，不单独建设通用重定向表或后台改址历史页面。

## F-02 · 返图公开来源信息

阶段 D 首版只公开返图图片及关联作品，不公开返图者昵称、个人主页、社交账号或授权记录。

只有在景宸明确需要展示返图者署名，并确认字段来源、公开授权和撤回方式后，才评估：

- 可选公开昵称；
- 可选主页链接；
- 链接协议和域名安全校验；
- 署名撤回与历史缓存处理；
- 与私有授权记录的边界。

## F-03 · 独立展会内容模型

阶段 D 不建设独立展会实体，只在展会掉落作品上保存展会名称和展会时间。

只有出现以下实际需求之一时，再评估独立 `events` 模型：

- 同一届展会关联多件掉落并需要统一修改；
- 需要地点、摊位、主办方、封面或统一销售规则；
- 需要独立展会页、历史归档、日历订阅或活动时间线；
- 同一作品需要跨多届展会保留完整历史。

届时应从现有轻量字段迁移，而不是提前预建空表和管理入口。

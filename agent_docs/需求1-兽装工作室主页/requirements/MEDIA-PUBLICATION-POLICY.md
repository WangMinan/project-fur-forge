# 媒体公开与保护策略

> **角色**：当前媒体公开行为的唯一事实源。
> **状态**：阶段 C 媒体迁移已完成，并于 2026-08-07 经用户浏览器人工验收。
> **适用范围**：首页、委托页、作品、领养、管理预览、OSS 衍生图、品牌水印切换与清理；阶段 D 返图墙的新增规则在范围确认后写入本文。

## 1. 核心原则

是否打水印由**公开展示位置**决定，而不是由图片横版或竖版决定。

- 站点展示位用于品牌首页和业务入口，应保持图片干净，不打水印。
- 作品展示位用于公开作品档案和领养展示，继续使用活动品牌水印。
- 永久原图、预处理源和水印 Logo 始终保存在私有 Bucket，不得直接作为公开 URL 返回。
- 所有公开图片都必须是服务端预生成、可校验、不可变的公开衍生图；浏览器不得通过 OSS 查询参数临时变换私有原图。
- 新增媒体角色必须显式登记用途、配方、保护模式、公开宽度和清理边界，不能归入含义模糊的通用“图片”。

## 3. 两类已落地公开配方

### 3.1 站点展示配方

阶段 C 已落地 `site-display-v1` 配方族，覆盖首页 Hero、委托页 Hero 和首页两个业务入口。

身份至少包含：

- `assetId` 与输入 SHA-256；
- 公开用途；
- 输出宽高、格式、质量、裁剪或焦点身份；
- `recipeVersion = site-display-v1`；
- `protectionMode = none`；
- 不携带水印 Logo、profile、位置、不透明度或缩放身份。

数据库使用显式保护模式表达是否有水印，不靠空字符串和宽松 NULL 组合推断。

站点展示衍生图必须：

- 同时提供 WebP 与 JPEG/PNG fallback；
- 写入公开 Bucket；
- 使用内容寻址或完整身份寻址的不可变 Object Key；
- 禁止覆盖既有对象；
- 写入后校验 MIME、尺寸、字节数、摘要与匿名读取；
- 失败时只清理本次新建对象，不影响当前已启用版本。

### 3.2 作品保护配方

作品列表、详情、领养列表和领养设定图继续使用：

- `recipe-v2`；
- 活动 `brand-centered-v2` profile；
- 当前配置的 Logo、位置、透明度和缩放身份；
- 现有横竖图片水印几何规则。

水印 profile 的变化必须生成新 Key，并在完整校验后原子切换。旧 profile 在仍被公开快照引用时不得删除。

## 4. 首页业务入口的独立派生

首页两个入口不得直接消费：

- 委托页 Hero 当前公开 URL；
- 第一件领养作品设定图当前公开 URL。

允许继续从对应业务源资产选择输入，但必须生成独立用途：

- `home-entry-commission`；
- `home-entry-adoption`。

独立用途保证：

- 两个入口采用统一比例、尺寸和裁剪策略；
- 入口图片无水印，而作品和领养页面仍有水印；
- 调整首页入口样式时不改变委托 Hero 或作品详情图；
- 清理与再生成可以按展示位置精确执行。

若委托 Hero 或可公开领养不存在，对应入口应隐藏或显示无图片的受控状态，不得回退到任意作品或私有原图。

## 5. 品牌 profile 切换边界

应用新的水印 Logo 或参数时：

- 只重新生成和切换需要水印的作品保护衍生图；
- 不重新生成 `site-display-v1` 无水印衍生图；
- 不删除站点展示衍生图；
- 管理端影响摘要明确区分“作品保护图片”和“站点无水印图片”；
- 旧 profile 切换失败时，公开作品继续使用旧活动 profile，站点展示图片不受影响。

阶段 D 的返图配方是否随活动 profile 切换，必须在 T35–T36 前明确，并写入不可变配方身份；实现者不得自行猜测。

## 6. 私有与公开存储边界

### 私有 Bucket

保存：

- 永久原图；
- FFmpeg 预处理或低分辨率适配源；
- 水印 Logo 候选；
- 管理预览与临时处理对象；
- 阶段 D 新增返图原图与可选授权记录关联的私有媒体。

要求：

- 匿名读取失败；
- Object Key 不进入公开 DTO、HTML、日志或 CSV；
- 临时对象有精确清理和生命周期兜底；
- 永久原图不得由生命周期规则误删；
- 返图授权记录不得进入公开 DTO、图片元数据或日志。

### 公开 Bucket

只保存通过完整身份生成和验证的衍生图。公开对象必须能从数据库记录追溯到输入资产、用途、配方和保护模式。

## 7. 阶段 C 迁移结果

阶段 C.1 已完成以下迁移：

1. 保留既有作品水印变体和历史 profile；
2. 为站点展示位生成新的无水印变体，验证完成后切换公开投影；
3. 未原位覆盖旧有水印 Hero 对象；
4. 新代码不再生成旧 Hero 水印目标；
5. 首页领养入口使用独立无水印用途，领养列表与详情继续引用有水印变体；
6. reconcile 失败时保持旧公开页面可用，并留下可恢复 operation；
7. 真实双 Bucket 验证 9/9 通过；
8. 用户已完成人工浏览器验收。

仍被历史记录或公开快照引用的旧对象不得无依据批量删除。后续清理必须按引用和精确 manifest 执行。

## 8. 当前验收状态

阶段 C 已确认：

- 首页 Hero 和委托页 Hero 的横竖请求命中无水印站点展示变体；
- 首页委托与领养入口命中各自独立的无水印入口变体；
- 作品列表、作品详情、领养列表和设定图继续命中活动水印变体；
- 更换活动水印 profile 后，作品图片变化，四类站点展示图片的 URL 和摘要保持不变；
- 匿名用户无法读取永久原图、预处理源、Logo 候选或管理预览；
- 三个固定视口 `390×844`、`768×1024`、`1440×900` 无坏图、错误裁剪和横向溢出；
- 真实双 Bucket、失败清理、重启恢复和公开 DTO 泄漏检查通过。

正式目标环境、GitHub Actions 全绿和线上发布演练不属于本策略的媒体行为结论，分别由 T49、T52 收口。

## 9. 阶段 D 返图墙待确认项

T35–T36 开始前，必须由业务范围确认并在本文增补：

- `return_photo` 的媒体数量和方向约束；
- 公开用途和配方版本；
- 轻量水印的位置、不透明度、缩放和是否允许关闭；
- 输出宽度、格式、质量和裁剪身份；
- 是否随活动品牌 profile 切换；
- 发布、下架、失败、清理和旧公开版本保留规则；
- 返图墙与作品详情各自使用的 SourceSet；
- 真实双 Bucket 和隐私验收矩阵。

在这些事实确认前，不得把返图公开图直接归入 `recipe-v2`，也不得使用客户端查询参数临时叠加水印。

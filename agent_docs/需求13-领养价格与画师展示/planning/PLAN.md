# 计划：领养价格与画师展示

## 执行顺序

1. schema 与0057前向迁移增加可选 artist；管理保存/回填/预览/变更快照接通。
2. 公开快照保留字段，由领养目录和详情分别白名单投影；首页使用无署名/价格的schema。
3. WorkBasicsFields 管理输入，AdoptionCard 目录卡片，works/:slug 详情信息表；继续使用现有组件，无新增组件框架。
4. 沿用金额formatter，支持两种语言前缀；词条统一管理标签和带姓名插值的署名。
5. 迁移/约束、管理往返、公开矩阵、表单/金额单测；真实浏览器检查中英、布局与交互；更新状态与证据。

## 技术决策

- artist 为nullable文本，100字符；请求允许省略兼容既有调用，更新省略时保留现有署名，显式null清空。
- 价格仅详情adoption对象持有；署名只目录与详情持有，不加入公共作品基础DTO。
- 复用既有首屏SSR和语言状态，不增加API按语言分支。

## 开放问题

无，技术细节按现有架构收敛。

## 执行结论

按上述链路完成；无需新增依赖、独立组件或货币模型。验证及未覆盖边界见 [STATE](../STATE.md)。

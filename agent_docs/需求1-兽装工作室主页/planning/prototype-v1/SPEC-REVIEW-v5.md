# PLAN 原型 v5 · SPEC 自审

## 结论

v5 在修改原型前，先把景宸确认的“简洁、以图片为主，Logo、文字介绍和符号均为兽装展示服务”同步到 `requirements/SPEC.md` 与 `planning/PLAN.md`。原型已取消 v4 的文字/图片等权左右分栏：首页由代表作品图铺满首个视口，向下先进入精选作品，再出现图片式委托/领养入口。当前未发现与已更新 SPEC 冲突的页面或交互；用户已于 2026-07-28 通过 `PLAN:OQ-018` 确认 v5 为一期 UI/交互基线，同时要求暂不进入 TASKS 或业务编码。

## 本轮契约变更

| 用户/景宸决策 | SPEC/PLAN 落点 | v5 表达 |
| --- | --- | --- |
| 简洁，以图片为主 | SPEC OQ-005、需求与设计边界、接口契约、验收项；PLAN 体验目标 | 公开站固定为“作品图片 > 品牌/页名 > 业务事实与行动 > 装饰” |
| Logo、文字和符号只辅助兽装展示 | SPEC 视觉层级与叠加安全区；PLAN 素材焦点 | 首页只保留工作室名、短口号、一个作品行动和向下提示；删除首屏说明段落 |
| 首页采用传统全幅作品开屏 | SPEC 首页首屏契约；PLAN 首页动线 | 一张代表作品图铺满桌面/手机视口，导航叠加；不再使用左右分栏 |
| 下滑先看作品 | SPEC 首页内容顺序；PLAN 信息架构 | `全幅首屏 → 精选作品 → 图片式委托/领养入口 → 营业状态 → 当前领养推荐` |
| 参考渔屋/万物通行各页签视觉 | PLAN 参考站动线与页签映射 | 作品/领养/返图保持图片优先；委托先显示代表作品宽图再显示范围、邮件和 FAQ；关于/联系按事实职责使用文字 |

## 自审发现与修正

1. 首轮 v5 截图发现 `.hero` 旧版双列网格仍影响全幅首屏文字的水平位置。已在 `.hero-cinematic` 显式改为单列，保证它不是隐性的左右分栏。
2. 首轮标题居中覆盖占位角色眼部。已把工作室名移到首屏上方安全区，并把作品行动移到底部；正式素材仍必须根据后台主体焦点分别校准桌面和手机安全区。
3. 首页业务入口最初仍继承旧卡片的纯色块语义。已改成两张全幅图片卡，短标题和行动叠加在底部渐变区。
4. 自设委托原先在进入正文前只有文字页头。已加入代表作品宽图，使委托页先展示制作气质，再进入范围、邮件与 FAQ。
5. 公开站、独立后台登录、后台工作流和 v4 已确认的禁用文案没有因首页重构发生回归。

## 原型阶段边界

- 几何 SVG 只验证图片比例、裁切、层级和响应式顺序；正式上线前必须替换为获授权的出厂照、设定图与正式 Logo。
- hash 路由、任意非空凭据登录、上传、处理、发布、导出和下载均为本地交互模拟，不连接 SQLite、OSS 或 SMTP。
- 2026-07-28 技术路线更新后，原型展示的单图上限已同步为 20 MB；生产由 Nitro 编排 OSS V4 直传和 OSS 图片处理，不再采用 MySQL/FFmpeg 链路。
- 正式作品图比例和主体位置不可预知，实施阶段必须读取后台焦点并用真实素材复核文字对比与安全区。
- 参考站只提供动线和层级证据；原型没有复制其 Logo、摄影、文案、FAQ 答案或高度可识别的专有版式。

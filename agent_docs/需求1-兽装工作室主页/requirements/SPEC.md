# 规格说明：兽装工作室主页

> **状态**：2026-07-30 T09 契约修订版。旧版 118 项 OQ 的讨论历史保留在 Git 历史中；OQ-119 已由用户回答，当前无开放 OQ。
> **边界**：本文件定义“做什么、验收什么”，技术实现由 `planning/PLAN.md` 决定。

## 1. 产品目标

1. 为“有点小狗工作室”建立以真实作品为核心的公开展示网站，让首次访问者迅速理解制作风格和完成能力。
2. 让访客能够连续浏览作品、了解自设委托与角色领养的真实营业状态，并通过邮件、QQ 或抖音继续沟通。
3. 为每件作品建立稳定、可分享、可索引的 `/works/{slug}` 档案。
4. 提供与公开站隔离的唯一管理员后台，使景宸可以维护作品、图片、状态与必要站点内容。
5. 在不建设站内交易、委托表单或客户管理系统的前提下，形成可靠的内容发布和原图保管链路。

## 2. 品牌与视觉结果

- 正式中文名：“有点小狗工作室”。
- 英文暂用 `dite dog`，后续允许从统一站点设置整体替换。
- 首版面向中国大陆，以简体中文为默认语言。
- 业务邮箱为 `3114559925@qq.com`，官方 QQ 为 `3114559925`，抖音为 `to3114559925`；例图中的个人 QQ 二维码一期不使用。
- 正式 Logo 尚未交付；“景宸的毛毛.png”中的狗头闪电不得提取、描摹或当作正式 Logo。
- 网站整体应是图片大底/白底的编辑型摄影作品集；Logo、文字和符号只为作品展示服务。
- 首页首屏由一张获授权代表作品图占据首个主要视口，不使用文字与图片等权的左右分栏。
- 明显蓝色面积常态 5%–10%，单页不得超过约 15%；不得出现连续蓝底区块、蓝色卡片墙或大面积渐变营销面板。

## 3. 公开页面与 URL

固定一级页面：

- 首页 `/`；
- 作品展示 `/works`；
- 作品详情 `/works/{slug}`；
- 自设委托 `/commission`；
- 角色领养 `/adoptions`；
- 返图墙 `/returns`；
- 关于我们与基本约定 `/about`；
- 联系 `/contact`。

兼容规则：

- `/adoptions/{slug}` 永久 301 到 `/works/{slug}`；
- `/terms` 永久 301 到 `/about#terms`；
- 首次发布后 slug 默认冻结；显式纠错时保存旧 slug 并永久 301；
- 后台、预览、API 与开发媒体路由不进入公开导航或 Sitemap。

## 4. 公开内容与行动

### 4.1 首页

首页首屏包含代表作品图、工作室名称/Logo、最多一句短口号、一个进入作品展示的主要行动和向下提示。首屏之后优先展示 3–6 件精选作品，再展示自设委托与角色领养入口，之后才是营业状态和辅助信息。

精选区域可以是横向轨道，也可以是编辑型图片网格；T05 必须用真实截图比较，最终以用户确认的视觉结果为准。

### 4.2 作品展示与详情

- 作品列表按人工顺序显示，并提供“作品用途 × 装型”的交集筛选和结果数；一期不提供全文搜索。
- 作品详情至少显示角色名、物种、装型、非空的角色主人展示值、主图、有序图集，以及适用的业务状态、展会、作品短属性和价格。工作室作品显示“有点小狗工作室”，隐私作品显示“不公开”。
- 每件作品可保存 0–8 条有序短属性；单条去首尾空白后 1–24 个字符，同件作品内不得重复。
- 价格仅在领养/掉落作品已录入人民币金额时显示，格式如 `¥15,600`；未录入时删除整个价格区域，不显示零价、“请咨询”或空标签。
- 公开页面不得包含联系人、返图授权记录、私有 Object Key、后台备注或交易控件。

### 4.3 自设委托

- 展示代表作品宽图、全装/半装制作范围、委托营业状态、人工估价说明、邮件行动、可复制邮箱、已确认 FAQ 和基本约定入口。半装由头、爪、尾巴组成；一期不宣传其他配件或服务。
- 不提供站内表单、自动报价、统一公开价目、固定排期、付款比例或其他未确认逐单规则。
- 邮件行动必须明确打开邮件客户端或复制邮箱，不模拟站内提交成功。

### 4.4 角色领养

- 展示领养营业状态、角色图片、领养方式、业务状态、当前展会、作品短属性和已录入人民币价格。
- 一般领养与展会掉落都进入统一作品详情；不建设第二套详情页。
- 网站不接受登记、定金、付款或签约。
- 展会掉落既可以是已完成头部、成交后继续制作，也可以是已完成全装并即买即穿；通过装型、状态与短属性表达，不建设全站制作进度字段。

### 4.5 返图墙

- 每张返图必须关联已有作品；每件作品最多 5 张返图。
- 可公开显示返图者昵称、日期与主页链接；均为可选。
- 后台可额外保存三个可选私有授权记录：授权来源、确认时间、简短备注。全部为空仍可发布，不形成刻板审批流。
- 当前没有真实返图时，SSR 页面显示经过设计的真实空状态，不使用假图，也不写“功能后续开放”。

### 4.6 关于与联系

- 关于页承载工作室事实、制作范围、官方渠道和基本服务约定；不虚构品牌故事。
- 联系页以 `3114559925@qq.com` 为主要业务行动，并展示确认后的 QQ、抖音和防诈骗提示。
- 基本约定至少覆盖：工作室与制作范围、逐单沟通原则、作品著作权与实体所有权、个人非商业使用、商业用途另行沟通、作品展示与完工前不公开请求、二次转让通知与反炒卖、基本售后、官方联系与防诈骗。
- 服务约定与法律文本在正式上线前由工作室确认和审阅，不复制竞品原文。

## 5. 管理端需求

### 5.1 访问与账号

- 后台使用独立 Host，公开站不显示后台入口。
- 一期只有一个管理员，不提供注册、第二管理员或账号管理列表。
- P0 提供登录、退出、修改密码和受保护命令重置密码；邮件找回属于 P2，不阻塞核心上线。
- 未认证时只显示登录或明确启用的找回页面，不渲染后台内容。

### 5.2 P0 管理能力

- 作品列表、新建、编辑、草稿、预览、发布、下架；
- 基础信息、作品短属性、适用人民币价格、营业状态；
- 原图上传、处理状态、主图、必要裁切/焦点、排序；
- 首页精选、委托/领养营业状态与必要站点内容；
- SQLite 一致性备份和恢复命令/说明。

### 5.3 P1 管理能力

- 返图上传、可选授权记录、排序和发布；
- 当前展会及作品关联；
- 完整多图、裁切和水印工作流；
- 受限站点内容编辑；
- 30 天回收站、slug 显式改址；
- 手机完成登录、查看、状态切换、文字修改、单图上传和发布。

### 5.4 P2 管理能力

- 邮件找回密码；
- CSV 导出中心；
- 永久原图档案 UI 与批量下载；
- 最小化访问统计；
- CDN 与复杂媒体失败恢复。

P2 页面在实现前不得以空导航或假功能出现。

## 6. 数据模型契约

### 6.1 作品

`works` 是统一聚合；委托、领养和展示作品不拆成不同核心表。字段至少覆盖：

- 稳定 ID、slug、角色名、物种、装型、非空的角色主人公开显示值；
- 可选业务用途、领养方式、业务状态、当前展会；领养方式固定为“常规领养/展会掉落”，业务状态固定为“准备中/可领养/展会出售中/排期中/制作中/已完成交付”；
- 0–8 条有序短属性；
- 可选 `priceAmountMinor` 与固定 `priceCurrency = CNY`；
- 发布状态、人工排序、首页精选；
- 后台私有联系人。

明确禁止保存：

- 禁止保存 `depositNote`、`paymentNote` 或等价定金/付款备注；
- 一期禁用的美元价格字段；
- 通用 EAV、制作进度、订单或支付记录。

### 6.2 图片资产

图片来源只有：领养设定图、出厂照、返图。原图和网页衍生图必须分离。每件作品最多 5 张出厂照和 5 张返图；领养作品另有 1 份设定图。同一图片不能同时属于出厂照与返图；网站不保存视频、制作过程图或独立制作完成度。

- 永久私有原图最大 30,000,000 字节，最长边 12,000；
- 原图 Key 每次上传新建且禁止覆盖；
- 数据库存相对 Key、摘要、宽高、来源、焦点/裁切、配方版本和状态，不存环境相关完整 URL；
- 管理端 DTO 使用 `assetId` 等业务标识，不直接向浏览器暴露私有 Object Key；
- 原图下载由认证管理员使用 `assetId` 换取短时签名 GET。

### 6.3 返图授权记录

返图记录可包含：

- `consentSource`: `qq | email | other | null`；
- `consentConfirmedAt`: 时间或 `null`；
- `consentNote`: 简短文本或 `null`。

这些字段仅作圈内轻量备忘，不是合同系统，不进入公开投影，不作为发布必填项。

### 6.4 公开投影

公开投影只返回已发布内容和公开衍生图，类型上排除：

- 联系人；
- 返图授权记录；
- 私有 Object Key；
- 密码、Session、找回令牌；
- 审计、内部错误和运维字段。

### 6.5 OQ-119 · `ownerDisplay` 空值语义（已答）

用户于 2026-07-30 确认：

- `ownerDisplay` 始终为去首尾空白后非空的公开显示值；
- 工作室作品填写并显示“有点小狗工作室”；
- 不公开角色主人时填写并显示“不公开”；
- 一期不增加 `ownerType`，也不以空值承载工作室作品语义。

因此管理端必须把 `ownerDisplay` 作为必填项，并删除“留空表示工作室作品”的提示。T12 建模时保留非空约束，不新增 `owner_type` 列；不得为漏填值提供会把作品静默归类为工作室作品的默认值。

## 7. 媒体结果契约

- 私有 Bucket：`project-furry-forge-private`；公开 Bucket：`project-furry-forge-public`。
- 浏览器只向私有 Bucket 上传；公开 Bucket 只含已发布网页衍生图。
- 发布时由 OSS 图片处理从私有原图生成确定性结果并 `sys/saveas` 到公开 Bucket；不通过 Object ACL 切换公开性。
- 草稿预览使用私有衍生图和短时签名 GET；公开页面永不读取原图。
- OSS 是唯一像素转换权威；`@nuxt/image` 不进行第二次动态转换。
- `recipe-v1`：
  - 3:4 卡片：480 / 768 / 1200；
  - 16:9 首屏/宽图：768 / 1280 / 1920；
  - 原比例详情：960 / 1600 / 2400；
  - WebP + 一种源兼容 fallback。
- 只生成实际页面使用的比例和宽度，不做组合爆炸。

## 8. 非功能需求

- 公开页面 SSR，可索引；关键标题、正文、链接、图片 alt 与作品元数据存在于服务器 HTML。
- 390 × 844、768 × 1024、1440 × 900 三个固定视口的主要路径完整，无横向溢出。核心浏览器为 Android Chrome、iPhone Safari、Windows Chrome/Edge 当前稳定版；前一个大版本尽力兼容。
- 首屏主图提供宽高/比例并避免 CLS；以下图片懒加载。
- 所有管理写操作具备服务端认证、校验、幂等或资源版本、可读错误和集成测试。
- 普通页面错误渲染 Nuxt 错误页；API 错误返回统一 JSON，不把页面请求统一转成 JSON。
- 日志不得记录凭据、签名 URL、联系人、返图授权备注或私有 Object Key。
- SQLite 使用 WAL、外键、busy timeout 和一致性备份；单进程单写入者。
- 委托/领养营业状态和作品状态发布后，下一次正常打开或刷新对应页面必须读取新状态，不要求管理员手动清缓存。

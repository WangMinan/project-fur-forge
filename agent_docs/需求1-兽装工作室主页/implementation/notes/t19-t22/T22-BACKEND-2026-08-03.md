## 2. Schema 与 API 决定

### 2.1 写入联合类型

`createWorkRequestSchema` 和 `updateWorkRequestSchema` 共用 `workFieldsSchema`：

- 通用必填：`slug`、`characterName`、`species`、`suitType`、非空 `ownerDisplay`、`ownerContact`（可为 `null`）、`featureTags`、`sortOrder`、`featured`；
- `commission` / `showcase`：严格拒绝 `adoptionMethod`、`businessStatus`、`priceCnyMinor` 及未知字段；
- `adoption`：T22 只接受 `adoptionMethod: "regular"`；`businessStatus` 接受 `preparing | available | scheduled | in_production | delivered`；`event_sale` 留给 T37；
- `priceCnyMinor` 可为 `null`，非空时必须是正整数；请求不接受币种输入，服务端固定写入 `CNY`；
- 短属性逐条去首尾空白，按 Unicode 字符计数 1–24，最多 8 条，去空白后同件作品不得重复；数组顺序就是公开顺序。

### 2.2 管理读写

沿用既有路由和安全中间件：

- `GET /api/admin/v1/works`：返回三类作品，按 `sortOrder, id` 排序；列表项含资源版本、排序、精选和适用领养字段；
- `POST /api/admin/v1/works`：创建三类草稿；Schema 矩阵错误返回 400；
- `GET /api/admin/v1/works/{id}`：返回完整管理 DTO；`ownerContact` 只位于 `private.ownerContact`；
- `PUT /api/admin/v1/works/{id}`：要求 `expectedVersion`，陈旧版本返回 409；完整作品字段仍须先下架；purpose 变化原子清理不适用列；已有设定图时离开 adoption 返回 409；
- `PUT /api/admin/v1/works/{id}/presentation`：只接受 `sortOrder` 与 `featured`，要求 `expectedVersion`；草稿、下架和已发布作品均可写，原子递增作品版本，使公开列表与首页精选立即读取新顺序；
- 管理 Host、Session、Origin、CSRF、`no-store` / `noindex` 继续由既有全局中间件统一执行，没有旁路或新权限模型。

400 响应使用固定的用途字段矩阵消息，不回显请求值；409 使用稳定、可操作的版本冲突、slug 冲突或设定图阻断消息。

### 2.3 历史展会兼容

- 不删除 `event_drop`、`event_sale` 或 `current_event_name`；
- 新创建/更新请求不提供这些写入能力，避免把自由文本当成 T37 的 `events` 模型；
- 已有历史记录在认证管理详情和列表中保持可读；
- 管理员后续提交常规领养完整 payload 时，`adoption_method/business_status/price` 被显式更新，`current_event_name` 原子清空，形成可验证迁移路径；
- 历史 adoption 若缺少公开必需的方式或状态，管理端仍可读取，但公开 mapper 安全忽略，直到被显式修正；不静默把任何记录归为工作室作品、领养作品或展示作品。

## 3. 数据库、迁移与 backfill

未新增迁移。理由：

1. `0000` 已建立本任务全部列、默认值和 CHECK：三用途、两装型、非领养字段清空、正数 CNY、非空 owner、非负排序、正版本；
2. `work_feature_tags` 已在数据库层约束位置 0–7、去空白后 1–24 和同作品唯一值；
3. `works_publication_sort_idx(publication_status, sort_order)` 已覆盖公开人工排序主路径；当前数据量不需要为布尔 `featured` 再建索引；
4. 现有作品已经由列默认值确定性得到 `sort_order = 0`、`featured = false`、`version = 1`，没有待补列数据；
5. 历史展会字段不存在可从事实安全推导的 backfill。保留原值并提供显式常规领养迁移，比猜测展会或用途更安全。

空库迁移仍为 11 项且可重复执行；既有历史数据的兼容读取和显式转换由集成测试覆盖。

## 4. 公开投影与隐私

- `/api/public/v1/works`：每次请求读取当前 SQLite，只返回已发布且当前活动水印 variant 完整的三类作品；用途 × 装型筛选保持交集语义；
- `/api/public/v1/works/{slug}`：草稿、下架、公开媒体不完整或历史领养事实不完整均按不存在处理；
- `/api/public/v1/works/featured`：复用作品快照的人工顺序，过滤 `featured = true` 后截取前 6 项；0 项安全返回空数组；
- 首页精选与 `site_hero_slides` 仍是两个对象，没有合并字段、表或 API；
- 公开 DTO、序列化测试和 mapper 不包含 `ownerContact`、`currentEventName`、私有 Object Key、签名 URL、Session、水印内部 identity 或请求中的额外私有字段。

## 6. 前端接口清单

前端必须完成以下接线，完成前不得勾选 T22：

1. 创建/编辑表单支持三种 `purpose` 和两种 `suitType`；切换 purpose 时显式移除不适用字段，不能把字段留在请求里依赖服务端丢弃；
2. 所有创建/更新 payload 提交 `sortOrder`、`featured`；adoption 额外提交 `adoptionMethod: "regular"`、允许的 `businessStatus` 和 `priceCnyMinor: number | null`；
3. `ownerDisplay` 改为任意去空白后非空文本，同时提供“有点小狗工作室”“不公开”的便捷选择；
4. 显示短属性数量、长度、重复、顺序和价格正整数错误；
5. 保存时带当前 `expectedVersion`，处理 409 stale、slug 冲突和设定图阻断；
6. 管理列表展示/编辑人工排序、精选和适用领养状态；
7. 历史 `event_drop/event_sale/currentEventName` 只读显示并提供“转为常规领养”的明确确认，不提供展会编辑器；
8. 首页精选 0 项时不渲染空轨道，1–6 项按服务端顺序消费。

2026-08-03 用户验收补充：已发布作品的排序/精选不再要求下架，作品列表与内层编辑页均改走独立 presentation 写接口；勾选精选且当前顺位与已有精选重复时，由服务端自动选择下一个空闲非负顺位，保证两个入口一致。完整字段与媒体编辑的下架门禁不变。

当前只把既有 `WorkBasicsForm` 的 TypeScript 字段宽度同步到新共享 DTO，未增加任何领养、排序、精选或历史展会 UI。

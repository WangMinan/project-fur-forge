# 规格说明：管理列表风格统一

## 状态与来源

- 日期：2026-10-08；用户已授权新建分支实施。
- 来源：用户提供的委托列表、作品管理截图与本轮请求；当前作品页实现为视觉基准。
- 继承 [需求4删除契约](../../需求4-站点视觉升级与内容合规/requirements/SPEC.md) 与 [需求5邮件通知契约](../../需求5-委托邮件通知与站点配置/requirements/SPEC.md)。

## 目标

1. 委托页采用与作品管理一致的表格、搜索/筛选栏和分页条，明确显示状态与操作，不显示缩略图。
2. 抽取两页实际复用的表格与筛选栏，继续使用现有分页、状态徽标、按钮及删除流程。

## 契约

- 桌面表格将名称与物种拆为独立列，作品和委托两页均适用；委托其余列为提交时间、处理状态、回执编号、邮件通知、操作。窄屏卡片也单列标注物种，全部操作可达。删除委托页“联系方式在详情中按需查看。”提示文案。
- 2026-10-08 用户追加：委托状态新增“全部状态”，默认全部；保留 pending/accepted/rejected URL 和浏览器历史导航。两页搜索均无按钮，输入时不筛选，失焦后应用；回车触发失焦，清除恢复默认筛选并清空关键词。关键词不进入 URL 或本地持久存储。
- 保留分页大小、范围计数、搜索/状态变化回到第一页、空态与失败重试；删除只对已拒绝申请出现，仍先 dry-run 再确认执行。
- 共用组件边界：`ListTable` 接收列名/无障碍名称，默认 slot 放表格行、mobile slot 放窄屏列表；`ListToolbar` 接收统计/清除状态并发出 reset，slot 放各页原控件；`CommissionListTable` 仅展示列表并向页面回传 deleted ID；`ListSearch` 统一可见标签、输入与失焦提交。
- 管理端列表 API 增加显式 `status=all`，复用服务层已有全量查询；未带 status 的 API 仍默认 pending，非法或重复状态参数仍拒绝。数据模型、存储、权限、私有字段投影及媒体访问保持原契约。

- 管理端 `AdminSelect` 的所有调用方复用公开站“关于我们”菜单的面板/选项 CSS：相同 padding、无额外选项间距、边框、圆角、阴影，选中与悬停均为浅蓝底/蓝字。鼠标展开时不为选中项画额外蓝框；键盘导航仍保留活动项焦点提示、无障碍语义及原生降级。公开菜单的原有外观与行为保留。

## 非目标

- 不新增批量操作、排序功能、通知能力或组件库依赖；不执行发布部署。

## 开放问题

无。具体实现与验证状态见 [任务清单](../implementation/TASKS.md)。

## 验收标准

- 两页共用视觉组件；委托支持桌面表格和窄屏卡片，长内容不造成页面横向溢出。
- 搜索、状态、分页、详情入口、受控删除、加载/失败/空态符合上述契约。
- lint、typecheck、受影响 core 与真实浏览器自动验证通过；保留虚构数据截图。
- 用户体验与真实手机由用户验收，远程 CI、发布及生产操作单独记录。

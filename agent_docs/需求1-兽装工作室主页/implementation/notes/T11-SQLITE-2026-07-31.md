## 2. 实现

- `server/utils/database.ts`
  - 每次连接强制并复核 `journal_mode=WAL`、`foreign_keys=ON`、`busy_timeout=5000`、`synchronous=FULL`；
  - 开发库固定为 `.data/dev.db`，生产库固定为 `/app/data/studio.db`，测试库必须是系统临时目录内的绝对 `.db` 文件；
  - Drizzle 版本化迁移读取 `_journal.json`，重复运行采用幂等语义；
  - 已存在数据库有待执行迁移时，先通过 SQLite Backup API 创建一致性备份；
  - 独立备份拒绝不存在/空源、同路径和覆盖既有目标，并执行 `integrity_check`。
- `server/plugins/01.database-config.ts`：应用启动时校验数据库路径边界，Nitro 关闭时释放连接。
- `scripts/db-migrate.ts`、`scripts/db-backup.ts`：提供迁移与一致性备份命令；不包含恢复 UI 或运维编排。
- `drizzle.config.ts`、`server/database/migrations/meta/_journal.json`：建立 Drizzle Schema 与版本化迁移入口。
- Playwright、生产验证和集成测试均使用独立临时数据库，不会写入开发库。

数据库事务范围内没有 OSS、HTTP 或其他网络调用；备份使用 SQLite 在线备份接口，没有复制活动 WAL 数据库主文件。

## 3. 命令

```text
pnpm db:generate
pnpm db:migrate
pnpm db:backup -- --output <absolute-backup.db>
```

`pnpm db:migrate` 从当前运行配置解析数据库文件。`pnpm db:backup` 只接受显式输出路径并拒绝覆盖。

## 5. 风险与后续

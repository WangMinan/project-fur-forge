## 2. 认证实现

- `nuxt-auth-utils@0.5.29` 提供密封 Cookie Session；Cookie 名为 `__Host-fur-forge-session`，固定 `HttpOnly`、`Secure`、`SameSite=Strict`、`Path=/`，不设置 `Domain`。
- Session 最长 8 小时无操作；每次访问重新校验唯一管理员仍为 active、数据库 `session_version` 与密封 Session 一致，并更新最后访问时间。
- 密码使用 Node.js `crypto.scrypt` 随机盐哈希，不保存明文；登录不存在账号时执行同成本密码推导，响应不区分账号不存在、密码错误和锁定。
- 连续失败 5 次锁定 30 分钟；锁定、失败计数清理和成功登录在 SQLite 即时事务中按最新用户行提交。
- 改密使用 `expectedVersion` 做服务端资源版本控制，成功后同时递增资源版本和 `session_version`，清除调用者 Session；受保护重置命令和退出同样使旧 Session 失效。
- 登录 POST、退出和全部管理写 API 执行精确 Origin 校验；受保护写请求还执行随机 CSRF token 校验。Host 中间件在公开 Host 对 `/admin`、`/api/admin`、`/api/auth` 和模块内置 `/api/_auth` 返回 404。
- 模块内置 Session API 不作为产品接口；公开与管理 Host 均不能访问它，只暴露本项目的逐字段响应。
- 安全日志只记录事件名和经过现有脱敏器处理的用户名，不记录密码、Cookie、Session、CSRF、请求体或数据库私有字段。

## 3. API 与命令

| 方法与路径 | 作用 | 主要边界 |
| --- | --- | --- |
| `POST /api/auth/login` | 登录并返回管理员公开字段、资源版本和 CSRF token | 管理 Host、精确 Origin、统一 401 |
| `GET /api/auth/session` | 校验并滑动更新当前 Session | active、SessionVersion、8 小时无操作 |
| `POST /api/auth/logout` | 退出并清除 Cookie | Session、Origin、CSRF；旧 Session 全部失效 |
| `PUT /api/admin/account/password` | 修改当前管理员密码 | Session、Origin、CSRF、当前密码、`expectedVersion` |

请求和成功响应的可执行契约在 `shared/schemas/auth.ts`，统一错误 envelope 在 `shared/schemas/api.ts`。登录请求为 `{ username, password }`；Session 与登录成功均返回 `{ data: { user: { id, username, version }, csrfToken } }`，因此页面刷新后用 `GET /api/auth/session` 恢复内存中的 CSRF token。受保护写请求通过 `x-csrf-token` 发送该 token。改密请求为 `{ expectedVersion, payload: { currentPassword, newPassword } }`，成功返回 `{ data: { version, reauthenticationRequired: true } }` 并要求重新登录。用户名只去首尾空白，不转换大小写。

初始化和重置默认直接使用隐藏 TTY 密码输入，不把密码写入命令参数、日志或 Shell 历史：

```text
pnpm auth:init
pnpm auth:reset-password -- --confirm RESET_SINGLE_ADMIN_PASSWORD
```

受控自动化可以使用进程环境。PowerShell 使用 `SecureString`，并在 `finally` 中清理环境和安全字符串：

```powershell
$adminPassword = $null
try {
  $env:ADMIN_USERNAME = Read-Host 'Admin username'
  $adminPassword = Read-Host 'Admin password' -AsSecureString
  $env:ADMIN_PASSWORD = [System.Net.NetworkCredential]::new('', $adminPassword).Password
  pnpm auth:init
} finally {
  Remove-Item Env:ADMIN_USERNAME, Env:ADMIN_PASSWORD -ErrorAction SilentlyContinue
  if ($null -ne $adminPassword) { $adminPassword.Dispose() }
  Remove-Variable adminPassword -ErrorAction SilentlyContinue
}
```

密码重置同样使用交互输入：

```powershell
$adminPassword = $null
try {
  $env:ADMIN_USERNAME = Read-Host 'Admin username'
  $adminPassword = Read-Host 'New admin password' -AsSecureString
  $env:ADMIN_PASSWORD = [System.Net.NetworkCredential]::new('', $adminPassword).Password
  pnpm auth:reset-password -- --confirm RESET_SINGLE_ADMIN_PASSWORD
} finally {
  Remove-Item Env:ADMIN_USERNAME, Env:ADMIN_PASSWORD -ErrorAction SilentlyContinue
  if ($null -ne $adminPassword) { $adminPassword.Dispose() }
  Remove-Variable adminPassword -ErrorAction SilentlyContinue
}
```

Bash 使用 `read -s`，通过 `trap` 保证退出时 `unset`：

```bash
cleanup_admin_credentials() {
  unset ADMIN_USERNAME ADMIN_PASSWORD
}
trap cleanup_admin_credentials EXIT HUP INT TERM
read -r -p 'Admin username: ' ADMIN_USERNAME
read -r -s -p 'Admin password: ' ADMIN_PASSWORD
printf '\n'
export ADMIN_USERNAME ADMIN_PASSWORD
pnpm auth:init
```

重置时把最后一行替换为 `pnpm auth:reset-password -- --confirm RESET_SINGLE_ADMIN_PASSWORD`，并把密码提示改为 `New admin password`。`auth:init` 对同一管理员重复运行不会替换首次密码。两项命令都要求数据库已先执行 `pnpm db:migrate`；它们不会隐式迁移。重置命令要求显式确认短语，重置后旧 Session 全部失效，stdout 只输出非敏感结果。

# 阶段 D 范围确认（2026-08-07）

> **性质**：用户确认的阶段 D 产品决策记录。当前业务契约以 `requirements/SPEC.md`、`planning/PLAN.md` 和 `implementation/TASKS.md` 为准；本文件保留本次范围收敛依据。
> **代码基线**：`93557c38c9d3d4b0586c96bef5c05d8d369fb424`。

## 1. 确认结论

阶段 D 只保留两个产品成果：

1. 独立一级导航 `/returns` 的返图墙；
2. 复用现有作品与领养管理的轻量展会掉落。

阶段 D 不建设更多通用内容平台能力，也不以任务编号连续性为由实现已取消功能。

## 2. 返图墙

用户确认：

- 公开返图页为一级导航中的独立 `/returns`；
- 不在作品详情内部建设返图 Tab；
- 公开端采用原比例瀑布流；
- 返图公开图不加水印；
- 私有原图仍保存在私有 Bucket，公开端只读取预生成、校验完成且去除 EXIF 的公开衍生图；
- 返图必须关联已有作品；
- 可选授权来源、确认时间和备注只在后台保存，不进入公开 DTO、HTML、图片元数据或日志；
- 首版不建设访客投稿、用户账号、点赞、评论、社交主页或算法时间线；
- 首版不建设返图回收站，已发布内容先下架，永久删除不作为阶段 D 必做入口。

一张公开返图对应一条返图记录，避免再引入“返图相册/批次”层级。公开卡片可以显示关联作品名称并链接 `/works/{slug}`，但作品详情不反向嵌入完整返图墙。

## 3. 轻量展会掉落

用户确认展会掉落必须实施，但不建设独立展会系统：

- 底层继续使用 `purpose = adoption`；
- 通过 `adoption_method = event_drop` 表示展会掉落；
- 管理端可以把业务选择显示为“委托作品 / 常规领养 / 展会掉落 / 纯展示”，内部映射回现有三种 purpose；
- 发布展会掉落时只要求填写展会名称和展会时间；
- 复用现有领养价格、状态、设定图、出厂照、发布、下架和公开详情链路；
- `/adoptions` 同时展示常规领养与展会掉落，并允许按二者筛选；
- 首页“当前领养”可以包含展会掉落，卡片和详情展示展会名称与时间；
- 展会时间只用于展示，不自动切换业务状态；
- 不创建 `events` 表、展会管理页、展会详情页、展会封面、地点、摊位、主办方、归档或日历订阅。

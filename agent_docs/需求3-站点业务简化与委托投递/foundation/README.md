# 需求3 · 产品地基

> **角色**：固定本轮站点业务简化、动效升级、委托投递和破坏性退役的不可突破边界。
> **基线**：继承 [`../../需求1-兽装工作室主页/foundation/README.md`](../../需求1-兽装工作室主页/foundation/README.md) 的双 Host、私有媒体、安全、部署和验收基线；继承需求2仍然适用的官方渠道与公开搜索能力。
> **覆盖规则**：本文件与同目录 `requirements/SPEC.md` 对返图墙、最新动态、作品字段、领养方式、Hero、品牌英文名和委托入口的明确规定，覆盖需求1、需求2中的旧产品行为；未明确改变的安全、媒体和生产规则继续有效。
> **代码基线**：立项审查基于 `main@9a6add09db559ac134b58cd5b75af1c588c76306`。

## 1. 本轮目标

把站点从“功能较全的工作室 CMS”收敛为“图片成果展示 + 设定领养 + 委托线索收集”，同时提升公开端动效和首页表现：

1. 永久退役返图墙与最新动态，删除页面、接口、数据表、私有原图、公开派生和相关备份；
2. 将品牌英文名恢复为 `DITE DOG`，不再使用 `DITE DOG FURSUIT`；
3. 重做首页 Hero 的排版、移动端首屏覆盖与横竖素材管理；
4. 将作品模型缩减为名称、物种、图片和必要内部发布字段；
5. 让设定领养统一使用普通领养逻辑，并增加独立横版单头成果图；
6. 新增匿名访客提交、后台查看和处理的自设委托申请流程；
7. 在公开端系统性增加导航、页面切换、区块入场和图片交互动效。

## 2. 已锁定产品决策

- 公开品牌英文名固定为 `DITE DOG`；代码、SEO、测试、文档和可见文案中的旧英文名全部回退。
- 当前首页 slogan 固定更新为 `不只做小狗毛 | 只做海绵头`。
- 返图墙与最新动态不做隐藏保留，执行不可恢复的永久删除；用户已明确授权本地与生产环境的破坏性清理。
- 退役页面不做搜索引擎兼容、不做跳转，路由移除后直接进入普通 404。
- 公开端取消“尽量少动效”的旧视觉原则，但 `prefers-reduced-motion` 仍是必须保留的无障碍边界。
- 首页横版与竖版大图完全独立维护、独立排序、独立启停；每个 placement 和 orientation 各允许 1–5 张启用素材，不允许跨方向自动裁切兜底。
- `/works` 与 `/works/{slug}` 的文字事实只保留名称和物种；详情页的主要内容是图片图集。
- 不再维护装型、单主公开值、单主私有联系人、作品属性标签、制作进度、领养方式和展会字段。
- 作品内部仍保留 `purpose`，用于区分普通作品、领养作品和纯展示；它不是公开筛选事实。
- 领养状态收敛为 `available | adopted`；价格继续保留。若未来确有保留业务，再另立需求增加 `reserved`。
- 领养列表使用一张独立横版单头成果图；作品展示继续使用竖版全装主图。设定图最多一张、仅作为可选详情素材，不再是领养列表封面或发布门禁。
- 委托申请必须提交一张设定图、称呼、手机号、QQ、身高和体重；手机号和 QQ 都必填。
- 委托申请只在后台分为待处理、已接单、已拒绝；不发邮件、不接 SMTP、不提供访客查询状态，也不自动生成作品。

## 3. 模块边界

- `shared/constants/project.ts` 及品牌静态内容：英文名与固定展示文案。
- `app/utils/public-nav.ts`、公开 Header/MobileNav/Footer、sitemap/analytics：移除返图和动态入口，增加动效反馈。
- 首页公开组件、`/admin/site/home`、Hero Schema/repository/runner/recipe：横竖素材解耦、首屏布局和独立轮播。
- `works`、`work_assets`、作品管理和公开作品 repository：字段收缩、公开 DTO 收缩和图片展示。
- `/adoptions`、领养公开投影和作品管理：统一领养状态、独立 `adoption_cover` 媒体。
- `/commission`、新 `/commission/apply`、新 `/admin/commissions`：委托入口、匿名上传、申请提交和后台队列。
- `site_content` 及文案配置：删除 FAQ 与邮件行动文案，保留委托介绍、估价说明、关于、法务、官方渠道和防诈骗信息。
- 返图、动态相关页面、API、repository、service、runner、Schema、测试、迁移约束和媒体身份：完整移除。

## 4. 数据与破坏性清理边界

本需求是对通常“只做前向兼容迁移”原则的一次显式例外，但仍不得重写已经执行过的历史迁移：

- 只新增前向迁移和受控清理工具；
- 清理顺序必须先枚举精确数据库行与 OSS Object Key，再删除对象并验证，最后删除表和收紧约束；
- `updates`、`return_characters`、`return_photos` 及其关联数据必须从本地和生产数据库永久删除；
- 所有 `return_photo` 私有原图、私有预处理、公开派生、预览、未完成上传对象和 ESA 缓存必须永久删除；
- 项目脚本管理的旧数据库备份若仍包含返图或动态数据，也必须删除，并在迁移后生成新的净化备份；
- OSS 若启用版本控制，必须删除所有对象版本和 delete marker，而不是只写一个删除标记；
- 不在仓库、日志、dated note 或长期 manifest 中保留返图内容、动态正文、手机号、QQ、设定图或完整 Object Key；
- 最终 contract migration 完成后，不保证旧镜像可回滚；出现问题采用前向修复。

## 5. 媒体边界

- 公开作品、领养、Hero 继续只消费验证完成的 ESA HTTPS 派生图。
- `studio_photo` 继续承担作品竖版主图和作品图集；作品卡保持 3:4 成果展示。
- 新增 `adoption_cover`：每个已发布领养作品恰好一张横版单头成果图，用于 `/adoptions` 和首页当前领养。
- `design_sheet` 最多一张，仅作可选详情素材，不参与领养列表卡和发布资格。
- 新增委托设定图媒体身份；它只保存私有源图和必要私有验证结果，不生成公开派生、不上 ESA、不加水印。
- 首页与委托页 Hero 的横竖素材继续使用站点展示无水印派生，但由 orientation 独立发布。

## 6. 隐私与安全边界

- 委托称呼、手机号、QQ、身高、体重和设定图全部属于私有委托数据，只能在管理 Host 的认证页面和 API 中读取。
- 匿名上传不能放宽现有管理上传会话的 `created_by`、CSRF 或管理员归属约束；必须建立独立的短时、一次性、限流上传会话，并复用已有 OSS 校验和图片验证基础设施。
- 公开提交必须校验 Origin、Content-Type、请求体大小、字段格式、上传会话状态和一次性绑定关系。
- 首版使用可信客户端地址限流、隐藏蜜罐和短时 token，不引入第三方验证码服务。
- 私有字段不得进入 analytics、普通日志、错误文本、公开 DTO、HTML、URL query、截图或测试 fixture 的真实值。
- 后台只显示业务可理解的中文，不暴露 Object Key、摘要、内部会话 ID 或数据库术语。

## 7. 明确不做

- 不恢复返图墙、最新动态或其只读归档；
- 不建设订单、支付、排期、合同签署、邮件通知、短信通知或用户账号；
- 不建设委托申请的公开查询、撤回、编辑或自动转作品；
- 不增加多图设定提交，一次委托申请只允许一张设定图；
- 不建设通用 CMS、富文本、页面搭建器或第三方搜索服务；
- 不将横版领养头图从竖版出厂照或设定图自动裁切生成；
- 不新增展会、掉落类型或展会管理系统；
- 不移除 `prefers-reduced-motion`、键盘操作、焦点管理或其它既有无障碍要求。

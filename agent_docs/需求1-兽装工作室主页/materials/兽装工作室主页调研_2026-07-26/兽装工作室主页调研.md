## 一、结论先行

这四组网站共同在解决三个问题：

1. **先让访客相信作品的审美和制作能力**：首屏几乎都用大幅兽装照片、视频或强世界观画面建立第一印象。
2. **再让访客快速找到业务入口**：把“自设委托”“设定领养”“作品展示”“FAQ / 服务条款”放在顶部导航或首页核心区。
3. **最后降低高客单价交易的不确定性**：公开价格或价格区间、制作周期、排单状态、委托流程、修改规则、版权、售后和安全说明。

对于朋友的新工作室，最值得借鉴的不是某一种视觉风格，而是这套稳定的信息顺序：

**品牌气质 → 业务选择 → 作品证据 → 价格与排期 → 流程与规则 → 明确行动按钮。**

建议初版采用一个站点承载委托与领养，只有在领养角色数量、设计师合作和交易运营明显变复杂后，才考虑像万物通行一样拆出独立领养商城。

## 三、共同点

### 1. 首页不是产品目录，而是品牌海报

四组网站都把最强的视觉资产放在首屏：

- 万物通行、鸿萌、渔屋使用实拍兽装或活动照片；
- 虚构都市使用动态粒子、线框角色和系统终端语汇；
- 标题非常短，首屏只保留一个最核心动作，例如“立即估价”“申请加入都市”。

这说明首页首屏的首要任务不是解释全部业务，而是让用户在数秒内感受到“这家做出来的东西是什么气质”。

![万物通行委托站首页](./imgs/01-万物通行-委托站-首页.png)

![虚构都市首页](./imgs/19-虚构都市-首页.png)

### 2. 委托与领养必须被明确分流

只要同时经营两种业务，网站都会把它们做成不同入口：

- 万物通行直接拆成两个站；
- 鸿萌在“产品定制”内并列“领养委托 / 自设委托 / 角色风格化”；
- 渔屋在“委托投递”下设置“自设委托 / 设定领养”。

用户不应该先理解工作室内部术语，才知道自己该点哪里。首页需要用一句话解释：

- **我已经有设定** → 自设委托；
- **我想挑选现成设定** → 设定领养；
- **我想在展会购买已完成头部的角色** → 展会掉落。

### 3. 作品展示承担“质量证明”

所有样本都有作品或居民展示，区别只在呈现方式：

- 万物通行有作品、委托人和活动；
- 鸿萌有出场照、活动照；
- 渔屋把“作品展示”和“返图墙”分开；
- 虚构都市把成品角色称为“居民档案”。

作品页不只是相册。成熟做法会给每个角色保留名称、系列、种族、画师或制作方等结构化信息，方便用户理解工作室擅长的风格。

### 4. 高客单价交易需要公开规则

四组网站都用不同方式补足信任信息：

- 价格或估价工具；
- 当前排期与制作周期；
- 定金、锁定、付款和发货；
- 制作前后的修改边界；
- DTD / 量体要求；
- 版权、转让和商用范围；
- 售后、保养、保修与安全提示；
- 服务条款、隐私政策与官方联系方式。

这部分往往比“关于我们”的品牌宣言更能影响用户是否愿意提交设定图。

### 5. 都在使用“状态标签”

领养业务尤其依赖状态标签：

- 即将上架；
- 可申请 / 应征领养；
- 直接领养；
- 展会掉落 / 展会出售中；
- 未锁定 / 锁定；
- 未领养；
- 当前未开单。

状态必须同时回答“现在能不能买”和“下一步做什么”，不能只用颜色表达。

## 四、类似的设计语言

### 1. 大图、短文案、强对比

共同模式是大幅视觉、短标题、少量按钮。即使风格差异很大，构图都强调单一焦点：

- 白底站点用黑色大字和大量留白；
- 深色站点用高饱和品牌色制造层级；
- 卡片区则恢复稳定、可扫描的信息结构。

### 2. 中英双语小标题

`COMMISSION`、`PRODUCT`、`GALLERY`、`SERVICE`、`VALUATION`、`REGISTRATION PROCESS` 等英文常被当作装饰性副标题。它能增强专业感和品牌感，但不应替代中文业务说明。

### 3. 卡片化呈现

作品、角色、设计师、服务步骤和价格方案几乎都使用卡片：

- 图片负责审美；
- 标签负责状态；
- 名称、画师、系列负责识别；
- 价格和按钮负责转化。

卡片很适合领养业务，因为用户会快速横向比较多个角色。

### 4. 固定顶部导航

长页面普遍保持顶部导航可见，让用户在作品、价格、FAQ 和表单之间快速切换。导航项数量一般控制在 4–6 个一级入口。

### 5. 情绪区与功能区分层

首页上半段负责“想要”，下半段负责“敢买”：

- 上半段：视觉、角色、世界观、活动氛围；
- 下半段：价格、周期、表单、FAQ、条款、联系方式。

这是后续设计最应该保留的节奏。

## 五、核心用户动线横评

### 1. 自设委托

四站的共同主线是：

**首页主视觉 → 委托类型 / 系列 → 价格与周期 → FAQ / 条款 → 估价或申请表 → 人工确认。**

差异主要在提交前的信息量：

- 万物通行先用 WP / SP 两列回答价格、材料与交期，再进入估价；品牌说服力最强，但本次估价终端未正常渲染；
- 鸿萌造物直接进入高密度表单，基础信息、地址、货主、体测和制作备注一并收集，适合已有客服和订单系统的团队；
- 渔屋使用三步估价，先设定与系列，再联系方式，最后身体数据，认知负担最低；
- 虚构都市把配置选择、体测和联系方式合为一套“申请加入都市”，并在首页先公开 20% 定金、8–9 个月周期和报价有效期。

首版开发建议采用渔屋式分步表单，但在进入表单前放置万物通行式“系列 / 起价 / 周期”对比，避免用户填完才发现预算不匹配。

### 2. 一般领养

页面已实际观察到的 UI 链路是：

**列表筛选 → 角色卡片 → 详情 → 阅读权利与规则 → 申请 / 锁定入口。**

“人工联系或支付”属于页面规则描述或登录后的后续动作，本次没有提交或完成交易。

- 角色汤：卡片进入详情，采用直接领养或“应征领养”；详情强调价格包含内容和权利范围；
- 鸿萌造物：详情同时展示设定图、背景、20% 定金、分期总价和全款优惠；“绑定角色并支付”前要求登录；
- 渔屋：详情展示 UID、画师、系列、种族、发布时间、价格和领养须知；点击“开放领养”后先出现二次确认弹窗。

![鸿萌造物领养详情：角色、背景与三档价格](./imgs/53-鸿萌造物-领养详情-角色与三档价格.png)

![渔屋领养提交前确认](./imgs/66-渔屋Fursuit-领养详情-提交前确认弹窗.png)

三站共同证明：领养详情不能只是一张设定图和价格。至少要明确年龄门槛、联系时效、设定与兽装权利、转让规则、保修、付款节点以及当前状态。

领养“类型”和交易“状态”应在数据层分开：

| 字段 | 建议取值 | 作用 |
| --- | --- | --- |
| `adoptionType` | 直接领养、应征领养、展会掉落 | 决定规则、提交方式和是否依赖展会 |
| `status` | 即将上架、开放中、已锁定、已领养、已结束 | 决定现在能否操作及按钮文案 |

### 3. 展会掉落

角色汤已截图的站内 UI 链路是：

**专题列表 → 某届展会专题 → 本届掉落角色 → 角色详情。**

角色详情中的页面文字继续说明“现场抽选 → 支付 → 签订合同 → 按领养人体型制作身体”。这些线下步骤来自规则说明，本次没有在现场验证。

专题列表保留展会名称、地点、日期和历史记录；专题详情再聚合本届角色。它把“活动内容”和“可交易库存”绑定起来，比在普通领养列表中只放一个“展会掉落”标签更有营销价值。

![角色汤展会专题列表](./imgs/49-万物通行角色汤-展会专题-列表顶部.png)

![角色汤展会专题详情](./imgs/51-万物通行角色汤-展会专题-专题详情.png)

如果新工作室未来参加兽展，建议把展会当作一级内容对象，具备时间、地点、摊位、掉落角色、销售规则和结束状态，而不是只发一篇公告。

### 4. 作品浏览

成熟网站通常不是“点开一张大图就结束”，而是提供结构化浏览：

- 万物通行：系列筛选 → 四列角色卡片 → 角色 8 张图灯箱；
- 鸿萌造物：出场照 / 活动照切换 → 暗色多列照片墙 → 纵向浏览；
- 渔屋：系列与全装 / 单头筛选 → 网格卡片 → 作品详情弹窗；
- 虚构都市：首页居民横向跑马灯 → 居民名片弹窗。

这四种模式分别适合“作品量大”“强调沉浸照片”“需要精确筛选”“品牌世界观强”的团队。

## 六、作品、返图与社会证明横评

### 1. 标准作品与用户返图应分开

标准作品回答“工作室能做多好”，返图回答“真实用户穿起来如何、角色是否活起来”。渔屋把两者拆为独立一级导航，是样本中最清楚的做法：

- 作品展示：统一主图、角色名、系列、全装 / 单头、完成时间；
- 返图墙：真实场景瀑布流、设定名搜索、返图者昵称和个人主页入口。

![渔屋返图墙瀑布流](./imgs/62-渔屋Fursuit-返图墙-瀑布流中段.png)

![渔屋返图详情与用户主页入口](./imgs/64-渔屋Fursuit-返图墙-返图详情与用户主页入口.png)

### 2. 作品详情的最小字段

综合四站，建议保留：

- 角色名称、系列、种族；
- 全装 / 半装 / 单头；
- 完成时间；
- 设计师、制作方；
- 3–8 张多角度照片；
- 棚拍 / 出场 / 活动 / 用户返图类型；
- 可选的角色主页或社交账号；
- 若角色来自领养，关联原领养详情或设计师。

### 3. 活动记录是另一种信任证据

万物通行把活动独立成时间线，记录展会 / 聚会类型、日期、城市、摊位、展示 / 贩卖 / 掉落信息，并链接外部展会页。这不仅证明工作室真实活跃，也能为展会掉落导流。

![万物通行线下活动记录](./imgs/69-万物通行-线下活动-展会记录顶部.png)

### 4. “作品橱窗”的四种可借鉴形态

| 形态 | 样本站点 | 优点 | 风险 |
| --- | --- | --- | --- |
| 网格 + 灯箱 | 万物通行 | 扫描效率高，可快速看大量角色 | 若无详情字段，搜索和分享能力弱 |
| 暗色多列照片墙 | 鸿萌造物 | 同屏图片多，活动氛围强 | 部分图片加载失败时空洞很明显 |
| 网格 + 结构化弹窗 | 渔屋 | 筛选与详情兼顾 | 需要持续维护元数据 |
| 世界观名片 | 虚构都市 | 品牌记忆强、角色资产感强 | 文案不能遮蔽真实作品信息 |

## 七、逐站观察

### 7.1 万物通行：成熟的“品牌官网 + 领养商城”

#### 委托站

顶部功能包括：兽装委托、作品展示、委托人、线下活动、客服支持、关于我们。委托页进一步提供常见问题、合同样本、开放时间表和立即估价。

委托系列对比非常直接：

- WP：22000+ CNY；3D 打印头，可付费升级海绵；最快约 6 个月，最长不超过 12 个月；
- SP：26000+ CNY；柔软海绵材质、量身定制设计；最快约 12 个月，最长不超过 18 个月；
- 两者都展示毛布、风扇、涂装和售后差异。

![万物通行系列价格](./imgs/27-万物通行-委托价格与周期.png)

![万物通行材质与交期](./imgs/28-万物通行-委托材质与交期对比.png)

值得借鉴：

- 用并列卡片回答“贵在哪里、慢在哪里、适合谁”；
- 在同一区域展示价格、材料和交期，不让用户来回翻 FAQ；
- 首页中段把委托、硬件配件和养护服务做成不同视觉卡片，形成完整产品生态。

当前问题：

- “立即估价”终端页在本次 Chrome 访问中出现空白，入口存在但未渲染出可操作内容；
- 个别内容依赖图片和动画加载，首次滚动会短暂出现较大空白。

作品与返图在信息架构上被刻意分开：

- “作品展示”是四列网格，卡片显示角色名、系列图标和照片数量；点击主图后在原页打开多图灯箱，不改变 URL；
- “委托人”先用大幅返图做人物推荐，再进入独立角色档案；档案含角色名、设计师、生日、活跃城市、特征、角色曲与社交链接；
- “线下活动”按时间记录展会和聚会，“客服支持”则按兽装委托、装师服务、风扇、DRA.s 四类业务分流，并把反诈警示放在主内容区。

![万物通行作品列表](./imgs/42-万物通行-作品展示-列表顶部.png)

![万物通行作品多图灯箱](./imgs/44-万物通行-作品展示-图集弹窗.png)

![万物通行委托人角色档案](./imgs/47-万物通行-委托人返图-角色详情.png)

这里最重要的动线判断是：标准作品用“快速浏览 + 灯箱”，用户返图用“可分享角色档案”。前者降低浏览成本，后者增加人物和社区感。

#### 角色汤领养站

角色汤使用独立站点承载领养交易，导航只有领养角色、设计师、专题，目标非常聚焦。

领养列表支持种族、颜色和排序；卡片展示名称、设计师、价格、热度和状态。详情页会写清价格包含内容、版权范围和注意事项。

![角色汤领养列表](./imgs/05-万物通行角色汤-领养列表.png)

一般领养使用“应征领养”：提交申请后由工作室挑选合适委托人。展会掉落则明确说明：

- 角色在展会现场抽选；
- 通常头部已经制作完成；
- 身体根据领养人体型制作；
- 抽选结束后现场支付并签订合同。

![角色汤展会掉落详情](./imgs/06-万物通行角色汤-展会掉落详情.png)

值得借鉴：

- 设计师页展示“可领养 / 已被领养”数量，强化画师资产；
- 专题页按展会组织掉落角色，适合活动营销；
- 领养类型、时间、价格和权利范围都在详情页一次讲清楚。

角色汤的页面视觉从委托站的“高级产品官网”切换为白底商城：卡片密度更高、标签更多、价格与热度更醒目。它保留统一品牌，但没有强迫交易页沿用委托站的大留白和长动画。

专题页不是普通图文文章，而是“展会信息容器”。用户先看地点和日期，再进入本届可领养角色，因此后续开发应把专题、角色和领养类型设计成可关联的数据对象。

### 7.4 虚构都市：世界观最完整的单业务网站

虚构都市没有领养业务，而是把委托包装成“申请加入都市”、把成品角色包装成“居民”。这不是简单换词，而是从首页、居民档案、按钮、表单到流程说明都保持统一。

首页“现有居民”使用自动横向跑马灯展示成品卡片。点击后在遮罩层打开“VERIFIED CITIZEN”名片，包含成品照片、居民编号、简介、状态和校验编号。它没有单独维护传统作品详情 URL，而是把作品当作世界观中的档案对象。

![虚构都市居民卡片](./imgs/67-虚构都市-市民大厅-居民卡片.png)

![虚构都市居民名片详情](./imgs/68-虚构都市-市民大厅-居民名片详情.png)

世界观区解释“虚拟居民”如何通过物理同构进入现实，让作品展示和委托流程具有叙事关系。

![虚构都市世界观](./imgs/39-虚构都市-世界观与市民档案.png)

流程概览公开：

- 当前最快交期：2026 年 9 月；
- 整体约 8–9 个月；
- 排单定金：全额 20%；
- 报价有效期：1 周；
- 报价通常以 USD 区间给出。

![虚构都市流程概览](./imgs/40-虚构都市-委托流程概览.png)

完整流程分为七步：初步评估、设定完善、报价确认、支付定金、开工前最终确认、制作沟通、尾款与发货。还说明：

- Head Only 通常按全装委托约 50% 计价；

配置式估价页可选择标准全装、贴身全装、半装、服装设计、脖子毛、手爪、脚爪和肌群填充，随后填写体测数据、上传设定图、填写联络信息与验证码。

- 品牌世界观不是装饰，而是信息架构的一部分；
- 价格、交期和修改边界公开程度高；
- 服务条款还包括数据使用、保养、保修、穿戴安全和作品展示授权。

当前问题：

## 八、给后续主页设计的具体建议

### 推荐信息架构

1. **首页**
   - 品牌主视觉；
   - “我有设定，想委托”与“我想领养设定”两个大入口；
   - 代表作品；
   - 当前开单 / 排期状态；
   - 简短制作优势；
   - FAQ 摘要和联系方式。
2. **自设委托**
   - 系列 / 风格；
   - 制作范围；
   - 起步价与大致周期；
   - 材质、结构和可选配置；
   - 七步以内的流程；
   - FAQ；
   - 分步估价表。
3. **设定领养**
   - 默认视图与画师视图；
   - 类型、价格、画师、状态筛选；
   - 明确区分直接领养、应征领养、展会掉落；
   - 详情页写清“价格包含什么、权利有什么、何时制作身体”。
4. **作品**
   - 标准作品展示；
   - 用户返图 / 活动照片；
   - 可按系列、种族或单头 / 全装筛选。
5. **排期与公告**
   - 当前是否开单；
   - 下一次开放时间；
   - 展会安排与掉落专题。
6. **支持**
   - FAQ；
   - 服务条款、隐私政策；
   - 版权、修改、售后、保养、安全；
   - 官方联系方式与防诈骗提醒。
7. **关于我们**
   - 团队、职责、地点；
   - 真实照片；
   - 社交平台；
   - 不保留任何占位内容。

### 建议的数据与组件边界

为了让后续开发既能复用、又不在首版过度建设，建议只抽象这些真实重复对象：

| 对象 | 关键字段 | 主要页面 |
| --- | --- | --- |
| 作品 `Work` | 名称、系列、种族、装型、完成时间、设计师、图片集 | 首页、作品列表、作品弹窗 |
| 返图 `CustomerPhoto` | 图片、角色、返图者、日期、场景、主页链接 | 返图墙、返图详情 |
| 领养角色 `Adoption` | 角色资料、画师、类型、状态、价格、权利、上架 / 展会时间 | 领养列表、详情、专题 |
| 展会 `Event` | 名称、地点、起止时间、摊位、规则、关联角色 | 公告、展会专题、领养详情 |
| 委托系列 `CommissionTier` | 风格、范围、起价、周期、材料、可选项、开单状态 | 委托页、估价 |
| FAQ / 条款 | 分类、问题、答案、版本、生效时间 | FAQ、提交前确认 |

首版不必把灯箱、弹窗、卡片各自做成复杂内容系统；只要它们读取同一份作品或角色数据即可。

### 关键状态不要只存在于文案

建议领养状态使用明确枚举，并让按钮、标签和可执行动作由状态统一驱动：

`即将上架 → 开放领养 / 应征中 → 已锁定 → 已领养`

展会掉落可作为领养类型，不与状态混用；“未锁定”和“未领养”也不应同时以同等级标签重复表达。状态变化必须有更新时间，避免列表、详情和专题出现不一致。

### 关键事件与转化埋点

后续需要验证的不是“页面是否有人看”，而是用户在哪一步放弃：

- 首页点击自设委托 / 设定领养；
- 查看价格与周期；
- 打开作品详情、返图详情；
- 使用筛选 / 搜索；
- 打开领养须知或 FAQ；
- 开始估价、完成每一步、提交；
- 进入领养确认、登录 / 联系、最终提交。

这些事件足以判断首版动线，不需要一开始建设复杂用户中心。

### 首页必须马上回答的六个问题

1. 你们做什么风格？
2. 现在接不接单？
3. 我该走委托还是领养？
4. 大概多少钱、多久？
5. 我需要准备什么？
6. 下一步点哪里？

### 领养卡片的最小字段

- 角色主图；
- 名称；
- 画师；
- 系列 / 种族；
- 领养类型；
- 当前状态；
- 价格；
- 上架或展会时间；
- 明确按钮。

### 不建议直接照搬

- 没有运营需求时，不做账户、收藏、锁单和支付系统；
- 内容没有准备好时，不提前放多语言、成员卡片和公告入口；
- 不用长加载动画遮住核心内容；
- 不把“未锁定、未领养、可申请”等多个状态混成难懂标签；
- 不让用户在不知道起步价和排期的情况下填写一整页个人资料。

## 九、建议的首版方向

建议首版采用：

- 一个域名；
- 委托与领养两个一级业务入口；
- 白底或浅色内容区，保留朋友工作室自己的一个强品牌色；
- 首页用一张高质量成品主视觉；
- 作品、价格、周期、流程、FAQ 和表单全部可在移动端顺畅阅读；
- 先做内容完整、路径清楚的静态站，再按真实运营需要增加角色库存、账户或支付能力。

如果朋友的品牌世界观很强，可以借鉴虚构都市的“统一命名”，但必须同时保留直白业务词，例如：

**“加入居民档案（自设委托）”**，而不是只写“加入都市”。

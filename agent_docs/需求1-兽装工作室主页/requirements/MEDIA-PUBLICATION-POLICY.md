# 媒体公开与保护策略

> **角色**：当前媒体公开行为的唯一事实源。
> **状态**：阶段 C 媒体迁移已完成；阶段 D 返图和展会掉落规则已于 2026-08-07 确认。
> **适用范围**：首页、委托页、作品、常规领养、展会掉落、返图墙、管理预览、OSS 衍生图、品牌水印切换与清理。

## 1. 核心原则

是否打水印由**公开展示位置和媒体用途**决定，而不是由横竖方向决定。

- 首页 Hero、委托 Hero 和首页业务入口是站点展示位，无水印；
- 标准作品、常规领养和展会掉落是作品档案位，使用活动品牌水印；
- `/returns` 返图墙是独立真实使用照片展示位，无水印；
- 永久原图、预处理源、Logo 候选、管理预览和返图授权记录始终私有；
- 所有公开图片由服务端预生成、校验并使用不可变身份；
- 浏览器不得通过 OSS 查询参数临时加工私有原图，也不得使用 CSS 临时叠 Logo 冒充发布结果；
- 新媒体角色必须显式登记用途、配方、保护模式、输出集合和清理边界。

## 3. 已落地公开配方

### 3.1 站点展示配方

`site-display-v1` 覆盖首页 Hero、委托 Hero 和首页两个业务入口。

身份至少包含：

- `assetId` 与输入 SHA-256；
- 公开用途；
- 输出宽高、格式、质量、裁剪或焦点身份；
- `recipeVersion = site-display-v1`；
- `protectionMode = none`；
- 不携带水印 Logo、profile、位置、不透明度或缩放身份。

站点展示衍生图必须提供 WebP 与 JPEG/PNG fallback，写入公开 Bucket，使用不可变 Key，写后验证 MIME、尺寸、字节数、摘要与匿名读取。失败只清理当前 attempt 新建对象，不影响当前启用版本。

### 3.2 作品保护配方

作品、常规领养和展会掉落继续使用：

- `recipe-v2`；
- 活动 `brand-centered-v2` profile；
- 当前 Logo、中心位置、不透明度和缩放身份；
- 现有横竖水印几何规则。

profile 变化生成新 Key，并在完整校验后原子切换。旧 profile 仍被公开快照引用时不得删除。

## 4. 阶段 D 返图配方

### 4.1 身份

返图公开变体使用：

```text
media_role = return_photo
usage = return-wall
recipe_version = return-display-v1
protection_mode = none
watermark_profile_id = NULL
```

身份至少包含：

- 返图资产 ID 与输入 SHA-256；
- `return-wall` usage；
- 输出宽度、格式、质量；
- 原始宽高比与方向；
- EXIF 收敛版本；
- `return-display-v1`；
- `protection_mode=none`。

不得携带 Logo、profile、位置、不透明度或缩放身份。

### 4.2 图像处理

返图公开生成必须：

- 保持原始宽高比，不强裁为统一 3:4；
- 根据瀑布流实际展示生成受控响应式宽度；
- 提供 WebP 和 JPEG/PNG fallback；
- 纠正 EXIF 方向后移除不需要的 EXIF；
- 不公开 GPS、设备、原文件名或其他拍摄隐私；
- 不增加水印、边框、文字或品牌角标；
- 写入公开 Bucket 后验证 MIME、尺寸、字节数、摘要和匿名读取；
- 使用完整身份寻址且禁止覆盖。

浏览器只能消费生成好的 SourceSet，不追加 OSS 处理参数。

### 4.3 与活动 profile 的关系

应用或切换作品水印 profile 时：

- 不扫描返图；
- 不重新生成返图；
- 不切换返图公开引用；
- 不删除返图公开对象；
- 影响摘要明确说明返图无水印且不受本次操作影响。

## 5. 首页业务入口的独立派生

首页两个入口不得直接消费委托 Hero 或第一件领养设定图当前 URL。允许使用相同源资产，但必须生成：

- `home-entry-commission`；
- `home-entry-adoption`。

独立用途保证统一比例和裁剪、入口无水印、作品/领养继续水印，以及按展示位置精确清理。缺少可用源时显示受控无图状态，不回退到任意作品或私有原图。

展会掉落可以成为首页领养入口或当前领养的数据来源，但入口图仍使用独立无水印 `home-entry-adoption`，掉落作品自身卡片和详情仍使用水印图。

## 6. 私有与公开存储边界

### 6.1 私有 Bucket

保存：

- 永久作品原图；
- 永久返图原图；
- FFmpeg 预处理或大图适配源；
- 水印 Logo 候选；
- 管理预览和临时处理对象。

要求：

- 匿名读取失败；
- Object Key 不进入公开 DTO、HTML、日志或 CSV；
- 临时对象有精确清理和生命周期兜底；
- 永久原图不得被生命周期规则误删；
- 返图授权记录只存在数据库私有字段，不写入图片元数据或对象标签。

### 6.2 公开 Bucket

只保存通过完整身份生成和验证的衍生图。每个公开对象能从数据库追溯到输入资产、用途、配方和保护模式。

公开 Bucket 不保存永久原图、处理源、Logo 源、管理预览或授权附件。

## 7. 发布、下架与恢复

### 7.1 作品与领养

继续使用现有作品 publication operation。展会掉落不会增加新的媒体 operation，只增加发布前字段检查。

### 7.2 返图

返图发布必须：

1. 固化返图版本和关联作品状态；
2. 生成缺失 `return-wall` 变体；
3. 验证公开对象；
4. 原子切换返图状态与公开投影；
5. 写审计记录；
6. 失败只清理当前 attempt 新建对象，保留旧公开版本。

返图下架先撤销公开投影，再精确清理不再引用对象。阶段 D 不建设 30 天回收站；不以批量删除替代下架。

返图 publication operation 复用 attempt、lease、heartbeat、recovery reason、提交 CAS、启动扫描和幂等核对。重复重启不得制造重复对象或卡死运行态。

### 7.3 关联作品状态

公开返图查询同时要求返图和关联作品 published。作品下架后返图立即不可见，但不自动删除返图记录、私有原图或 READY 公开对象。重新发布作品后，返图按其既有发布状态重新满足查询条件。

## 8. 清理边界

- 任何清理使用精确 Object Key manifest，不列举或模糊删除前缀；
- 失败保留待清理清单和稳定 reason；
- 返图不增加通用软删除、统一 `deleted_at` 或 30 天 OSS 到期任务；
- 存在返图关联时阻止作品永久删除；
- 活动 profile 清理不得触及站点展示和返图；
- 仍被公开投影或旧有效版本引用的对象不得删除。

## 9. 验收标准

### 9.1 阶段 C 保持有效

- 首页和委托 Hero 横竖请求命中无水印站点展示变体；
- 首页委托与领养入口命中各自独立无水印入口变体；
- 作品、常规领养和设定图命中活动水印变体；
- profile 切换不改变站点展示 URL 与摘要；
- 私有原图、处理源、Logo 候选和管理预览匿名不可读。

### 9.2 阶段 D 返图

- `/returns` 每张图片命中 `return-display-v1` 无水印变体；
- 横图、竖图、方图保持原比例，无统一强裁；
- 公开响应和下载对象不包含授权记录、私有 Key、原文件名、GPS 或敏感 EXIF；
- profile 切换前后返图 URL、摘要和像素结果不变；
- 关联未发布作品的返图不可公开；
- 发布失败、下架、进程中断和重复重启保持唯一终态；
- 私有返图原图匿名读取失败，公开衍生匿名读取成功；
- 三固定视口无坏图、异常裁切、巨大空洞和横向溢出。

### 9.3 阶段 D 展会掉落

- 继续命中与其他领养相同的活动水印变体；
- 不产生 event 专用媒体角色、配方或公开对象；
- 展会名称和时间只作为业务元数据展示，不进入图片身份。

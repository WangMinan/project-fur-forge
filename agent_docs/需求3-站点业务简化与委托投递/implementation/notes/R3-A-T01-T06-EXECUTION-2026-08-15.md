## 首次失败记录

按任务追加首次失败、根因、修复与精确重测，不通过 skip、删除仍有效测试、放宽断言或只改 fixture 处理失败。

- T01 首次 `pnpm typecheck` 失败：四个待 T02 删除的返图/动态管理页仍向 `AdminShell` 传入已从可见导航移除的 current key。根因是 T01/T02 的顺序边界，不是产品入口残留；T01 临时把两个 key 仅保留在 `AdminNavCurrent` 类型中，T02 删除页面时一并删除过渡类型，然后重跑 typecheck。
- T01 首次调整 E2E 后 `pnpm lint` 失败：替换首页动态摘要测试后遗留了已无引用的截图目录常量。删除该常量并重跑 lint。
- T01 首次 slogan migration 冒烟失败：把 test DB 放在仓库 `.tmp`，触发既有 `resolveDatabaseFile` 隔离门禁（test DB 必须位于系统临时目录）。改用已解析的系统临时目录绝对 `.db` 路径重跑，不放宽门禁。
- T02 首次 `pnpm typecheck` 失败：公开 analytics client 仍把已退役的 `return_character` DOM marker 纳入联合类型。删除该 marker 分支后重跑；未放宽 analytics Schema。
- T02 首次全量 `pnpm test`：36 files / 185 tests 通过，但 `tests/unit/search.test.ts` 在收集期仍导入已删除的返图查询 Schema。删除该过期导入和返图断言后重跑全量 unit。
- T02 首次退役路由 focused E2E：公开页面/API 均为 404，但 `/admin/returns` 返回了 CSR 管理应用壳的 200。根因是 `/admin/**` 全局 `ssr:false` 对未知客户端页面仍提供壳；新增只匹配阶段 A 退役路径的 Nitro 404 middleware 后原样重测。第二次 E2E 证明管理页面已为 404，同时发现缺失的管理 API 会先被通用鉴权拦为 401；把同一退役保护置于 Host 边界之后、管理鉴权之前，并覆盖两组管理 API 前缀后继续原样重测。
- T02 selected integration 首次运行命令误用 unit config，Vitest 报 `No test files found`；改为显式 `--config vitest.integration.config.ts` 后执行到测试。4 files / 19 tests 中 16 通过，3 个联系分区写入失败，根因均为历史 migration 仍强制五平台 JSON；这是 T04 Contract 的直接红灯和复测基线，不通过临时补回三平台或放宽测试处理。

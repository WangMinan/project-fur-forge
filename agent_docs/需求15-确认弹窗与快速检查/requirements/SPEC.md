# 规格说明：确认弹窗与快速检查

## 来源与目标

2026-10-11 用户截图及追加授权。让站内放弃修改的决策使用已有管理端确认组件，减少快速检查中的重复工作。

## 确认交互

- 作品页离开、站点配置页离开、文案语言切换共用AdminConfirmDialog的薄封装。
- 默认聚焦“继续编辑”；取消、Escape、背景关闭均保留原页面和草稿，焦点回到触发位置。确认后才继续原路由或语言切换。
- 同一组件至多保留一个待确认请求；组件销毁时结束等待，不留下悬挂的导航Promise。
- 干净页面直接离开；会话失效放行回登录，不能被未保存提醒困住。
- 不移除刷新、关闭标签页时的beforeunload数据丢失保护，不将其伪装成可定制组件。
- 本次不新增其他页面的离开保护，也不扩展成全局弹窗服务。

## 快速检查

- 保留quality的checks job标识、全部unit/integration发现范围和所有release步骤。
- 将原Fast checks按lint、typecheck、core拆成显式步骤，便于分别定位耗时；本地check:fast仍顺序调用同三项命令。
- runtime-api的Nuxt夹具保留完整生产模式构建与真实HTTP检查，关闭夹具重复的typecheck；独立typecheck仍是CI必经步骤，生产build本身的typecheck不变。
- FFmpeg发布用例继续使用真实二进制，保留尺寸、摘要、原图留存、失败处理、长竖图和发布状态断言。只把相关测试图的高频纹理换为带边缘与透明度的棋盘，不改生产压缩、尺寸或媒体参数。
- 记录同一测试集优化前后实测耗时；本地和GitHub数据分别说明，不虚报远程提速。

## 验收

- 全局扫描无业务原生alert/confirm/prompt/Notification调用。
- 浏览器验证取消/确认、返回键、焦点循环/返回、窄屏、未保存内容保留、无原生confirm及无遗留滚动锁。
- lint、typecheck、完整core与生产build通过；独立工作流契约检查通过。

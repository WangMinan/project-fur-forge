# 后台减少动态效果与同步几何修复

## 授权与根因

用户于2026-09-10要求扩查裁切以外的同类场景，直接在main修复、同步文档并commit/push。基线为`bcf7425`，工作树初始干净。本次不执行镜像发布或生产部署。

Chrome现场的`prefers-reduced-motion: reduce`为true。后台全局规则对所有后代及伪元素设置`transition-duration: 0.01ms !important`；原本没有过渡的元素默认`transition-property: all`，因此也意外获得过渡。Cropper连续写入transform并读取`getBoundingClientRect()`时读到过渡前的尺寸，导致图片与选区错位。

在生产页面的诊断副本中，仅在浏览器内将作品状态映射为可编辑并拦截所有非GET/HEAD请求，没有下架或保存生产作品。实测图片高约259px、选区高约366px，底部越界约144px。保留减少动态偏好，临时将过渡时长改为0s后，图片恢复为画布的324px高，选区回到图片内，移动和缩小可用。诊断副本随后关闭。

使用当前组件与真实后台样式、合成7008×4672原图元数据及640×427预览隔离验证：普通模式正常；原减少动态规则可复现约191px越界；0s恢复正常；恢复原规则后再次越界。CSS缩放也能产生坐标问题，但现场祖先元素zoom均为1，不作为本次现场根因。

此前比例精度修复仍保留：亚像素误差与本次过渡时序问题可独立触发，不能因本次发现而回退原图比例校正，也不能断言早期录屏完全由本问题导致。

扫描app内的尺寸读取、ResizeObserver、requestAnimationFrame、CSS过渡/动画及结束事件，并检查相关组件的数据流。

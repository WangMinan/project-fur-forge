# 需求3 · 公开端与管理端设计说明

> **角色**：把需求3的视觉、响应式和交互动效要求转成可验收的设计约束。
> **状态**：方向已锁定；尚无最终高保真稿。实现可以在不改变本文件行为的前提下优化细节。
> **参考**：`https://www.ww-pass.com/wp-fursuit/` 的 Tab 悬停、层级和页面动效仅作为交互参考，不复制其品牌、颜色、素材或完整布局。

## 1. 总体方向

- 继续保持白底、摄影优先、文字辅助的基础视觉；
- 公开端从“尽量少动效”调整为“有节奏、可感知、不过度拖慢”的品牌展示；
- 作品、领养和 Hero 的图片仍是最高视觉层级；
- 动效用于说明层级、方向、状态和可点击性，不使用无意义粒子、持续漂浮、大面积模糊或高成本滤镜；
- 管理端保持高密度、稳定、清楚，动效只服务操作反馈。

## 2. 品牌文字与联系面

- 中文导航品牌：`有点小狗`；
- 首页完整标题：`有点小狗工作室`；
- 英文品牌：`DITE DOG`；
- 首页 slogan：`不只做小狗毛 | 只做海绵头`；
- 任何当前页面不得显示 `DITE DOG FURSUIT`；
- 当前官方联系面只包括邮箱、QQ、QQ群；
- 抖音、小红书和 Bilibili 不再出现于公开卡片、页脚、管理表单或空占位。

## 3. 首页 Hero

### 3.1 桌面布局

1440×900 等桌面视口下，Hero 高度占完整首屏。文字位于底部安全区：

```text
┌──────────────────────────────────────────────────────┐
│                                                      │
│                    摄影主画面                         │
│                                                      │
│                 有点小狗工作室                       │
│ DITE DOG                 不只做小狗毛 | 只做海绵头   │
│                                            轮播控件  │
└──────────────────────────────────────────────────────┘
```

要求：

- 中文主标题水平居中；
- 第二行使用同一内容宽度，英文靠左、slogan 靠右；
- 第二行不是两个按钮，不使用实心色块；
- 删除 Hero 主行动按钮；
- 轮播控制保持右下或底部独立区域，不能压住文字；
- 渐变遮罩只覆盖可读性所需区域，不把整张照片压暗成灰图；
- 文案容器不能像截图标注中的大矩形面板一样形成重边框。

### 3.2 移动布局

390×844 等移动视口下，不复制桌面居中结构：

```text
┌─────────────────────┐
│                     │
│      摄影主画面      │
│                     │
│ DITE DOG            │
│ 有点小狗工作室       │
│ 不只做小狗毛 |       │
│ 只做海绵头           │
│           轮播控件   │
└─────────────────────┘
```

要求：

- 整组文字左对齐；
- 相比当前版本下移，进入画面底部安全区；
- Hero 至少覆盖完整首屏，页面内容不能从 Hero 底部露出白块；
- 使用竖版素材，不拿横图裁成竖图；
- slogan 可折行但不能截断、溢出或压住轮播控件；
- 顶部品牌和汉堡菜单保持清晰，不与角色耳朵或高对比部位产生不可读冲突。

### 3.3 Hero 入场与切换

首次进入首页：

1. 图片先可见；
2. 英文、中文主标题、slogan 依次入场；
3. 轮播控制最后出现。

推荐时序：

- 单项 500–700ms；
- 错峰 70–120ms；
- 位移不超过 16px；
- 使用 `cubic-bezier(0.22, 1, 0.36, 1)` 或同等自然 easing。

轮播切换允许轻微横向方向感和 1% 左右缩放，不允许明显白闪、黑帧或同时下载全部大图。

## 4. 主导航

### 4.1 桌面

每个主导航项拥有独立可点击胶囊区域：

- 常态透明或极浅底；
- hover/focus 时出现 8–12px 圆角底；
- 增加柔和阴影；
- 上移 1–2px；
- 文字保持高对比；
- 当前项仍有稳定的 active 标识，不能只靠 hover 阴影识别。

下拉菜单：

- 淡入、下移复位、chevron 旋转；
- panel 阴影比主导航 hover 更明显，但不使用厚重描边；
- 子项 hover 使用浅背景，不做整页跳动。

### 4.2 移动

- 抽屉保留背景滚动锁定、焦点陷阱、Escape、路由关闭和焦点归还；
- 面板和菜单项可以错峰进场；
- 不模拟桌面阴影 hover；
- 菜单中不出现返图墙和最新动态。

## 5. 页面切换

公开站内页切换时：

- Header 保持稳定；
- 主内容离场 140–200ms；
- 新内容入场 240–360ms；
- 动画由 opacity + 8–16px 纵向位移组成；
- Footer 可随内容自然移动，但不能先消失再闪回；
- 页面切换期间旧内容不得继续接收指针事件；
- 浏览器后退、前进和锚点跳转不应被动画破坏。

不对管理端所有路由应用同样的全页动画。

## 6. 首页内容区

- “精选作品”“自设委托”“设定领养”进入视口时可以一次性揭示；
- 标题字号、字重、行高和基线统一；
- 精选作品按精选标记展示，包括已领养作品；设定领养只展示 available。
- 删除“最新动态”区块后，当前领养直接衔接页脚前的收尾留白；
- 业务入口两张卡继续并列，标题改为“委托与领养”；
- 卡片 hover 使用上浮、阴影和轻微图片放大，不额外增加大号按钮。

## 7. 作品页

### 7.1 `/works`

- 卡片图片保持 3:4；
- 图片下只显示“名称 · 物种”，点号两侧保留空格；
- 首页、`/works`、`/adoptions` 复用同一名称字体与字号；
- 删除装型、用途、状态等元信息；
- 删除用途和装型筛选后，名称搜索与结果网格保持同一节奏；
- 图片 hover 可以比当前略明显，但缩放不超过 1.04。

### 7.2 `/works/{slug}`

- 名称和物种作为简短标题区；
- 图集占主要宽度；
- 删除事实表、标签、价格和长说明造成的侧栏空洞；
- 宽屏可以使用单列大图或轻量双列瀑布，但不能牺牲图片完整性；
- 前后浏览和继续浏览保持小型辅助入口。

## 8. 领养页

- 列表不再显示“全部/常规/展会掉落”筛选；
- 卡片主图固定使用横版 `adoption_cover`，推荐 16:9；
- 图片为单头成果照，使用 cover；
- 名称、物种、状态和价格在图片下形成清楚层级，作品标识同样使用“名称 · 物种”；
- 状态不能只用颜色，必须同时有文字；
- 可领养使用绿色，已领养使用非绿色中性色；
- 设定图不作为卡片图；
- 首页“当前领养”复用同一卡片视觉。

## 9. 委托页、关于页与表单

### 9.1 `/commission`

- Hero 或代表图继续服务品牌展示；
- 首个明显行动为“提交委托申请”；
- 次级入口为“关于我们与全部联系方式”；
- QQ 与 QQ群二维码在当前页面可直接看到；
- 邮件不做主按钮；
- 不出现抖音、小红书或 Bilibili 卡片、Logo、空位或说明；
- 常见问题区完整删除；
- 估价说明保持短段落，不做大段 CMS 文案。

### 9.2 `/about#contact`

- 顶部或首项保留邮箱备用联系；
- 渠道卡片只有 QQ 与 QQ群两张；
- 宽屏两张卡保持自然内容宽度，不拉伸为五等分；
- 移动端两张卡可单列或双列，但二维码必须清晰可扫；
- 不显示已经取消的三类平台，也不保留“即将补充”占位。

### 9.3 `/commission/apply`

表单使用单列移动优先、宽屏两列的清楚结构：

- 顶部说明只强调收集用途和人工联系；
- 设定图上传区独占一行，明确“仅一张”；
- 称呼、手机号、QQ、身高、体重使用可见 label，不只依赖 placeholder；
- 必填项有文字或符号说明；
- 错误紧邻字段，提交失败不清空用户输入；
- 主按钮为“提交委托申请”；
- 提交成功进入独立成功态，显示回执编号和人工联系说明；
- 不出现邮箱、年龄、围度、备注、室内脚或其它未授权字段。

## 10. 委托后台与联系配置

- 管理导航新增“委托申请”；
- 默认展示待处理；
- 状态切换使用三个清楚 Tab 或 segmented control：待处理、已接单、已拒绝；
- 列表不直接铺开手机号和 QQ；
- 详情页显示私有字段和大图预览；
- 状态操作有明确确认和成功反馈；
- 内部备注使用普通 textarea；
- 不显示 Object Key、上传会话、摘要或技术状态枚举；
- 联系配置只显示 QQ 与 QQ群两行，邮箱继续使用独立输入；
- 抖音、小红书、Bilibili 不以只读、禁用或隐藏折叠项继续存在。

## 11. reduced-motion

系统减少动效时：

- 页面立即切换；
- Hero 不自动轮播；
- 区块不做错峰；
- 卡片不位移和缩放；
- 抽屉、对话框可以保留最短可见状态切换，但不做大幅滑动；
- 内容、焦点、导航和状态提示必须完整保留。

## 12. 验收视口

必须验证：

- `390×844`：移动 Hero、表单、移动导航、QQ/QQ群联系卡；
- `768×1024`：平板 Hero、作品与领养网格、表单、两渠道布局；
- `1023×900` 与 `1024×900`：公开/管理导航断点；
- `1440×900`：桌面 Hero、导航 hover、页面切换、作品、领养和两渠道联系区；
- 至少一台真实手机：动态地址栏、首屏高度、图片解码、QQ/QQ群二维码可识别、表单输入法与提交。

验收同时检查键盘、焦点、console、network、图片请求方向、布局偏移和 reduced-motion。
